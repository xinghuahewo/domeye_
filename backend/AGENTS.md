# Backend 分层协作规则

本文件适用于 `backend/**`。仓库根 `AGENTS.md` 与当前 Worktree 的任务合同继续生效；
本文件只补充后端约束，不复制或放宽根级 Git、发布、文档和任务治理。规则不一致或任务
需要越出允许路径时，必须停止并请求确认。

下文中 MUST 表示必须遵守，SHOULD 表示默认做法，MAY 表示满足所列条件后可以执行。

## MUST：职责与运行边界

- `backend/core/**` 与 `backend/core.sha256` 在普通任务中属于冻结迁移边界。只有独立、
  经用户明确批准且由任务合同精确授权路径的 Core 迁移任务，才可以受控修改；该任务必须
  重建并独立核验迁移清单，不能通过更新摘要掩盖无关变化。修改后端运行时代码后，必须在
  `backend/` 执行 `sha256sum -c core.sha256`。
- 生产 Web 默认启动必须保持只读且无初始化副作用：不得默认建表、加载全量核心数据、
  启动离线检测、运行数据管线或写数据库；不得改变 `AUTO_INIT_DB=false` 和
  `LOAD_CORE_DATA_ON_STARTUP=false` 的默认边界。
- Flask 请求或启动路径不得执行 `data_pipeline/`、`info_pipeline/` 的 writer、CLI、
  发布动作、长任务或子进程。可以读取纯定义、只读适配器和已准入制品。
- 新增或修改的请求派生 SQL 值必须参数化。动态表名及其他 SQL 标识符只能来自既有
  白名单或确定性校验结果，不能直接采用请求输入。

## MUST：事实与数据语义

- 运行入口和普通实现中的数据窗口、快照时钟与业务时区只从根目录
  `config/data-profile.json` 及既有校验适配器取得，不得复制固定值。机器合同、fixture、
  边界断言和安全断言可以固定预注册值，但必须由现有一致性检查反向绑定
  `config/data-profile.json`，不能形成第二配置源。
- 对已有 `null`、`unknown`、缺槽、不完整或身份冲突语义的合同，不得补成 `0`、完整或
  成功；错误与不可用状态必须按现有合同失败关闭。
- 国家中断、Agent 及其相关 v2 读模型和数据产品必须保留事件、publication、revision、
  collector、人口、单位和时间窗绑定。RRC25 BGP 控制面观察不得扩大为全国网络状态、
  真实用户影响、原因、责任、攻击归因或实际恢复。

## MUST：API 与安全边界

- 公共 API 的新增、修改或删除必须在同一任务中同步维护 Flask 路由、路由白名单、
  `contracts/openapi.json`、相关响应契约测试和生成的前端类型。当前任务未允许跨目录时，
  必须停止，由用户重新确认范围，并在新的干净 Worktree 和任务合同中实施，不能原地
  扩展已封存的任务合同或只改后端。
- 应用构造器必须保留全局身份注入和数据窗口 Guard；单个 Resource 不得绕过它们。
- Chat 代理必须继续失败关闭：只接受受信身份与授权范围，校验幂等键和输入大小，只访问
  既有策略允许的本机 Sidecar，禁止重定向和环境代理，并保持稳定的公共错误投影。
  内部 token、Candidate、Receipt、Trace 和内部 Evidence 不得进入公共响应。
- 新增 POST、扩大 CORS、增加身份来源或公开内部字段，必须由用户对每一项变更逐项明确
  批准，并作为跨 Backend、Sidecar、OpenAPI 和 Frontend 合同变更实施，补齐对应拒绝
  路径测试。

## MUST：依赖与验证

- Python 依赖只维护 `pyproject.toml` 与 `uv.lock`，不得新增或恢复 `requirements.txt`。
- 单元测试和契约测试必须使用 testing 配置、fixture、mock 或临时目录，不得依赖真实
  生产数据库、凭据、网络、Sidecar 或进程，也不得启动 Screen、Nginx 或发布动作。
- 修改 Python 运行时后，先在 `backend/` 运行受影响的 `uv run --frozen pytest ...`；
  再按根目录风险分类器和任务合同运行要求的全量后端、OpenAPI、前端类型或发布级无副作用
  检查。健康接口成功不能代替数据库、API 契约或部署验收。

## SHOULD：新增代码的默认结构

- 新请求链应保持 API 层只处理 HTTP 校验和响应映射，领域编排放在 `services/`，数据库
  访问放在 `database/`；不要在 Resource 内新增 SQL 或隐藏业务计算。
- 普通功能任务应采用最小充分改动，不顺手重构旧 Core、整份 legacy SQL 或无关调用链。
- 应先运行最小受影响测试，再按风险等级升级；不要把全量生产验收塞进日常短循环。
- 本文件只记录稳定约束，不维护端点全集、端口、固定日期、依赖版本、服务器路径或临时
  发布身份；这些事实以当前机器合同、测试、代码和专门配置为准。

## MAY：条件性例外

- 显式集成任务可以访问任务合同声明的隔离数据库或 Sidecar，但必须使用测试身份和隔离
  数据，不得访问生产；验证结束后不得遗留进程、端口或状态。
- 显式数据准备、迁移或离线管线任务可以执行获准的写操作，但不得把这些能力接入生产
  Web 默认启动或普通请求路径。需要修改 Core 时，必须另行进入上文规定的独立 Core
  迁移任务，不能借当前数据或管线任务越过该边界。
- 只有当后端某个子目录形成独立、稳定且可机器验证的权限、工具链或验收边界时，才可以
  提议增加更深层 `AGENTS.md`；不得仅为重复本文件而继续分层。
