# INFO 目录数据落库分阶段计划

> 本文是《[INFO 目录数据落库最终验收文档](./INFO目录数据落库最终验收文档.md)》
> 的阶段推进边界。本文只规定每个阶段从什么状态开始、以什么状态结束，以及不得
> 跨越的边界；不规定实现任务、代码结构、SQL、命令、责任人或排期。

## 一、总起点

- INFO 来源仍是只读文件目录；
- 24 个数据文件的用途、合同和质量差异已经能够被识别；
- 当前仅四个核心文件具备 shadow 落库能力；
- 数据库 release 不能激活，既有运行时仍以文件制品为准；
- 域名、pfx2as、关系、三元组、私有 AS 和历史数据尚未完成全量落库；
- API、静态快照和六类检测尚未完成数据库/文件的完整行为对账。

## 二、总终点

- 最终验收文档的 FA-01 至 FA-12 全部通过；
- 24 个文件的所有逻辑记录均已接纳或有原因地隔离；
- 查询、API、静态快照和六类检测不存在未批准语义差异；
- 性能、容量、权限、隐私、激活和回滚均达到最终阈值；
- 普通运行时不再直接读取旧 INFO 目录；
- 当前、上一 release 和获准的文件回滚制品仍然完整；
- 任一结果都能指向唯一 INFO 内容身份和完整验收证据。

总终点不是“数据库中已经有数据”，而是“数据库成为可信、等价、可回滚且唯一的
运行时静态信息来源”。

## 三、全局边界

- 原 INFO 目录始终只读，不连接或修改原项目生产数据库与进程；
- `backend/core/` 的检测业务逻辑不得借数据来源迁移发生改变；
- 未达到本阶段出口时，不得进入下一阶段；
- 后续阶段不得覆盖或删除前序阶段的失败、隔离和偏差证据；
- 任一阶段不得通过手工改状态、直接写 active 指针或降低最终验收阈值出场；
- 检查动作不得产生生产写入、激活、停服、删除或清理副作用；
- 阶段通过只代表对应边界成立，不代表最终验收已经通过；
- 阶段结束必须通过阶段结束 Hook；Hook 报告为 `fail` 时不得宣告阶段完成。

## 四、阶段总览

| 阶段 | 名称 | 入口概括 | 出口概括 |
|---|---|---|---|
| S0 | 冻结最终合同与来源基线 | 来源可只读核验，最终效果已定义 | 来源身份唯一，合同和基线可复核 |
| S1 | 四核心文件 shadow 成立 | S0 通过，候选库与运行时隔离 | 四核心文件可幂等落库且不可激活 |
| S2 | 全部 24 文件闭合 | S1 通过，未迁移文件边界明确 | 24 文件逐文件计数守恒并可追溯 |
| S3 | 查询与快照语义闭合 | S2 通过，全量 release 可供影子读取 | 查询、API 和静态快照无未批准差异 |
| S4 | 检测与非功能边界闭合 | S3 通过，固定输入与性能基线可用 | 六类检测、性能、容量、安全均通过 |
| S5 | 激活与回滚边界闭合 | S4 通过，候选 release 证据完整 | 受控激活成立，上一版本可安全恢复 |
| S6 | 运行时收口 | S5 通过并完成约定观察 | 旧目录依赖为零，保留与清理边界成立 |

## 五、阶段入口、出口与边界

### S0：冻结最终合同与来源基线

#### 入口

- 来源目录可以在不修改其内容的前提下完整读取；
- 24 个文件及其当前用途能够被识别；
- 最终验收效果和当前缺口可以被区分。

#### 出口

- FA-01 通过；
- 同一来源内容能够稳定得到同一内容身份；
- 24 文件集合、逻辑记录数、合同身份和当前质量状态均可复核；
- 最终验收要求不再依赖口头约定。

#### 边界

- 不导入生产在线库；
- 不改变任何消费者的数据来源；
- 不把质量探针通过解释为数据已经落库；
- 不把用途未决的数据强行解释成 active 数据。

### S1：四核心文件 shadow 成立

#### 入口

- S0 阶段结束 Hook 已通过；
- 来源内容身份未变化；
- 候选数据库与在线运行环境相互隔离。

#### 出口

- 四个核心文件在候选库中逐文件计数守恒；
- 相同内容重复进入不会形成重复业务结果；
- release 保持不可激活状态；
- 已完成文件、未完成文件和下一边界能够明确区分。

#### 边界

- 不宣称 24 文件已经全部落库；
- 不切换 API、检测器或普通运行时读取；
- 不修改 active release；
- 不删除既有四文件运行时制品。

### S2：全部 24 文件闭合

#### 入口

- S1 阶段结束 Hook 已通过；
- 四核心文件结果仍满足 S1 出口；
- 其余文件的用途、语义边界和例外处理方式已经明确。

#### 出口

- FA-02 和 FA-04 通过；
- 24/24 文件逐文件满足接纳数与隔离数之和等于清单逻辑记录数；
- 任一可见记录和隔离记录均可追溯；
- 不存在状态不明、计数不明或被静默丢弃的文件和记录。

#### 边界

- 全量落库不等于行为等价；
- 不切换对外读取；
- 不把 legacy、替代或用途未决数据冒充 active 数据；
- 不因完成计数对账而放宽语义合同。

### S3：查询与快照语义闭合

#### 入口

- S2 阶段结束 Hook 已通过；
- 同一全量内容身份可同时被文件后端和数据库后端确定性读取；
- 已批准例外具备明确范围。

#### 出口

- FA-03 和 FA-06 通过；
- ASN、prefix、国家、域名、关系、pfx2as、私有 AS、重要 AS 和三元组查询
  不存在未批准差异；
- 静态快照的键、值、顺序、空值和优先级语义一致；
- 所有差异均被解释为已批准例外，而非统计噪声。

#### 边界

- 影子结果不得影响对外响应或检测结果；
- 不用抽样通过率代替完整集合或确定性键对账；
- 差异证据不得包含联系人原文；
- 不因接口结果相似而跳过快照语义检查。

### S4：检测与非功能边界闭合

#### 入口

- S3 阶段结束 Hook 已通过；
- 固定 RIB、UPDATE、文件基线和同一 INFO 内容身份可供对照；
- 性能与权限检查处于隔离候选环境。

#### 出口

- FA-07、FA-08、FA-09 和 FA-11 通过；
- 六类检测结果不存在未批准差异；
- 查询延迟、快照装载、峰值 RSS、检测吞吐和容量均达到最终阈值；
- 最小权限、联系人隔离、无副作用检查和可复核运行状态成立。

#### 边界

- 不以修改核心检测逻辑换取 A/B 一致；
- 不用降低样本规模或排除失败类型掩盖差异；
- 不在在线服务上进行压力或权限破坏性试验；
- 不因功能正确而忽略性能、容量或隐私失败。

### S5：激活与回滚边界闭合

#### 入口

- S4 阶段结束 Hook 已通过；
- 候选 release 与全部验收证据属于同一内容身份；
- 上一 release 和文件回滚制品均可用。

#### 出口

- FA-05 和 FA-10 通过；
- 当前 release 的改变只能发生在受控激活边界；
- 请求、快照和检测运行均保持单一内容身份；
- 上一 release 能在批准的安全边界恢复，失败证据保持完整。

#### 边界

- 不允许绕过发布身份和确认边界直接修改 active 状态；
- 不在一次检测运行中热混合两个 release；
- 不用删除候选失败记录换取回滚成功；
- 不在回滚能力未经实证时停止文件回滚能力。

### S6：运行时收口

#### 入口

- S5 阶段结束 Hook 已通过；
- 数据库模式已经完成约定观察且没有未决阻断偏差；
- 当前与上一 release 均健康可用。

#### 出口

- FA-12 通过；
- FA-01 至 FA-12 在同一最终内容身份下全部通过；
- 普通运行时对旧 INFO 目录的直接读取次数为零；
- 当前、上一 release 和获准回滚制品仍可用；
- 保留、回滚和独立清理边界明确。

#### 边界

- 收口不等于删除原始来源；
- 不在同一收口动作中清理仍被引用的 release 或回滚制品；
- 不把观察期内“未发现问题”替代完整最终验收；
- 不把文档完成、代码合并或服务启动当作最终通过。

## 六、阶段封口规则

- 阶段结束 Hook 必须核对当前验收文档、阶段计划、前序通过回执和本阶段证据；
- 前序回执缺失、内容身份漂移、证据被覆盖、要求未到期却已确认失败，均视为偏离；
- 本阶段到期的最终要求必须为 `pass`，`blocked`、`fail` 或缺少证据均不能出场；
- S6 只有在 FA-01 至 FA-12 全部通过时才能产生最终通过回执；
- Hook 通过只证明阶段证据满足合同，不替代生产激活所需的独立授权。
