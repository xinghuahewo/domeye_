# 二三月固定开发模式

从 2026-07-19 起，Domeye Core 进入 `feb-mar-2026` 固定开发档。所有页面、接口和本地真实数据联调只允许读取：

```text
2026-02-01T00:00:00+08:00 <= t < 2026-04-01T00:00:00+08:00
```

业务时区固定为 `Asia/Shanghai`，查询快照时钟固定为 `2026-03-31T23:59:59+08:00`。数据库无时区字段只在读取边界按该时区解释，规范 API 时间使用 UTC RFC 3339。当前阶段禁止 Domeye Core 连接原生产数据库，也禁止执行实时数据库激活、回滚或直接源库制品构建。

## 运行结构

```text
Nginx 127.0.0.1:28471
  └── Flask 127.0.0.1:28473（Screen: domeye_core_app）
        └── 只读数据库 127.0.0.1:31627

本地真实数据联调
  └── Flask 127.0.0.1:31629（Screen: domeye_core_dev_api）
        └── 同一只读数据库 127.0.0.1:31627
```

两个 API 均由同一个受控启动器管理，显式设置 `DOMEYE_CORE_SKIP_LOCAL_ENV=true`，不会读取 `backend/.env`。它们只使用开发四文件 INFO_DIR、数据库只读账号、固定时间窗口和固定快照时钟。

从旧运行方式首次切入该数据档时，必须保持 `domeye_core_dev_api` 健康，先用 `deploy/stop-backend.sh` 停止没有冻结身份标记的旧 `domeye_core_app`，再执行 `deploy/manage-fixed-backend.sh start`。冻结启动器会故意拒绝自动停止或接管同名旧 Screen，不能为简化切换而放宽身份校验。若新 `28473` 未能启动，回退方式是让 Nginx 临时代理仍然健康的 `31629`，不得恢复原生产库配置。

## 常用命令

```bash
cd /home/bgpdata/Domeye-Core

./deploy/manage-fixed-backend.sh start
./deploy/manage-fixed-backend.sh status
./deploy/manage-fixed-backend.sh health
./deploy/manage-fixed-backend.sh stop

./deploy/build-fixed-frontend.sh <release-id>

./dev/backend/manage-dev-api.sh status
./dev/database/manage-dev-database.sh status
./deploy/status.sh
```

数据库 `prepare`、`verify`、`start` 和 `stop` 会在任一二三月 API 仍运行时拒绝操作，避免卸载正在使用的 OverlayFS。

生产前端只能通过 `build-fixed-frontend.sh` 构建和原子安装。脚本固定注入 `VITE_DATA_WINDOW_START` 和 `VITE_DATA_WINDOW_END`，避免浏览器退回系统当前时间；本地 `API_MODE=real` 同样被禁用，真实数据联调统一使用 `API_MODE=remote`。

## 恢复实时分析的前置条件

恢复实时数据分析不是普通启停操作，必须单独确认并完成：

1. 通过单独设计和评审的数据档切换方案替换 `config/data-profile.json`；不得在 Shell、前端或后端中直接复制新的时间常量。
2. 重新生成并验收独立数据库制品，不允许后端直接连接原生产库。
3. 完成数据库恢复、只读账号、静态信息制品和固定镜像验收。
4. 运行完整接口、前端、Nginx、隔离和回滚验收。
5. 明确切换窗口后，才允许执行实时数据库激活和后端配置生成。

在上述条件完成前，不得恢复旧 `.env`，也不得以紧急回滚为由让 Domeye Core 重新连接原生产库。
