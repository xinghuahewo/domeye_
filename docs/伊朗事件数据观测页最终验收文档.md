# 伊朗事件数据观测页最终验收文档

> 文档状态：目标效果合同
>
> 验收对象：`country_outage/2026-02-27 09:12:32/IR/1/r`
>
> 本文只定义页面最终呈现的效果、信息语义和验收判定，不规定开发阶段、技术实现、
> 数据结构、组件拆分、人员分工或排期。

## 一、文档目的

伊朗事件详情页最终应当是一张以图表为主体的 BGP 数据观测页。页面负责让用户看见：

- 观测覆盖了什么时间、collector、VP 和固定人口；
- IP/前缀资源状态在窗口内如何变化；
- BGP ANNOUNCE 与 WITHDRAW 报文如何变化；
- 哪些时间槽出现了窗口内峰值、谷值、最大变化和持续状态；
- IPv4、IPv6、ASN 等维度之间存在什么可直接读取的数值差异；
- 当前数据不能覆盖哪些范围。

页面不负责替用户解释这些变化意味着什么，不负责形成事件生命周期、恢复、因果、
影响程度、前兆关系或行动建议。上述分析能力属于后续 Agent，而不是当前数据展示页。

若本文与既有事件详情页文档在“前端是否应直接给出分析结论”上存在冲突，以本文作为
本次伊朗验收事件前端效果的验收基准；BGP 控制面、单 collector、固定人口、缺失值和
时间边界等既有安全边界继续有效。

## 二、最终页面定位

最终页面的角色是“可供人和 Agent 读取的观测数据底板”，不是研究报告，也不是自动
研判结果。

页面可以提供描述性统计，包括：

- 数量、比例、差值和变化率；
- 窗口内最大值、最小值、峰值和谷值；
- 最大单槽上升、最大单槽下降和绝对变化量排序；
- 连续状态持续的槽数和时间；
- 同一指标在地址族、ASN 或 VP 维度上的分布。

页面不得把描述性统计继续解释为：

- 事件正在扩大、稳定、恢复或已经结束；
- 当前只有一个 episode 或一个 wave；
- 某个更早记录是本次变化的前兆或原因；
- 某个 ASN、运营商、政策、物理链路或行为主体应当负责；
- BGP 控制面变化等同于用户流量或服务中断；
- 窗口内极值等同于长期正常范围之外的异常程度。

## 三、整体视觉效果

页面从上到下形成一条连续的数据阅读路径：

1. 事件身份与观测范围；
2. IP/前缀资源状态主图；
3. 相邻时间槽变化强度；
4. BGP 报文活动；
5. IPv4 与 IPv6 对比；
6. ASN 可见状态与持续时间；
7. 指标定义、数据限制和审计身份。

图表是页面主体，文字只承担以下辅助作用：

- 指标名称、单位、分母和统计范围；
- 图表操作提示；
- 数据缺失、正常带不可用和观测范围说明；
- 不得跨越的解释边界。

页面不得依赖长篇摘要、结论卡片、研究问答或证据编号串联出“完整故事”。

### 通用模板复用边界

伊朗是本验收文档的首个数据实例，不是展示组件的硬编码边界。通用事件观测模板必须
由 `event_observation_v1` 数据合同驱动国家、事件身份、collector、时区、观察窗口、
时间粒度、固定人口、可用图表和统计范围。

通用模板不得硬编码国家、collector 或时间粒度。替换一份满足同一合同的观测数据后，
页面应自动替换标题、范围标签、报文统计范围、横轴时间语义和连续状态时长；不得要求
修改页面组件。某个数据实例没有国家资源、地址族拆分或 ASN 状态数据时，对应图表应
不出现，不得用零值或伊朗数据占位。

模板复用只复用展示结构，不扩张数据含义。不同国家或事件仍需各自的数据生产、质量
状态和观测边界，不能因为使用同一模板就推定具有相同事件阶段、影响或原因。

## 四、最终效果要求

### FA-01：首屏是观测身份，不是事件结论

首屏应直接显示：

- 伊朗及事件引用身份；
- RRC25 单 collector；
- 北京时间观察窗口；
- 五分钟状态粒度；
- 窗口起点唯一 VP 数量；
- 固定 origin ASN 和 Prefix×VP 人口；
- 状态点完整度、质量状态和最后观测时间。

首屏不得显示 `ONGOING`、严重等级、当前判断、恢复状态或带有解释性的事件摘要。
事件类型可以作为历史登记身份显示，但不能代替实际指标变化。

### FA-02：观测边界在阅读图表前即可看见

用户无需打开折叠面板即可知道：

- 当前数据只代表 RRC25 视角；
- 当前数据是 BGP 控制面状态和报文，不是用户流量或服务可用性；
- 所有核心比例使用固定人口；
- 正常带不可用；
- 正式窗口开始前和结束后的同口径状态没有被本页覆盖。

边界说明应简短、靠近首屏或主图，不应扩展成分析结论或行动建议。

### FA-03：IP/前缀资源状态是页面主视觉

页面最主要的图表必须使用统一时间轴展示固定人口内的资源状态，至少能够读取：

- 可见 Prefix×VP 数量；
- 不可见 Prefix×VP 数量；
- Prefix×VP 可见率；
- 可见 origin ASN 数量；
- 全可见、部分可见和全不可见 ASN 数量。

绝对数量应当能够被直接读取；比例只能在分母清楚的前提下显示。不同单位、不同方向或
数量级明显不同的指标，不得仅为了减少图表数量而堆叠在一个难以解释的纵轴上。

如果页面展示“前缀数量”，它必须是真正的唯一前缀统计；Prefix×VP 不得简写或冒充为
唯一前缀数。

### FA-04：变化强度通过相邻槽差值直接展示

页面必须让用户看见相邻五分钟状态之间的变化，而不只看见平滑后的总体曲线，至少包括：

- 可见 Prefix×VP 的单槽差值；
- Prefix×VP 可见率的单槽百分点变化；
- 可见 origin ASN 的单槽差值；
- ANNOUNCE 与 WITHDRAW 的单槽数量变化。

正向和负向变化应以零线为共同参照。窗口内最大单槽上升、最大单槽下降和最大绝对变化
可以突出显示，但必须写明是“当前观察窗口内”的排序，不得称为相对长期正常水平的
显著异常。

### FA-05：BGP 报文图与资源状态图时间对齐

页面必须在与资源状态一致的时间语义下展示：

- ANNOUNCE 数量；
- WITHDRAW 数量；
- UPDATE 总量；
- WITHDRAW 占 UPDATE 的比例；
- 各指标的窗口内峰值和对应时间。

报文统计必须明确是 collector 全量还是伊朗固定人口相关范围。无法确认统计范围时，
页面应标记为未知，不得让用户误以为报文数量与资源状态使用相同人口。

报文活动只能作为独立观测指标，不能被写成影响人口、用户规模或事件原因。

### FA-06：IPv4 与 IPv6 使用同尺度并列比较

页面必须让用户在共享时间轴上比较 IPv4 与 IPv6 的：

- 可见 Prefix×VP 数量；
- 固定人口分母；
- 可见率；
- 单槽变化量；
- 各自窗口内峰值和谷值。

图表应使用并列小图、同尺度切换或其他不会掩盖量级差异的方式呈现。标题和辅助文字只
描述比较对象，不直接替用户总结哪个地址族“受影响更严重”。

### FA-07：ASN 状态以分布、热力图和持续时间呈现

页面必须能够观察 ASN 维度的集中与持续情况，至少提供：

- 每个时间槽中全可见、部分可见、全不可见 ASN 的数量分布；
- ASN × 时间槽的可见状态热力图；
- 单个 ASN 连续处于某种状态的最长时长；
- 可见状态持续时间分布；
- ASN、地址族和固定人口规模的筛选或排序。

该区域使用“ASN 可见状态”“状态持续时间”等中性名称，不使用“持续受影响 ASN”
作为已经完成影响判断的标题。排序不得暗示用户规模、商业重要性或责任归属。

### FA-08：关键时间嵌入对应图表

页面不再设置独立的“时间语义”卡片区。关键时间应标注在产生该时间的指标图表上，
并至少包含：

- 观察窗口开始；
- 规则首次满足；
- 最大单槽变化；
- 各指标自己的峰值或谷值；
- 观察窗口结束。

每个标注必须同时显示“时间、指标、数值”，例如：

```text
22:35 · 可见 Prefix×VP 窗口最小值 · 316,733
```

不同指标的极值发生在不同时间时必须分别标注，不得合并成一个“最严重时刻”。

旧事实记录时间位于主观察窗口之外，只能作为历史身份或独立上下文时间带显示。不得为
了把它放入主图而压缩五小时状态曲线，也不得用视觉连续性暗示中间存在同口径数据。

### FA-09：所有描述性统计具有可核对语义

任一数量、比例、变化率、峰值、谷值和持续时间都必须能够回答：

- 指标统计的对象是什么；
- 分子和分母是什么；
- 单位是什么；
- 时间粒度是什么；
- 使用哪个 collector 和固定人口；
- 极值是在什么窗口内计算；
- 缺失值如何表达。

相同名称不得指代不同人口或不同计算口径。不同人口、不同快照和不同定义的历史数字
不得直接相减或绘制为可比较序列。

### FA-10：缺失、未知和正常带不可用被诚实展示

缺失值必须显示为“缺失”或“未知”，不得转换为 0、正常、未发生或已经恢复。

正常带不可用时，页面可以展示窗口内实际变化和窗口内排序，但不得显示：

- 相对长期正常值的偏离幅度；
- 标准差或异常分数；
- 已回到正常水平；
- 基于窗口起点伪造的正常线。

观察窗口开始时已经处于某种状态，只代表“窗口起点的观测值”，不代表精确事件起点。
观察窗口结束时出现数值回升，只代表终点数值，不代表恢复结论。

### FA-11：页面不生产分析 Agent 才应给出的结论

最终页面主内容中不得出现：

- episode、wave 或事件分段数量；
- `ongoing`、进行中、部分恢复、完全恢复、尚未恢复；
- 候选前兆、时间相关或因果未评估模块；
- 当前结论、结论等级、置信度卡片；
- 根因、责任主体、政治、物理或行为意图推断；
- 下一步研判顺序或行动建议；
- 把控制面数据外推为实际用户和服务影响的文案。

数据来源、哈希、质量和指标定义可以保留在折叠审计区，但证据编号不得重新成为页面
主叙事。

### FA-12：图表交互、响应式和可访问性可用

所有时间图表应具有一致的北京时间语义，并支持：

- 共享或可对齐的时间游标；
- Tooltip 中读取精确时间、数值、单位和分母；
- 数量与比例的明确切换；
- IPv4、IPv6 或指标系列的显示控制；
- 缺失点断开显示；
- 桌面和移动视口下无横向页面溢出。

移动端可以把并列图表改为纵向排列，但不得删除关键指标或让时间标注互相遮挡。
颜色不能成为区分状态的唯一手段；图例、文字或图形纹理必须提供第二种识别方式。

## 五、页面最终阅读顺序

### 5.1 首屏

用户首先看到事件身份、数据范围、质量和固定人口，以及资源状态主图的开端。首屏不先
给出结论，也不要求用户阅读研究摘要。

### 5.2 主图区

用户沿同一时间轴依次观察资源状态、单槽变化和报文活动。图表之间的时间对齐能够帮助
用户比较，但页面不替用户判断它们之间是否存在因果关系。

### 5.3 维度区

用户通过 IPv4/IPv6 对比、ASN 状态分布和热力图查看变化集中在哪些维度以及持续多久。

### 5.4 边界与审计区

用户最后按需展开指标定义、数据限制、来源文件、质量状态和哈希身份。该区域用于核对，
不承担前台叙事。

## 七、允许存在的内容

以下内容可以保留，但必须处于辅助位置：

- 旧事实记录的引用身份和登记时间；
- 数据质量状态、引擎版本、交付文件哈希；
- 固定人口来源和指标计算说明；
- 正常带不可用、窗口左右边界和单 collector 限制；
- 原始数据或审计信息入口；
- 明确标为“窗口内”的描述性峰值、谷值、变化和持续时间。

## 八、不构成最终通过的情况

以下任一情况存在时，不得宣称最终页面通过：

- 只是删除旧文案，但没有建立可读取的主图、变化图和维度图；
- 图表仍以长篇结论文字为主要信息来源；
- 把受影响 ASN 比例与 Prefix×VP 可见率混在同一纵轴且无法辨别；
- 把 Prefix×VP 写成前缀数量；
- 把不同指标的峰值和谷值合并为一个事件时间；
- 为了显示“突变”而伪造正常带或不公开判断规则；
- 把观察窗末数值回升写成恢复状态；
- 只展示 ANNOUNCE/WITHDRAW，却没有说明报文统计范围；
- 移除边界说明，使用户可能把 RRC25 控制面结果理解为全国服务事实；
- 桌面图表可用，但移动端丢失指标、时间或数值；
- 用代码完成、接口可用、测试通过或视觉截图代替最终效果验收。

## 九、最终判定

最终判定只有三种：

- **通过**：FA-01 至 FA-12 全部满足；
- **不通过**：至少一项已经确认偏离最终效果；
- **阻塞**：缺少数据、设计或验收证据，暂时无法判断。

阶段性完成、局部图表完成或 Hook 被调用均不等于最终通过。只有用户最终看到的页面
同时满足全部要求，才能宣告伊朗事件数据观测页验收完成。
