## 五、对审计项 A1 的最终判定

`c0f3be3`「添加ip前缀过滤」引入 `normalize_bgp_prefix` 与
`get_feature_prefix_skip_reason`（v4 `</8`、v6 `</16` 跳过），提交时间
`2026-03-25 07:27:17 UTC`。

窗口内最后一次特征进程启动为 `2026-03-25 06:54:53 UTC`（PID 67265），
**早于该提交 33 分钟**；窗口内不存在更晚的特征进程启动。

因此：

- 前缀长度过滤**从未被任何产出二三月数据的进程加载**；
- **A1 对本窗口不成立**——检测侧与特征侧在窗口内使用同一前缀口径，
  不存在"两条管线前缀口径不同"的情况；
- A1 仅在未来复用该 Python 实现时才成立，属实时接入债务，不属本数据档问题。

同理，`FEATURE_EXCLUDED_PREFIXES`（注释日期 2026-04-06）既晚于窗口，
其调用点也从未传入 `prefix` 参数，与二三月数据无关（S6 结论不变）。

结论类型：**代码事实**。本节不含数据级测量结论。

## 七、对后续阶段的影响（决策门已触发）

分阶段计划的门条件——"若生产者身份大部分不可得，R2 结论强度下降，
应考虑以有界原始重算替代纯测量"——**已触发，且比预估更严重**：不是
"2026-02-01~03-06 不可得"，而是**检测侧全窗口不可得**。

因此 R2 必须调整：

1. 检测侧（F2 私有 ASN、S2 泄漏闩锁、S4 MOAS 归属）不能以"代码版本 X 产生了该表"
   建立归属，必须以**有界原始重算**在候选环境重放小样本，与旧表逐项比对；
2. 特征侧 3 月 03-12 之后可用纯只读测量；
3. 任何"某缺陷影响了该表"的结论都必须来自重算比对或数据测量，不得来自代码阅读。
