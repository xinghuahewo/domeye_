逻辑边界固定为：

```text

  ├─→ raw MRT record sidecar
```

S1 没有建立 Prefix×VP 事实库。Prefix×VP 只是 S2 RouteState 的主键维度；
RouteState Checkpoint 只能是同一 RouteState 的可恢复快照；Prefix×VP Evidence 只能在
S5 从指定 RouteState/Publication 派生。

## 三、完整 RouteEvent 效果

1. 输入文件只读打开，解析时流式重算压缩字节数和 SHA-256；逻辑源根固定为
   `domeye://raw/rrc25-global-20260224-20260310-v1`，与 artifact `relative_path`
   组合成稳定 URI；完整校验后才写入
   `input_integrity_status=gzip_passed_and_stream_sha256_verified`；
2. 每个物理 MRT record 保存 ordinal、解压偏移、header+payload 总长度、type/subtype
   和 record SHA-256；
3. 每个逻辑元素保存由原始文件 SHA-256、record ordinal 和 element ordinal 确定的稳定
   RouteEvent ID；
4. RouteEvent 保存 VP peer IP/ASN、prefix、地址族、动作、事件时间、origin、完整
   AS_PATH 引用、属性 SHA-256 引用、原始坐标、质量标记和缺失理由；collector、源对象
   和修复血缘由逐事件所在的不可变分区清单绑定；
5. AS_PATH 保留 AS_SEQUENCE、AS_SET、AS_CONFED_SEQUENCE 和 AS_CONFED_SET，
   AS4_PATH 按 RFC 6793 重建，不用 origin 冒充完整路径；
6. 每个 artifact 形成确定性 `records.jsonl.gz`、`events.jsonl.gz`、
   `paths.jsonl.gz` 和分区清单；全局内容身份绑定窗口、来源、实现、修复血缘、人口和
   全部分区身份；
7. `ingest_time_utc` 与 `parse_time_utc` 只保存为操作证据，不进入语义内容摘要；
8. `--resume` 会逐文件重算大小和 SHA-256，任一篡改、人口偏差、完成清单副本偏差、
   并发写入或实现身份变化都失败关闭。

机器合同为
[`rrc25-route-event-store.schema.json`](../../contracts/data/rrc25-route-event-store.schema.json)。
