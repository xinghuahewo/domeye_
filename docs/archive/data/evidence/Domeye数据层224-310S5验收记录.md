- collector：`rrc25`；

- 本阶段只闭合发布时编译的事件读模型、紧凑序列、Prefix×VP Evidence 派生视图、
  只读 API 和不可变报告快照；不修改现有页面、Sidecar、`backend/core/`、部署配置或
  生产运行时，不执行 S6 旧库迁移或切换。

逻辑关系固定为：

```text
S2 唯一 RouteState（Prefix×VP 是主键维度）
  ├─ S3 国家五分钟指标 ─┐
  └─ Seed / 终点 Checkpoint ─ Prefix×VP Evidence 派生页
                              （只读、可删除、可重建）
S4 Incident + Observation/Analysis Publication ─┤
                                                 ↓ 发布时编译
事件快照 + 4,320 点紧凑序列 + Evidence View + 报告快照
                                                 ↓
只读 API
```

Prefix×VP Evidence 没有状态推进器和写入入口，不是平级事实库。它只把 S2 Seed cohort
在指定终点 RouteState 中的值按国家分页物化，并由事件的 Observation Publication 形成
逻辑 Evidence View。43 国物理页去重保存；81 个事件只登记各自的 Publication 绑定。

## 三、DLAE-12：预计算读模型与 API

### 3.1 发布时编译结果

- 81 个事件读模型均一次绑定 incident、Observation Publication、Analysis Publication、
  revision、窗口、三条 lifecycle fact、质量、TrendProfile、紧凑序列和 Evidence View；
- 43 个国家各有一份 4,320 点紧凑序列。时间以首状态点、300 秒步长和点数编码，不重复
  携带 4,320 个时间字符串；最大压缩响应为 45,317 字节，低于 1 MiB；
- 1,527,242 条物理 Prefix×VP 派生状态分成 1,551 个固定页。每条保留
  `collector + peer + prefix + address_family`、Seed origin、终点可见性、终点 origin、
  AS_PATH/属性摘要、最后 RouteEvent 坐标、更新时间和质量；
- 81 个逻辑 Evidence View 均保存 `derived_from_route_state_id`、Observation
  `publication_id`、投影器 `1.0.0` 和内容摘要。多个同国事件复用同一组不可变物理页，
  因而数据库中的 4,697,113 条逻辑引用人口不构成第二次状态存储；
- ASN 和 Prefix×VP 明细不进入事件首页或报告主载荷，只有显式下钻请求才读取一个已编译页。

### 3.2 API 读路径与性能

正式环境为 `buptserver16`、Python 3.10.12、服务已启动且 HTTP 连接缓存为空；首次访问
81 个不同事件定义为冷样本，随后五轮共 405 次定义为热样本。结果：

| 验收项 | 实测 | 预算 |
|---|---:|---:|
| 事件快照冷读 P95 | 1.481 ms | ≤ 2,000 ms |
| 事件快照热读 P95 | 1.539 ms | ≤ 500 ms |
| 报告快照 P95 | 1.166 ms | 不越过 5 秒调用预算 |
| 紧凑序列 P95 | 0.897 ms | ≤ 2,000 ms |
| 紧凑序列最大响应 | 45,317 字节 | ≤ 1 MiB |

访问审计实际覆盖事件、序列、报告、Evidence 元数据和 Evidence 页共七次请求；每次都明确
记录 `raw_mrt_scanned=false`、`route_event_scanned=false`、
`full_asn_state_scanned=false`、`publication_recomputed=false`。性能通过不是靠扩大 Sidecar
超时、增加进程或反复预热取得。

用户此前指出的两个入口也已直接抽查：
