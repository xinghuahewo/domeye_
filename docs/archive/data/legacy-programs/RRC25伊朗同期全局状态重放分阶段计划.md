# RRC25 伊朗同期全局状态重放分阶段计划

版本：1.0  
约束：只定义阶段入口、阶段出口和实施边界  
最终效果基准：
[RRC25伊朗同期全局状态重放最终验收文档](./RRC25伊朗同期全局状态重放最终验收文档.md)

## 一、总入口

- 伊朗 18:05–23:00 状态重放已经形成可复核的输入、cohort、60 点状态和页面
  基线；
- 同期输入已冻结为 1 个 RRC25 RIB、25 个 catch-up UPDATE 和 59 个正式 UPDATE；
- 现有重放完整读取全球 RIB，但只保留确定属于伊朗的状态；
- 通用国家中断页面与 v2 API 已能消费固定 cohort、状态、分页和审计数据；
- 本次尚未证明一次全球状态能够同时投影全部国家并接续后续增量 UPDATE。

## 二、总出口

- 同一冻结输入只生成一份确定性的 RRC25 全球 RouteState；
- 84 个 UPDATE 只通过一条有序状态流应用；
- 全部可归属国家和显式未知桶均有固定 cohort 与 60 点状态；
- 全球、国家、ASN、地址族和未知桶满足人口守恒；
- 伊朗结果与既有验收基线无损一致；
- 非伊朗国家无需专用重放即可被通用 API 和页面消费；
- 23:00 checkpoint 可作为后续增量 UPDATE 的起始状态；
- GSR-01 至 GSR-14 全部通过并留下阶段回检结论。

## 三、全局边界

- 只使用冻结的 RRC25 08:00 RIB 和 UTC `[08:00,15:00)` 的 84 个 UPDATE；
- “全球”只代表单 collector RRC25 控制面视角；
- 不扩大到其他日期、其他 collector 或 1,928 个 UPDATE；
- 不修改 `backend/core/`、旧 Detection 或现有伊朗不可变交付包；
- 不写旧业务数据库，不切换生产实时链路；
- 不为国家样本伪造国家中断事实、恢复、原因或服务影响；
- 未达到本阶段出口时不得进入下一阶段；
- 每阶段结束必须调用全局状态重放最终验收防偏离 Hook；
- 后续阶段不得通过降低最终验收要求消除前序偏离。

## 四、阶段入口、出口与边界

### S0：输入、基线与最终效果冻结

#### 入口

- 冻结 MRT 输入和既有伊朗验收包可读取；
- 最终验收文档已经存在；
- 尚未形成全球重放现状基线。

#### 出口

- 1 个 RIB、25 + 59 个 UPDATE、60 个状态点和时区边界可复核；
- 伊朗不可回退数值、mapping、算法和数据身份已冻结；
- GSR-01 至 GSR-14 的验收范围与非目标无冲突；
- S0 Hook 结论为“一致”或“已修正”。

#### 边界

- 不执行真实全球重放；
- 不修改生产数据；
- 不把目标设计写成当前已有能力。

### S1：全球状态、国家落位与 cohort 合同闭合

#### 入口

- S0 出口全部成立；
- 输入与伊朗基线保持冻结。

#### 出口

- RouteState 身份、UPDATE 顺序、country mapping、未知桶和固定 cohort 语义闭合；
- 全球、国家、ASN 和地址族人口守恒式可机器判定；
- checkpoint、处理游标、revision 和 COMPLETE 身份合同可复核；
- GSR-02 至 GSR-05、GSR-07、GSR-08、GSR-11 至 GSR-13 到期合同通过；
- S1 Hook 结论为“一致”或“已修正”。

#### 边界

- 不以国家代码设计状态分支；
- 不把 AS_PATH 中间节点当作 origin 国家；
- 不用零值代替 mapping unknown、歧义或不适用。

### S2：全球 RIB 初始状态闭合

#### 入口

- S1 合同和质量门全部成立；
- RIB 输入身份、资源上限和恢复目录已冻结。

#### 出口

- 完整 RRC25 seed RIB 形成唯一全球状态；
- 全部国家 cohort、未知桶和人口守恒通过；
- 伊朗 seed cohort 与既有基线一致；
- RIB checkpoint 可重载并得到相同人口与哈希；
- GSR-01、GSR-02、GSR-04、GSR-05、GSR-07、GSR-11 至 GSR-13 到期部分通过；
- S2 Hook 结论为“一致”或“已修正”。

#### 边界

- 本阶段不处理 84 个 UPDATE；
- 不因性能方便只保留验收国家；
- 不发布未闭合的全球人口。

### S3：单 UPDATE 流与 60 点状态闭合

#### 入口

- S2 全球 RIB checkpoint 已通过；
- 84 个 UPDATE 的连续性、角色和哈希已冻结。

#### 出口

- 25 个 catch-up 和 59 个正式 UPDATE 只应用一次；
- 18:05–23:00 的 60 个全球状态点完整；
- 国家迁移、替换、撤回、重复和未知事件计数闭合；
- 中途恢复与连续运行末状态一致；
- GSR-03、GSR-06、GSR-08、GSR-11、GSR-12 到期部分通过；
- S3 Hook 结论为“一致”或“已修正”。

#### 边界

- 不启动国家级独立重放；
- 不以并行解析改变状态应用顺序；
- 不读取 15:00 之后的真实 UPDATE。

### S4：国家投影、伊朗对账与非伊朗覆盖闭合

#### 入口

- S3 的全球 60 点状态和处理游标完整；
- 全球、国家和未知桶均可查询。

#### 出口

- 所有非零 cohort 国家生成同合同的 60 点状态；
- 全球、国家、ASN 和地址族逐槽守恒；
- 伊朗 60 点和 cohort 与既有验收包逐项一致；
- 非伊朗大、中、小 cohort 样本完成数值对账；
- GSR-05、GSR-07、GSR-09、GSR-10、GSR-13 到期部分通过；
- S4 Hook 结论为“一致”或“已修正”。

#### 边界

- 样本只增加验收覆盖，不限定实际生成国家；
- 不为无真实事件的国家伪造事件；
- 不通过修改伊朗基线消除差异。

### S5：通用 API、页面与增量接续效果闭合

#### 入口

- S4 国家数据和审计身份全部闭合；
- 通用国家观测 API 与页面可在隔离候选环境使用。

#### 出口

- 伊朗和非伊朗样本由同一 overview、series、ASN、audit 合同读取；
- 伊朗真实事件以及至少一个非伊朗合法验收事件引用均通过同一事件解析和页面
  路由进入通用页面；隔离验收引用不得写入真实事件列表；
- 页面只使用事件携带或解析得到的 country、collector、窗口、cohort、revision
  和 data_through，不使用伊朗默认值；
- capability、来源模式、revision、data_through 和缺失状态可见；
- 从 23:00 checkpoint 至少追加一批时间连续的新 UPDATE，过程中不重新读取
  RIB；
- 新批次处理完成后 data_through 单调推进，页面能够读取新增时间点；
- 页面不增加国家专用组件或字段解释；
- GSR-10、GSR-13、GSR-14 到期部分通过；
- S5 Hook 结论为“一致”或“已修正”。

#### 边界

- 只使用隔离候选，不切换生产；
- 不以 Mock 页面代替真实交付包消费；
- 不把隔离验收事件引用发布成真实国家中断事件；
- 不把历史重放标记为实时数据。

### S6：最终重现与整体效果验收

#### 入口

- S0 至 S5 出口全部成立；
- 输入、状态、国家投影、API 和页面证据可共同复核。

#### 出口

- GSR-01 至 GSR-14 全部通过；
- 连续运行、checkpoint 恢复和独立重复运行结果一致；
- 伊朗与非伊朗样本同时通过数据、API、页面和审计验收；
- 未知、缺失、失败和窗口外语义没有被改写；
- S6 Hook 给出最终“一致”或“已修正”结论。

#### 边界

- 不以局部单测、退出码或文档检查代替最终数据效果；
- 不把未执行的生产实时接入写成已经完成；
- 不授权扩窗、生产切换、旧核心替换或因果分析。

## 五、阶段封口

- Hook 必须同时回读最终验收文档和本计划；
- Hook 必须核对阶段入口、出口、边界和到期 GSR；
- 回检结论只允许为“一致”“已修正”“无影响”或“存在待处理偏离”；
- “存在待处理偏离”必须列出 GSR 编号、位置和原因；
- Hook 结构检查通过不等于数据、恢复、API 或页面效果通过；
- S6 只有在 GSR-01 至 GSR-14 全部通过后才能宣告最终完成。

阶段结束调用：

```bash
python3 .codex/hooks/rrc25_global_state_replay_review.py --stage S0
```

后续阶段将 `S0` 替换为对应阶段编号。
