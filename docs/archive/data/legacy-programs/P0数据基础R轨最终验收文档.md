# P0 数据基础 R 轨最终验收文档

版本：1.1（2026-07-27 整体合理性审查后修订）  
状态：最终效果合同  
适用对象：Domeye Core 固定数据档 `feb-mar-2026` 的数据基础  
起始等级：`P0 历史数据兼容准入`  
目标等级：全窗口 `raw_traceable`，且遗留语义风险已结案

## 一、文档目的

本文只规定 R 轨结束时数据基础必须达到的可观察状态，不规定实施顺序、模块划分、
脚本名称、数据库结构或人员分工。阶段划分见
[P0 数据基础 R 轨分阶段计划](./P0数据基础R轨分阶段计划.md)。

R 轨承接 [P0 数据基础建设计划](./P0数据基础建设计划.md) 第 15 节声明的"另立任务"，
并补入该计划未覆盖的两项：生产者代码身份绑定，以及复制保真与语义正确的分离。

本文不要求二三月历史数据被改写为"正确"数据。历史事实由原 Domeye 生产处理产生，
R 轨只负责让这些数据的来源、覆盖、正确性风险和不可得边界成为已知量。

## 二、最终状态定位

R 轨结束时，任何人对固定数据档中的任一数值提问，都应当能够得到四类回答之一：

1. 该值可追溯到原始记录，且原始引用、哈希与 VP 身份可复核；
2. 该值只具备历史兼容身份，其生产者代码身份为已登记的不可得；
3. 该值受某项已确认的遗留语义风险影响，影响范围与量级已测量；
4. 该值所在槽位为已登记的缺失，缺失原因明确。

不允许出现第五类：无人知道该值从哪来、是否受已知缺陷影响、覆盖是否完整。

## 三、最终效果要求

### RFA-01：生产者身份可解析或显式不可得

- 二三月每张事实表与特征表具备可解析的生产者身份记录；
- 生产者身份必须以机器清单逐条覆盖 37 张目标表，不能只用表族或通配符汇总；
- 每条记录至少包含原项目代码标识、算法版本、产出时间归属和证据引用；
- 原系统没有独立算法版本号时，可将进程启动时绑定的完整 Git 内容 SHA
  作为 `git_commit_content` 算法版本，但必须显式写明版本方案；
- 无法恢复的部分必须登记为 `unrecoverable` 并写明原因，不得留空；
- 不得以数据库转储身份代替生产者代码身份。

### RFA-02：复制保真与语义正确分离命名

- 源精确对账与独立语义对账是两个独立门禁，具有各自名称与报告；
- 源精确对账只声明旁路数据忠实复制原表，不得被表述为数据正确；
- 独立语义对账必须以独立基准重算，不得以源表自身作为正确性依据；
- 任何文档、报告、接口字段或页面文案不得使用无限定词的"对账"指代正确性。

### RFA-03：遗留语义风险由数据结案

- F2、S2、S4 三项各自取得确认或排除结论；
- 确认项必须给出受影响指标与量级，排除项必须给出排除依据；
- 结论必须来自只读数据测量或有界原始重算，不得来自代码阅读推断；
- 规则日期晚于数据窗口的项目（S6）不得进入二三月污染论证。

### RFA-04：原始槽覆盖为已知数

- 全窗口 UPDATE 与 RIB 槽位的准入、不可得与解析失败数量为确定值；
- 每个未准入槽位具备登记原因；
- 覆盖率以实测值表述，不使用"基本完整""大部分覆盖"等模糊表述；
- 不得以抽样覆盖率冒充全窗口覆盖率。
- 源仍可得但项目方拒绝补取属于范围决定，可登记但不得表述为源不可得，
  也不得据此宣称全窗口原始覆盖已经完成。

### RFA-05：全窗口 RouteEvent 闭合

- 在明确声明的事件范围内，RouteEvent 具备语义解析、稳定 VP、原始偏移与记录哈希；
- Incident、RouteEvent 与原始引用三者互相可达；
- 声明范围之外的部分明确标注为未闭合，不得默认视为已闭合；
- RouteEvent 不再是 pilot 身份。

### RFA-06：语义复现结果可归档

- 全量跨运行语义复现已执行并产出可归档结果；
- 复现差异（若有）具备登记与解释，不得以"环境差异"一句带过；
- 复现未通过时保持 `raw_traceable` 未达成状态，不得部分声明达成。

### RFA-07：缺失与不可得诚实表达

- 缺测、真实零值、解析失败与源不可得四类状态互相独立且可机器区分；
- 任何一类都不得在数据、接口或页面上被转换为 0、正常或已恢复；
- 聚合补零必须具备显式标记。

### RFA-08：冻结核心不被修改

- `backend/core/` 业务逻辑在 R 轨全程不被修改，`core.sha256` 校验持续通过；
- 新实现与旧实现的差异通过影子对账呈现，不通过改写冻结核心消除；
- 不得以更新哈希清单的方式掩盖变化。

### RFA-09：只读与激活分离

- R 轨全部检查与测量可只读重复执行，不产生数据库写操作；
- 候选制品准备、生产激活与回滚使用独立授权，不由本轨结论自动触发；
- 不连接原生产数据库，不恢复实时发布。

### RFA-10：等级声明不得越界

- 未满足 RFA-04 至 RFA-06 时，只能声明 `P0 历史数据兼容`，不得声明 `raw_traceable`；
- 不得使用"全量原始证据完成""生产已发布"等超出实际等级的表述；
- 等级声明必须可由归档证据复核。

### RFA-11：结论携带来源身份

- 任何对外结论标明其数据来源、运行身份与结论类型；
- 结论类型区分代码事实、候选验收、已部署事实与未来设计；
- 不得从代码目录问题推断页面数据错误，不得从验收文档推断生产部署。

### RFA-12：阶段结论不得通过降低要求达成

- 阶段偏离必须记录并修正，不得通过改写本文要求消除；
- 后续阶段不得重新定义前序阶段已确认的偏离；
- 每个阶段结束留下防偏离回检结论。
- `scope_stopped` 允许诚实结束工作，但不等于阶段 `passed` 或最终通过。

## 五、允许存在的内容

- 已登记原因的 `unrecoverable` 生产者身份；
- 已登记原因的未准入槽位与不可得原始制品；
- 已登记但不冒充不可得的范围终止决定；
- 明确声明范围的部分闭合；
- 标注为非业务样本的隔离验收数据；
- 未激活的候选制品。

## 六、不构成最终通过的情况

- 以源精确对账结果宣称数据正确；
- 以代码阅读结论宣称二三月数据已被污染或未被污染；
- 以抽样覆盖率表述全窗口覆盖率；
- 将缺测、解析失败或源不可得显示为 0 或已恢复；
- 修改 `backend/core/` 或更新哈希清单以消除差异；
- 在未满足 RFA-04 至 RFA-06 时声明 `raw_traceable`；
- 以脚本执行完成、测试通过或文档更新代替实际数据状态验收。
- 以 `scope_stopped`、范围缩减或“项目方接受”替代原阶段出口或最终效果。

## 七、最终判定

- **通过**：RFA-01 至 RFA-12 全部满足；
- **不通过**：至少一项已确认偏离；
- **阻塞**：缺少数据、原始制品或验收证据，暂时无法判断。
- **范围终止**：明确停止后续投入并保持较低等级；属于“不通过最终合同”的已知终态，
  不得改写为通过。

阶段性完成、脚本可运行或报告已生成均不等于最终通过。
