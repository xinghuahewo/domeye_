# INFO 目录数据落库最终验收文档

## 一、文档目的

本文只定义 INFO 目录数据完成数据库化以后，系统必须呈现的最终效果。
本文不规定开发阶段、代码结构、数据库表结构、迁移命令、人员分工或排期。

最终验收关注的不是“文件是否已经 COPY 进数据库”，而是：

- 数据是否完整、可解释、可追溯；
- 既有查询和检测语义是否被保持；
- 运行时是否真正摆脱对旧目录的依赖；
- 性能、安全、发布和回滚是否达到可长期运行的水平；
- 任何未知、异常或例外是否被诚实表达，而非被静默丢弃。

## 二、验收对象

最终验收对象是同一个不可分割的 static INFO release，包括：

- 来源目录合同规定的全部 24 个数据文件；
- 由这些文件形成的数据库内容；
- 对外查询、API 和检测器所消费的静态信息；
- 与该 release 对应的质量、追溯、性能、安全、激活和回滚证据。

文件来源、数据库内容、运行时快照和验收证据必须能够指向同一个内容身份。
不同内容身份的结果不得拼接成一次最终验收。

## 三、最终效果要求

### FA-01：来源身份唯一且可复现

同一份来源内容无论位于什么路径、何时重新核验，都得到相同的内容身份；任一文件、
字段合同、解析规则或优先级发生变化，均会形成新的内容身份。

验收者能够明确知道最终 release 来自哪 24 个文件、每个文件的内容哈希和逻辑记录数，
并能识别读取期间发生的替换、缺失、增添或软链接绕行。

### FA-02：全部数据都有去向

24 个文件中的每条逻辑记录最终只能处于以下两种可解释状态之一：

- 已进入其应属的可查询数据集合；
- 已进入具备明确原因的隔离集合。

逐文件满足：

```text
已接纳记录数 + 已隔离记录数 = 清单逻辑记录数
```

不存在静默跳过、无法解释的计数差、重复导入或以聚合总数掩盖单文件缺口。

### FA-03：既有数据语义得到保持

数据库化后的键类型、空值含义、大小写、顺序、去重、first-wins、最长前缀匹配、
AS 关系方向、私有 AS 判断、三元组稳定度和来源优先级，与批准的文件语义一致。

非规范值可以被规范化用于查询，但原始值必须仍可辨认；不得通过“清洗”把未知、
冲突或非法数据改写成正常值。

### FA-04：业务结果可追溯，异常可解释

任一对外可见的业务记录都能够追溯到明确的来源文件、来源位置和来源记录身份。
冲突、重复、非规范和非法记录均具有稳定分类及原因。

质量结论能够区分：

- 通过；
- 明确隔离；
- 当前未知；
- 来源缺失；
- 合同不适用。

“未知”和“没有”不得混用，“隔离”不得等同于“删除”。

### FA-05：运行时消费同一 release

一次 API 请求、一次静态快照装载和一次检测运行，只能消费一个固定的 INFO 内容身份。
运行期间即使当前 release 发生变化，已开始的工作也不会混入另一个 release 的内容。

用户能够从运行结果或运行证据中确认实际使用的 INFO 内容身份。

### FA-06：查询与 API 行为等价

ASN、prefix、国家、域名、AS 关系、pfx2as、私有 AS、重要 AS 和三元组等既有查询，
在批准的确定性样本和完整集合对账中不存在未批准差异。

批准隔离造成的差异必须逐项列明键、字段和原因，不能使用平均正确率、模糊相似度或
抽样通过率代替确定性对账。

### FA-07：检测行为等价

在固定 RIB、UPDATE 和 INFO 内容身份下，数据库来源与批准的文件来源对六类检测结果的：

- 事件数量；
- 自然键；
- 过滤原因；
- 风险级别；
- 关键描述；

不存在未批准差异。数据来源替换不得改变核心检测算法的业务含义。

### FA-08：性能和容量达到可运行水平

预热后的本地精确查询满足：

- 普通精确查询 p95 不高于 20 ms，p99 不高于 50 ms；
- longest-prefix-match p95 不高于 30 ms；
- 请求路径不会触发全表装载。

静态快照装载时间和峰值 RSS 相比批准的文件基线恶化不超过 10%，检测吞吐下降不超过
5%。当前 release、上一 release、构建临时空间和运行峰值能够同时容纳，不依赖临时
透支或人工删除回滚材料。

### FA-09：权限与隐私边界成立

应用运行身份只具备完成查询所需的最小只读权限，不能修改 release、业务数据、质量
结果或数据库结构。只有获准的发布身份能够改变 active release。

联系人原文不会出现在普通应用查询、日志、质量证据或影子差异中；对联系人数据的
访问与普通静态信息访问相互隔离。

所有检查类操作均无生产写入、激活、停止服务或删除数据的副作用。

### FA-10：激活与回滚可控

激活只能发生在全部最终门禁通过之后，并且只能把一个身份明确、证据完整的 release
设为当前版本。

出现问题时能够在批准的安全边界恢复上一 INFO release 或文件后端；回滚不依赖逆向
修改业务数据，不覆盖失败证据，并且不会让一次检测运行混用新旧内容。

### FA-11：运行状态可观察且可复核

运维人员能够回答：

- 当前和上一 INFO release 分别是什么；
- 每个来源文件接纳、隔离和未处理了多少记录；
- 当前 release 通过了哪些质量、行为、性能和安全门禁；
- 导入、校验、索引和维护操作消耗了多少时间与磁盘；
- 任一失败发生在哪个边界，是否可以从健康检查点继续。

相同来源、合同和程序版本能够产生可复核的一致结果。

### FA-12：旧目录不再是运行依赖，回滚材料仍然完整

最终运行状态下，API、检测器和普通后台进程对旧 INFO 目录的直接读取次数为零，也不
连接或复用原项目的数据库与进程。

旧来源保持只读，当前与上一 INFO release 以及获准的文件回滚制品仍然可用。更旧内容
只有在不再被 active、previous、候选、运行中快照或回滚策略引用时，才允许进入独立
清理评审。

## 四、量化验收总表

| 要求 | 最终可观察结果 |
|---|---|
| FA-01 | 24 个合同文件全部具备稳定身份；未知文件、缺失文件、软链接和读取中变化均被拒绝 |
| FA-02 | 24/24 文件逐文件计数守恒；无法解释的记录差为 0 |
| FA-03 | 全部已批准语义合同通过；未声明语义变化为 0 |
| FA-04 | 可见记录追溯覆盖率 100%；隔离记录原因覆盖率 100% |
| FA-05 | 单次请求、快照和检测运行涉及的 INFO 内容身份数量均为 1 |
| FA-06 | 确定性查询和集合对账的未批准差异为 0 |
| FA-07 | 六类检测固定输入 A/B 的未批准差异为 0 |
| FA-08 | 查询、最长前缀匹配、装载、RSS 和吞吐全部满足规定阈值 |
| FA-09 | 未授权读写成功次数为 0；联系人原文泄露次数为 0；检查操作生产副作用为 0 |
| FA-10 | 激活前门禁缺口为 0；回滚演练成功且不丢失失败证据 |
| FA-11 | release、逐文件、质量、耗时、容量和检查点状态均可复核 |
| FA-12 | 旧目录运行时直接读取次数为 0；当前、上一版本及回滚制品可用 |

## 五、允许的例外

以下情况可以存在，但必须显式记录，且不得破坏计数守恒和行为解释：

- 来源本身存在的非规范键、重复键或非法值；
- 经批准进入隔离集合的记录；
- 明确归类为历史、替代或用途未决的数据；
- 因来源事实不足而无法回答的问题；
- 已获得单独批准、具有完整影响说明的语义变化。

例外必须具备稳定身份、适用范围、原因、批准依据和对账影响。没有证据的口头说明不
构成例外批准。

## 六、不构成最终通过的情况

以下任一情况存在时，不得宣称最终验收通过：

- 只完成文件清点或部分文件落库；
- release 仍为 shadow、`validating` 或只能依赖人工绕过门禁；
- 只比较行数，没有比较自然键、字段和集合语义；
- 只通过 API 冒烟，没有完成六类检测固定输入 A/B；
- 用抽样通过率掩盖未批准差异；
- 用删除失败记录、质量证据或 failed release 的方式让检查变绿；
- 数据库可查询，但运行时仍直接读取旧目录；
- 新版本可激活，但上一版本无法安全恢复；
- 性能结果缺少文件基线或没有覆盖峰值 RSS、吞吐和容量；
- 联系人原文进入普通查询、日志或验收证据。

## 七、最终判定

最终判定只有三种：

- **通过**：FA-01 至 FA-12 全部满足，且所有证据属于同一内容身份；
- **不通过**：至少一项要求出现已确认偏差；
- **阻塞**：证据不足，尚不能判断是否满足；阻塞不得解释为通过。

最终通过是整体结论，不允许用多个不同 release 的局部通过结果拼接，也不允许用后续
阶段的成功覆盖先前阶段尚未解释的偏差。
