## 一、这份文档解决什么问题

这份文档用于帮助后续开发者、研究人员和新任务快速理解两件事：

1. 伊朗国家路由异常事件目前有哪些可以确认的数据、哪些仍然未知；
2. 事件详情页为什么从旧式“字段和证据编号展示”改成现在的完整事件叙事。

它不是新的产品合同，也不替代研究报告。产品判断仍以
《[事件详情页产品合同](./事件详情页产品合同.md)》为准，阶段边界仍以
《[事件详情页阶段性任务计划](./事件详情页阶段性任务计划.md)》为准。

一句话概括当前结果：

> 系统已经用独立 Go 重放结果，为伊朗事件建立了一条从观测范围、异常发现、影响、
> 演化、证据、未知项到下一步行动的完整前端叙事；结论严格限定为 RRC25 的 BGP
> 控制面观测，不宣称全国用户断网，不判断政治或物理原因，也不把窗口末回升写成
> 已经恢复。

## 三、先理解两个不同的“事件时间”

### 3.1 Legacy 引用是导航身份，不是主事件精确起点

页面 URL 中的引用是：

```text
country_outage/2026-02-27 09:12:32/IR/1/r
```

其中 `2026-02-27 09:12:32` 来自旧数据库国家中断事实记录。它的作用包括：

- 唯一定位旧事实记录；
- 保持历史链接稳定；
- 与旧系统数字进行口径对账；
- 作为更早候选异常或候选前兆的时间对照。

它不能直接替代本次研究重放得到的主事件 onset、detected、peak 或 trough。

### 3.2 主事件研究窗口在 2026-02-28

独立 Go 状态重放覆盖的正式窗口是：

```text
北京时间 2026-02-28 18:05—23:00
UTC      2026-02-28 10:05—15:00
```

正式窗口开始时事件已经处于异常状态，因此：

- 18:05 只能表达为“事件不晚于 18:05 已经发生”；
- 18:05 不是已证明的精确起点；
- 事件在左侧被截断，即存在左删失；
- 23:00 尚未满足恢复门槛，事件在右侧也没有闭合。

### 3.3 候选前兆与主事件的关系

当前页面将更早的旧事实记录作为候选前兆对照，但只表达时间先后关系：

- 可以说更早出现过异常记录或相关波动；
- 可以说其时间上早于主事件；
- 不能说它导致了后续主事件；
- 不能说两者已经被证明属于同一因果链。

当前关系结论固定为“时间相关，因果未评估”。

## 四、数据底座

### 4.1 数据包位置与身份

权威研究交付包位于服务器：

```text
/home/bgpdata/Domeye-Core-dev-data/research-runs/
iran-rrc25-full-p0/20260723T094940Z-full-p0/
state-replay-1805-2300-go-v1
```

关键身份：

| 项目 | 值 |
|---|---|
| 引擎版本 | `rrc25-iran-go-replay/1.0.0` |
| 完成状态 | `COMPLETE.status=complete` |
| 质量状态 | `QUALITY.status=pass` |
| collector | `rrc25` |
| 正式状态点 | 60 |
| 状态间隔 | 5 分钟 |
| 最后观测时间 | `2026-02-28T15:00:00Z` |

`COMPLETE.json` 保存所有交付文件的 SHA256，前端 API 读取交付数据时会重新校验实际文件
哈希。文件缺失、质量门不通过或哈希不一致时，伊朗事件叙事接口会失败关闭，不会返回
看似完整但来源不确定的数据。

### 4.2 输入范围

重放采用以下输入：

- 1 个完整 RIB；
- 84 个 UPDATE 文件；
- 其中 25 个用于 RIB 后的 catch-up；
- 59 个用于 18:05—23:00 正式窗口；
- RIB 完整读取，但内存状态只保留伊朗相关固定人口；
- UPDATE 可以并行解析，状态按时间顺序应用。

质量报告记录：

| 项目 | 数量 |
|---|---:|
| RIB 物理记录 | 1,398,399 |
| RIB entries | 55,729,118 |
| 保留的伊朗 Prefix×VP 成员 | 384,767 |
| UPDATE 物理记录 | 15,488,874 |
| UPDATE RouteEvent | 42,682,699 |
| 输入压缩字节数 | 828,162,553 |
| checkpoint 恢复次数 | 0 |

这些数字说明研究窗口已完整跑通，但它们不是页面上的影响指标。页面影响指标必须来自
固定人口状态快照。

### 4.3 固定人口

本事件所有核心比例使用同一固定 cohort：

| 人口 | 固定值 |
|---|---:|
| origin ASN | 563 |
| Prefix×VP | 384,767 |
| 窗口起点唯一 VP | 96 |

固定人口来自完整 RIB。后续每个状态点都在同一人口上比较，因此分子和分母不会随异常
过程变化。

VP 数量 96 是从窗口起点的 route-state 快照中去重得到的冻结值。若未来替换研究包或
改变窗口，必须重新推导，不能直接沿用。

### 4.4 主要交付文件

| 文件 | 用途 |
|---|---|
| `COMPLETE.json` | 完成状态和交付文件 SHA256 |
| `QUALITY.json` | 输入规模、失败状态和质量门结果 |
| `cohort.json` | 固定 ASN、前缀和 Prefix×VP 人口 |
| `country-snapshots.jsonl.gz` | 60 个国家级五分钟状态快照 |
| `asn-states.jsonl.gz` | 逐 ASN、逐状态点分类 |
| `route-states.jsonl.gz` | 逐 Prefix×VP 状态，共约 2,309 万行 |
| `incident.json` | onset、detected、peak、trough、观察终点和恢复状态 |
| `episodes.json` | episode 划分 |
| `waves.json` | wave 划分和关系状态 |
| `input-summary.json` | RIB、UPDATE 和处理范围汇总 |

在线 API 主要读取汇总快照、ASN 状态、cohort、incident、episode、wave 和质量文件。
它不会在每次页面请求时重新扫描约 258 MiB 的 `route-states.jsonl.gz`，但会保留该文件
在完整交付清单中的身份和边界说明。

## 五、当前可以确认的事件事实

### 5.1 核心时间点

| 北京时间 | 产品语义 | 当前结论 |
|---|---|---|
| 02-27 09:12:32 | 旧事实记录时间 | Legacy 数据库事实，不是主事件精确 onset |
| 不晚于 02-28 18:05 | 首次正式窗口观测 | 此时已经异常，精确起点未知 |
| 02-28 18:10 | 检测确认 | 连续两个五分钟状态点超过规则门槛 |
| 02-28 22:00 | 受影响 ASN 峰值 | 218/563 |
| 02-28 22:35 | Prefix×VP 可见率谷值 | 82.3181% |
| 02-28 23:00 | 观察窗结束 | 有回升，但尚未确认恢复 |

页面必须继续区分这些时间，不得重新合并成一个模糊的“事件时间”。

### 5.2 关键状态快照

| 北京时间 | 受影响 ASN | 全不可见 / 部分可见 | 可见 Prefix×VP | 可见率 |
|---|---:|---:|---:|---:|
| 18:05 | 89 / 563 | 8 / 81 | 367,215 / 384,767 | 95.4383% |
| 18:10 | 91 / 563 | 27 / 64 | 366,844 / 384,767 | 95.3419% |
| 22:00 | 218 / 563 | 84 / 134 | 320,087 / 384,767 | 83.1898% |
| 22:35 | 210 / 563 | 87 / 123 | 316,733 / 384,767 | 82.3181% |
| 23:00 | 161 / 563 | 67 / 94 | 333,938 / 384,767 | 86.7897% |

受影响 ASN 峰值和 Prefix×VP 可见率谷值发生在不同快照。页面分别表达二者，不把它们
强行合并成一个“最严重时刻”。

### 5.3 地址族差异

窗口谷值附近：

- IPv4 Prefix×VP 可见率约为 82.29%；
- IPv6 Prefix×VP 可见率约为 95.43%。

因此可以确认 IPv4 的控制面可见性下降更明显，但不能仅凭这一差异判断具体运营商
行为、物理故障位置或用户服务影响。

### 5.4 事件生命周期

当前研究结果为：

- episode：1 个；
- wave：1 个；
- wave 因果关系：`not_assessed`；
- 22:35 后出现回升；
- 23:00 仍有 161/563 个 ASN 受影响；
- 未满足部分恢复条件；
- 未满足完全恢复条件；
- 窗口结束状态：`ongoing`。

恢复规则要求 ASN 与 Prefix×VP 指标连续多个状态点达到门槛；完全恢复还需要回到可信
正常带。当前正常带不可用，因此“有回升”不能写成“已经恢复”。

### 5.5 正常基线为什么未知

本次 RIB 后的 catch-up 阶段已经出现连续异常，可见性波动也超过本次检测尺度，无法用
这段输入构造可信正常带。

当前能够说明：

- 固定人口是什么；
- 窗口内实际下降了多少；
- 各时间点之间如何变化；
- 检测规则何时被满足。

当前不能说明：

- 相对长期正常水平精确偏离多少；
- 这是否是该国历史上的正常波动范围之外多少个标准差；
- 完全恢复是否已经回到可信正常水平。

## 六、仍然不能回答的问题

页面中的每个未知项都必须同时给出原因、所需证据和下一步。

| 未知问题 | 原因 | 所需证据 | 下一步 |
|---|---|---|---|
| 18:05 之前的精确 onset | 窗口开始时已经异常 | 更早且稳定的同口径状态窗口 | 只在需要精确起点时向前扩窗 |
| 23:00 后何时恢复 | 正式窗口在 23:00 结束 | 更晚 UPDATE 和连续恢复状态 | 向后扩展恢复观察窗 |
| RRC25 之外的传播范围 | 当前只有一个 collector | 其他 collector 的固定 cohort 状态 | 做多 collector 对照 |
| 实际用户流量和服务影响 | BGP 是控制面数据 | 主动探测、流量、时延和服务可用性 | 补充数据面证据 |
| 候选前兆是否导致主事件 | 只有时间先后关系 | 持续状态链和独立外部证据 | 保持因果未评估 |
| 政治、物理或人为原因 | 路由状态不能证明意图和物理原因 | 运营、物理链路及可信调查材料 | 不在当前页面推断 |
| 旧报告数字的精确复现 | 原人口、快照和分类定义未冻结 | 原报告同口径输入与定义 | 做口径对账，不凑数 |

## 七、为什么要修改前端叙事

### 7.1 旧页面的问题

旧事件详情页以 Legacy Evidence Bundle 为中心，主要问题是：

- 用户先看到字段和证据编号，必须自行拼接结论；
- 旧事实记录时间容易被理解为精确事件起点；
- `0/3` 阶段覆盖会让用户误以为没有任何可用数据；
- 旧 ASN 数字缺少固定人口和同快照语义；
- 没有正常基线说明；
- 没有回答事件是在扩大、稳定还是恢复；
- 没有明确区分 BGP 控制面与实际服务影响；
- 没有把候选前兆的时间相关与因果关系分开；
- 没有告诉用户下一步应该做什么。

数据重放已经完成后，继续给旧页面增加孤立字段并不能解决这些问题，因此改造目标不是
“多放几个图”，而是让页面形成完整的研究叙事。

### 7.2 新页面的叙事原则

新页面遵循以下顺序：

1. 先告诉用户当前结论；
2. 再说明结论适用于什么观测范围；
3. 给出固定人口和正常基线状态；
4. 解释发生了什么变化、为何触发异常；
5. 分离各种时间语义；
6. 量化影响和集中对象；
7. 说明事件演化与恢复状态；
8. 将证据挂在具体结论旁；
9. 明确仍然未知的问题；
10. 给出可执行的下一步。

页面不要求用户先理解底层文件或 Evidence ID，才知道发生了什么。

## 八、当前页面从上到下讲了什么

### 8.1 事件摘要

首屏直接说明：

- 伊朗固定路由人口的 BGP 控制面可见性显著下降；
- 当前是 RRC25 单 collector 视角；
- 23:00 有回升，但尚未确认恢复；
- 没有数据面、流量或服务可用性证据；
- 不能据此断言伊朗全国用户断网。

### 8.2 四个核心指标

页面突出：

- 峰值受影响 ASN：218/563；
- 同快照全不可见/部分可见：84/134；
- Prefix×VP 最大不可见比例：17.68%；
- 窗口结束仍受影响：161/563。

这些指标用于快速回答“影响有多大”和“是否恢复”。

### 8.3 观测范围与正常基线

页面明确展示：

- 18:05—23:00 的观察窗口；
- RRC25；
- 96 个窗口起点唯一 VP；
- 563 个固定 ASN；
- 384,767 个固定 Prefix×VP；
- 60/60 个状态点；
- 正常带不可用及其原因。

### 8.4 变化趋势与异常判定

主趋势图在同一时间轴展示：

- 受影响 ASN 比例；
- 可见 origin ASN 比例；
- Prefix×VP 可见率；
- 关键里程碑标记。

检测规则表达为连续两个五分钟状态点达到观察门槛。由于正常带不可用，页面只说明满足
了什么观察规则，不声称相对长期正常水平偏离了某个精确幅度。

### 8.5 五种时间语义

页面单独列出：

- 旧事实记录时间；
- 窗口开始时已异常；
- 检测确认时间；
- 受影响 ASN 峰值；
- Prefix×VP 谷值；
- 观察窗结束。

它们不再共用一个“EVENT TIME”。

### 8.6 IPv4、IPv6 与 UPDATE

地址族卡片说明 IPv4 与 IPv6 表现不同。ANNOUNCE/WITHDRAW 图作为旁证展示消息变化，
但不会被当成固定人口可见性的替代指标，也不会被称为用户规模。

### 8.7 持续受影响 ASN

ASN 表格基于逐 ASN 状态展示：

- ASN；
- 地址族；
- 固定前缀数；
- 固定 Prefix×VP 人口；
- 受影响槽数；
- 窗口结束分类。

排序表示本次观测中的持续性和固定人口规模，不代表用户数量、商业重要性或因果责任。

### 8.8 事件演化与候选前兆

页面说明本次正式窗口内是一个 episode、一个 wave，当前仍在进行。同时把旧事实事件
放在候选前兆区域，明确只存在时间相关，因果关系未评估。

### 8.9 结论与证据

每条关键结论都附带：

- 结论等级；
- 支持它的快照、ASN 状态或研究交付物；
- 适用范围；
- 不能覆盖的范围。

这样用户从结论向证据下钻，而不是从证据编号反推结论。

### 8.10 口径对账

旧报告、旧数据库事实和新重放数字并列展示，但不直接相减：

- 旧报告可能使用不同人口和快照；
- 旧数据库有旧事实身份和 ASN 数字；
- 新重放使用固定 563 ASN、384,767 Prefix×VP。

页面强调“口径不同不能直接相减”，不会为了复现旧数字而调整新数据。

### 8.11 未知项与下一步

页面底部集中回答：

- 现在仍不能回答什么；
- 为什么不能回答；
- 需要什么证据；
- 下一步如何补齐。

行动顺序包括扩展恢复窗口、查看持续受影响 ASN、核对其他 collector、补充数据面探测
以及在必要时下载或查看原始证据。

## 九、前后端数据流

### 9.1 请求流程

```text
事件 URL 中的 ref
  → 前端解析固定事件引用
  → 请求 Event Story API
  → 后端校验是否为伊朗验收事件
  → 读取并校验 Go 重放交付包
  → 组合 event_detail_story_v1
  → 前端按产品叙事顺序渲染
```

事件叙事 API：

```text
GET /api/v1/events/story/
    {event_type}/{start_time}/{problem}/{event_id}/{source}
```

当前只有以下引用返回研究型叙事：

```text
country_outage/2026-02-27 09:12:32/IR/1/r
```

其他事件类型仍使用 Legacy Evidence Bundle。这是阶段 9 尚未开始的明确边界。

### 9.2 失败行为

对于伊朗验收事件：

- 研究包缺失时显示明确错误；
- 质量门失败时显示明确错误；
- 交付文件哈希不一致时显示明确错误；
- 不会静默回退到过时的 Legacy 页面并假装完整。

对于其他事件：

- Event Story API 返回未配置；
- 前端继续使用原有 Legacy 详情；
- 不受本次伊朗事件改造影响。

## 十二、后续修改必须守住的边界

### 12.1 不得改变的表达

- 不把 RRC25 写成全球或多 collector 一致结论；
- 不把 BGP 控制面可见性下降写成全国用户断网；
- 不把旧事实记录时间写成主事件精确起点；
- 不把 18:05 写成已证明的精确 onset；
- 不把窗口末回升写成部分恢复或完全恢复；
- 不把候选前兆写成主事件原因；
- 不把缺失值写成 0、正常、未发生或已经恢复；
- 不把不同人口、不同快照和不同定义的数字直接相减；
- 不为了匹配旧报告而调整固定 cohort 结果。

### 12.2 替换研究包时

如果未来生成新的伊朗研究包，至少需要：

1. 重新验证 `COMPLETE.json` 和 `QUALITY.json`；
2. 重新确认 collector、窗口和固定 cohort；
3. 重新推导窗口起点唯一 VP 数量；
4. 检查 onset 是否仍然左删失；
5. 检查观察终点是否仍然右删失；
6. 重新评估正常带是否可用；
7. 重新计算 peak、trough 和窗口结束状态；
8. 重新评估部分恢复和完全恢复；
9. 重跑十问合同验收脚本；
10. 重跑桌面和移动浏览器验收。

不能只替换文件路径而继续沿用旧叙事结论。

### 12.3 推广到其他异常类型时

其他国家中断、AS 中断、前缀中断、劫持、子前缀劫持和路由泄漏不在本次已验收范围。

推广前必须单独进入阶段 9，并回答：

- 该类型的固定人口是什么；
- 正常基线如何定义；
- 检测信号是什么；
- 影响对象和严重程度如何表达；
- 生命周期和恢复规则是什么；
- 哪些字段是该类型专属；
- 缺少研究包时采用什么失败行为；
- 如何避免把伊朗事件的特殊结论硬编码为通用逻辑。

## 十四、权威来源优先级

发生数字或语义冲突时，按以下优先级处理：

1. 原始 RIB/UPDATE 及独立 Go 重放交付包；
2. `COMPLETE.json`、`QUALITY.json` 和固定 cohort；
3. Event Story API 返回的冻结产品语义；

重放结果。
