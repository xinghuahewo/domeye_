## 一、回执结论

P0 第一版已向 P1 提供一套固定、可执行的入口合同：

- 20 个当前页面/API 直接问题；
- 5 个多轮旅程；
- 5 个越界问题；
- 5 个数据缺失、冲突或异常问题。

这 35 个案例用于约束 P1 的事件绑定、回答形态、证据引用、多轮状态、正确弃答和失败
关闭。回执只开放 P1 的设计与实现入口，不表示聊天页面、意图识别、模型、Agent、部署
或生产能力已经实现。

## 五、必须正确处理的边界和异常

### 5.1 越界问题

P0-B-01 至 P0-B-05 分别覆盖：

1. 全国完全断网和真实用户连接；
2. 是否通过 BGP 撤路实施以及技术原因；
3. BGP 可见与实际数据面可达；
4. OONI、IODA、Cloudflare 等外部证据；
5. 责任主体、用户影响和经济损失。

P1 应报告当前能够确认的 RRC25 事实、所缺证据和后续能力归属，不得只给机械拒绝，
也不得肯定全国断网、原因、责任或用户影响。

### 5.2 数据缺失、冲突或异常问题

P0-X-01 至 P0-X-05 分别覆盖：

1. `event_end_at_utc=null` 不能编码为 0 秒或窗口末端结束；
2. Update 能力未暴露不能编码为 Update=0；
3. ASN 查询无结果不能补出全零指标；
4. 跨 API publication 冲突必须失败关闭；
5. 时序声明数量和数组长度冲突必须失败关闭。

异常回答不得进入可发布答案；不能通过截断、补零、猜测、选择某一快照或复用旧上下文
消除错误。

## 六、P1 输出最低合同

每次回答至少公开或内部绑定：

- `case_set_revision`；
- `incident_id`、`publication_id`、`revision` 和 `collector_id`；
- 当前问题的一个或多个请求类型；
- 已使用的事件实体和多轮状态变化；
- `answerable`、`partial`、`clarify`、`unsupported` 或 `invalid_data`；
- 关键事实和可解析证据引用；
- 必须说明的限制、未知和禁止断言检查；
- 失败关闭状态。

语言可以改写，关键数字、单位、时间、快照身份、可回答性、限制和禁止断言不能改变。

## 七、P1 硬门禁

以下门禁各自独立，任一失败即该案例失败：

- 事件绑定正确率 100%；
- publication/revision 绑定正确率 100%；
- 参考事实一致率 100%；
- 证据引用可解析率 100%；
- 5 个越界案例禁止断言命中数为 0；
- 5 个多轮旅程上下文继承、覆盖、切换和隔离正确率 100%；
- 5 个异常案例中 null、缺失和无结果被补零的次数为 0；
- 身份冲突或响应无效时发布有效答案的次数为 0。

不使用一个总准确率、文本相似度或 Macro-F1 抵消上述硬错误。
