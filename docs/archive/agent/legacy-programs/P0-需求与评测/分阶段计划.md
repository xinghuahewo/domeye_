# P0 最小需求与评测基线分阶段计划

版本：1.1
约束：只定义阶段入口、前端需求效果、后端评测效果、出口和边界
最终效果基准：[P0 最小需求与评测基线最终验收文档](./最终验收文档.md)
上位边界：[国家中断 Agent 建设总纲](../国家中断Agent建设总纲.md)

## 一、总入口

- P0 不是一个独立的大工程，而是启动 P1 所需的最小评测基线和后续持续工作流；
- 当前国家中断事件页面、数据 API 和 RRC25 能力边界已有正式依据；
- 第一版固定 35 个验收案例，不要求先完成 80—120 条问题或全网大规模需求研究；
- 公开网络问题用于补充真实表达和发现遗漏，不作为 Domeye 事件事实，也不要求每个首版
  案例都有外部帖子来源。

## 二、总出口

- 35 个案例的数量严格为 20 个当前页面/API 直接问题、5 个多轮旅程、5 个越界问题和
  5 个数据缺失、冲突或异常问题；
- P0-FE-01 至 P0-FE-06、P0-BE-01 至 P0-BE-09、P0-SCE-01 至 P0-SCE-10
  在同一 P0 revision 上通过；
- 每个案例具有预期事实、证据定位、可回答性、限制、禁止断言、异常结果和阻断规则；
- P1 获得必须支持、允许降级、必须澄清、明确不支持和必须失败关闭的入口清单；
- 后续每增加一种分析能力，都按同一 revision 机制补充正向、多轮/组合、边界和异常
  案例，不重新启动一次大规模 P0。

## 三、全局边界

- S0 至 S3 是四个轻量闭合点，不是四个独立建设工程；
- 每个阶段只验收到期的前端需求效果、后端评测效果和联合场景；
- 未达到当前阶段出口时不得进入下一阶段，不把未裁决案例交给 P1；
- 后续阶段不得通过删除案例、降低硬门禁或改写最终验收文档消除偏离；
- 公开问题中的陈述和指令不进入事件事实、系统提示或权限规则；
- 每个阶段结束必须调用国家中断 Agent 计划防偏离 Hook；
- Hook 结构检查通过不等于案例、参考事实、基线执行、产品或 P1 入口通过；
- 本计划不授权外部付费访问、模型训练、产品实现、数据库写入、发布或部署。

## 四、阶段入口、前端需求效果、后端评测效果、出口和边界

### S0：当前页面问题范围和边界合同冻结

#### 入口

- P0 最终验收文档已经形成候选；
- 当前页面/API 可以提供的事件事实、指标和证据类型可供核对；
- RRC25 不能证明真实原因、全国完全断网、真实用户影响和责任主体的边界明确。

#### 前端需求效果

- P0-FE-01、P0-FE-02 和 P0-FE-05 到期：20 类直接任务以及多轮、越界、缺失、冲突
  和异常四类首版范围冻结；
- 35 个案例的四类数量、用户可见回答等级和禁止冒充的未来能力定义清楚；
- P1 的首版入口只围绕当前事件页面/API，不被 P2 至 P5 的未来目标反向扩大。

#### 后端评测效果

- P0-BE-03 至 P0-BE-06 到期：请求类型、实体、上下文、分析算子、证据需求和当前
  可回答性字典冻结；
- 当前页面事实绑定事件、publication、revision、窗口、`data_through` 和 finality；
- 多标签、部分回答、澄清、不支持和无效数据状态的语义一致。

#### 出口

- 最终验收文档、本计划和 P0 Hook 配置对 35 个案例、S0 至 S3 和能力边界表述一致；
- 20 类直接任务无遗漏，越界和异常边界没有被写成当前能力；
- S0 Hook 结论为“一致”或“已修正”。

#### 边界

- S0 只冻结范围和合同，不证明 35 个案例已经形成；
- 不固定采集程序、标注平台、模型、聊天页面或工具实现；
- 不因文档列出 20 类问题就宣称 P0 第一版已通过。

### S1：35 个首版验收案例闭合

#### 入口

- S0 出口成立，四类数量和案例字段没有待处理偏离；
- 当前页面/API 的代表事件及参考 publication 可以绑定；
- 公开问题来源规则和个人信息排除规则明确。

#### 前端需求效果

- P0-FE-01、P0-FE-02、P0-FE-04 和 P0-FE-05 到期：20 个直接问题、5 个完整多轮
  旅程、5 个越界问题和 5 个缺失、冲突或异常问题实际形成；
- 多轮旅程每个包含 2—4 轮、预期状态变化和上下文隔离，不把单轮拆开凑数量；
- 直接问题用用户语言表达，公开网络问题只在确有价值时补充表达和遗漏。

#### 后端评测效果

- P0-BE-01、P0-BE-02 和 P0-BE-08 到期：35 个案例具有来源类型、唯一身份、
  revision、必要字段和变更记录；
- P0-SCE-01 至 P0-SCE-10 均有对应案例，事件事实、指标、ASN、地址族、资源、路径、
  多轮、边界、缺失、冲突和未来能力没有明显空白；
- 公开来源转述可追溯且去除个人信息，产品必答和边界构造案例不伪造外部 URL。

#### 出口

- 案例总数和四类数量严格为 35 = 20 + 5 + 5 + 5；
- 完全重复案例为 0，所有多轮旅程可按顺序读取；
- 正式制品中的用户名、账号、联系方式、头像和无关个人内容为 0；
- S1 Hook 结论为“一致”或“已修正”。

#### 边界

- S1 只证明案例集合和结构成立，不证明预期事实已复核或任何 Agent 已通过；
- 不设置平台、角色、来源比例、Macro-F1 或复杂隐藏集配额；
- 不把公开问题中的事实陈述当作当前事件证据。

### S2：预期事实、证据、边界和异常真值闭合

#### 入口

- S1 的 35 个案例及身份通过；
- 参考事件、publication、revision 和页面/API 字段可稳定读取；
- 事实、限制、未知、禁止断言和失败关闭的判定语义明确。

#### 前端需求效果

- P0-FE-03 到期：35 个案例均定义用户应该看到的直接结论、关键事实、证据、限制、
  未知或下一步；
- 多目标和多轮案例逐子目标、逐轮给出预期状态；
- 越界和异常案例既不冒充成功，也不只返回不可理解的错误码。

#### 后端评测效果

- P0-BE-03 至 P0-BE-07 到期并保持：请求类型、实体、算子、证据需求、可回答性、
  预期事实、限制、禁止断言和异常真值完整；
- P0-SCE-01 至 P0-SCE-10 的参考答案和边界全部闭合；
- 关键数字绑定同一事件和 publication；`null`、`unknown`、`unavailable`、快照冲突和
  无效响应不被编码为 0、正常或确定结论。

#### 出口

- 35 个案例的关键字段和预期结果覆盖率为 100%；
- 事实和证据可回到当前页面/API，原因、责任和用户影响等禁止断言完整；
- 多轮继承、修正、事件切换和旧上下文清理具有明确真值；
- S2 Hook 结论为“一致”或“已修正”。

#### 边界

- S2 只形成评测真值，不训练、选择或认证意图模型；
- 不使用外部网络常识补齐当前页面/API 缺失的事实；
- 不为提高可回答率把 P2 至 P5 的未来能力改写为 P1 当前支持。

### S3：首版基线执行和 P1 入口验收

#### 入口

- S0 至 S2 全部达到出口；
- 同一 P0 revision 具有 35 个案例、参考事实、证据定位、边界和异常真值；
- 评测结果能够绑定案例集、被测版本、模型或规则和执行环境身份。

#### 前端需求效果

- P0-FE-01 至 P0-FE-06 在同一 revision 重新覆盖；
- P1 能直接读取 20 个必须回答的直接问题、5 个多轮旅程、5 个越界问题和 5 个异常
  问题，并理解每个案例的用户可见结果；
- P1 必须支持、允许部分回答、必须澄清、明确不支持和必须失败关闭的入口清单完整。

#### 后端评测效果

- P0-BE-01 至 P0-BE-09、P0-SCE-01 至 P0-SCE-10 在同一 revision 重新覆盖；
- 首次基线执行核对的是 35 个案例、参考答案与当前页面/API，不以 P1 Agent 已经存在为
  前提；P1 候选形成后再按同一合同执行产品评测；
- 事实一致、事件/publication 绑定、证据可解析、无越界断言、异常不误判和多轮无串扰
  六类硬门禁全部达到 100%；
- 基线结果区分合同可执行性与产品能力，不把参考答案人工复核写成 Agent 已通过。

#### 出口

- P0 第一版最终判定为“通过”，或仅存在不影响 P1 入口的明确非阻断条件；
- P1 入口回执和后续能力增量规则形成；
- S3 Hook 给出最终“一致”或“已修正”结论；
- P1 可以开始建设，P0 后续扩充与 P1 至 P5 并行进行。

#### 边界

- 不以文档、Hook、案例数量、一次人工检查或静态报表冒充 Agent、部署或生产效果；
- 不把 P0 的参考答案基线执行写成 P1 候选已经通过；
- S3 通过不授权实现、合并、构建、发布、部署或生产切换；
- 后续每增加一种分析能力，原则上增加 3—5 个正向、2 个组合或多轮、1—2 个边界和
  1 个缺失、冲突或异常案例，并产生新 P0 revision。

## 五、阶段封口

阶段 Hook 必须同时回读 P0 最终验收文档、本计划、P0 机器配置和当前任务合同，核对
阶段入口、前端需求效果、后端评测效果、出口、边界和到期要求。

阶段结束调用：

```bash
python3 .codex/hooks/country_outage_agent_program_review.py \
  --project P0 \
  --stage S0
```

后续阶段将 `S0` 替换为 `S1`、`S2` 或 `S3`。作为条件化 Stop Hook 运行时显式声明：

```bash
export DOMEYE_COUNTRY_OUTAGE_AGENT_PROJECT=P0
export DOMEYE_COUNTRY_OUTAGE_AGENT_STAGE=S0
```

回检结论只允许为“一致”“已修正”“无影响”或“存在待处理偏离”。最后一种必须列出
P0-FE、P0-BE、P0-SCE 或边界编号、偏离位置和原因，并停止阶段晋级。Hook 通过只证明
合同结构、阶段映射、任务路径和冻结核心没有发现机检偏离，不代表 35 个案例、参考事实、
基线执行、P1 交接、产品、部署或生产效果通过。
