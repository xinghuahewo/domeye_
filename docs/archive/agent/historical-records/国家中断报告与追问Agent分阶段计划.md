# 国家中断报告与追问 Agent 分阶段计划

版本：2.2
约束：只定义阶段入口、阶段出口和实施边界  
最终效果基准：[国家中断报告与追问 Agent 最终验收文档](./国家中断报告与追问Agent最终验收文档.md)

## 一、总入口

- Domeye 已有合法 `country_outage` 事件、RRC25 页面和可授权读取的只读数据能力；
- 已有一份人工认可阅读风格的国家中断观测报告；
- 目标只包含前端最终效果和报告生成逻辑；
- Codex 对话、项目记忆和现成报告正文不构成 Pi Agent 的正式输入；
- 最终验收文档 2.2 是唯一最终效果基准。

## 二、总出口

- 核心剖面的 FE-01 至 FE-06、FE-08、FE-09，RG-01 至 RG-08、RG-10 至 RG-13，
  以及 SCE-01 至 SCE-04、SCE-07 至 SCE-10 全部通过；
- 前端形成可完成生成、阅读、追问和核心报告下载的技术报告研读工作台；
- 报告生成逻辑在固定 RRC25 快照上生成数字可信、边界正确、可复现的中文报告；
- 两条主线完成集成验收，不存在“界面通过但报告不可信”或相反情况；
- 每个阶段均留下防偏离 Hook 结论和可复核证据。
- 外部证据能力包单独记录为“未配置/未验收/通过/不通过”；未配置或未验收不阻塞
  核心剖面，但不得写成能力包已经通过。

## 三、全局边界

- 不修改 `backend/core/` 业务逻辑，不改写国家中断历史数据；
- 只处理已有合法 `country_outage` 事件，从始至终只使用 RRC25；
- 不支持任意国家、任意时间、collector 选择、多 collector 或自动定时报告；
- 不扩大到其他事件、通用 RCA、归因、责任判断、处置或生产写入；
- 不暴露 Shell、文件编辑、任意路径、SQL、数据库凭据或任意会话切换；
- 不把 Codex 记忆、模型训练记忆、未授权互联网资料和报告示例数字当作事实；
- 核心 `CountryOutageCore` 的公共网络访问固定为 `none`，不依赖、不注册也不知道
  Provider、URL、DNS、站点或 Gateway 等网络语义；
- Domeye 应用编排层只能通过
  `CountryOutageCore.generateReport -> Rrc25Report`、
  `ExternalEvidenceProvider.fetch -> EvidenceEnvelope` 和
  `AnnexComposer.compose(report,evidence?) -> DownloadArtifact` 三条窄接口组合
  核心报告与可选附录；外部证据不能修改报告正文；
- 外部证据能力包只在用户显式授权后通过 `managed-egress-v1` 读取受控公开网络；
  当前授权必须由用户主动打开外部证据开关并确认允许 URL，自然语言中的搜索意图
  或粘贴 URL 不会自动联网；正式范围仅为 `bgp.he.net`、
  `radar.cloudflare.com` 及其符合点边界的子域名，不提供通用搜索或来源发现；
  不读取内网、登录页面、浏览器会话或用户上传文件；
- Evidence Gateway 必须分为通用安全执行层、`country-outage-external-v1` 窄策略
  和 Hurricane Electric/Cloudflare Radar 来源适配器；DNS、代理、TLS、重定向、
  IP 校验、响应限制和基础 HTML 清洗属于通用层，域名、URL 数量、超时和授权属于
  窄策略，DOM、数据结构和发布日期提取属于来源适配器；
- 外部证据只作独立补充，不修改 Domeye 报告，也不补足最低数据门槛；能力包未配置、
  未就绪、未部署或未认证时不阻塞核心 A4/A5；
- 正式报告只接受与窗口首尾精确对齐、完整连续且无非观测槽的 RRC25 五分钟网格；
  任一缺槽、计数漂移或核心数值语义不闭合均失败关闭；
- 报告和问答只在短期会话内使用，不建设永久会话历史；
- 按用户确认，生产部署身份、生产 ACL 配置和特定真实读屏器环境不作为本轮 A0
  至 A5 阻断证据；代码级授权隔离、键盘、语义树和状态播报仍必须验收，不得把
  候选结果外推为生产验收；
- 不以文档、结构检查、单元测试、一次模型调用或候选环境替代阶段出口；
- 未达到当前剖面的本阶段出口时不得进入该剖面的下一阶段，后续阶段不得降低最终
  验收合同；
- 每个阶段结束必须调用国家中断报告与追问 Agent 最终验收防偏离 Hook。

## 四、阶段入口、出口与边界

### A0：两条验收主线和量化基线冻结

#### 入口

- 当前国家中断页面、只读数据和人工认可报告能够复核；
- 最终验收文档 2.2 已确认；
- 尚未用正式 Agent 证明前端和报告生成逻辑。

#### 出口

- FE-01 至 FE-09、RG-01 至 RG-13 和 SCE-01 至 SCE-10 的旧编号与全部细节均被
  保留，并已分别映射到核心剖面或外部证据能力包；
- 核心剖面的 SCE-01 至 SCE-04、SCE-07 至 SCE-10 输入、预期结果和证据形式已经
  冻结；SCE-05、SCE-06 保留为能力包独立到期项；
- RRC25、已有事件、用户触发、最低门槛、短期会话、核心下载和公共网络访问为
  `none` 的边界已形成核心基线；
- 会话、响应、容量、下载、视口、浏览器、隔离、清理、日志、权限和频率限制
  已形成版本化验收配置 `country-outage-agent-core-acceptance-v3`；外部 URL 和
  Gateway 规则只存在于独立 `country-outage-external-evidence-pack-v1`；
- 当前能力、目标效果和未实现项没有混写；
- A0 阶段结束 Hook 结论为“一致”或“已修正”。

#### 边界

- 不实现前端或报告生成逻辑；
- 不把 Codex 当前效果写成 Pi Agent 已具备能力；
- 不提前宣告任何 FE、RG 或 SCE 已通过。

### A1：报告输入、快照和事实闭合

#### 入口

- A0 出口全部成立；
- 代表性合法事件和量化验收配置已经冻结。

#### 出口

- RG-01 至 RG-04 通过；
- 合法事件、唯一 RRC25、固定快照、完整时间网格、首尾槽、缺槽账、能力状态、
  事实标识、固定分母、相邻变化和扩展极值可以重复核对；

- 前端能够获得显示事件身份、数据门槛和能力状态所需的确定结果；
- SCE-02 和 SCE-03 的数据侧结果通过；
- A1 阶段结束 Hook 结论为“一致”或“已修正”。

#### 边界

- 不要求正式中文报告、问答界面和下载已经完成；
- 不通过第二 collector、数据库直读或扩大权限解决事实缺失；
- 不使用 Codex 记忆、外部资料和示例数字补充事件事实。

### A2：基础报告生成逻辑闭合

#### 入口

- A1 出口全部成立；
- 固定快照能够提供经过核对的事实集合和明确能力状态。

#### 出口

- RG-05、RG-06、RG-08、RG-12 和 RG-13 的基础报告部分通过；
- 代表性事件能够生成达到人工认可风格的中文报告；

- 发布前完成事实、公式、来源、能力和语义校验，失败时不发布草稿；
- 国家名称、中文正文、变化方向和实际 Skill 摘要必须通过冻结的
  `country_outage_report_validator_rules_v5` 发布校验，Markdown
  必须安全转义模型文本和危险链接；
- PDF 与 Markdown 使用同一通过校验的报告制品；
- 无 Codex 记忆、无现成正文和无默认互联网的基础报告重放通过；
- SCE-01、SCE-02、SCE-03 和 SCE-09 的生成侧结果通过；
- A2 阶段结束 Hook 结论为“一致”或“已修正”。

#### 边界

- 不要求完整问答、外部证据和全部模型组合已经完成；
- 不为改善文风降低数字追溯、失败关闭或控制面边界；
- 不把一次成功生成等同于稳定通过。

#### 出口

- 桌面、平板、手机、键盘、语义树、滚动、焦点和减少动态效果均可完成关键旅程；
- 问答以研读记录呈现，事实可展开并返回数据观测位置；
- 默认模式始终为“仅使用 Domeye 数据”，连续追问不离开原快照；
- 取消、重复请求、短期重连、到期和新 revision 的前端结果稳定；
- SCE-04、SCE-08、SCE-09 和 SCE-10 的前端与问答部分通过；
- A3 阶段结束 Hook 结论为“一致”或“已修正”。

#### 边界

- 不提前开放外部搜索；
- 不把追问扩展为跨事件通用 RCA 或永久聊天历史；
- 不允许通用聊天外观、草稿流、强制滚动或并发答案互相覆盖。

  PDF/Markdown 下载仍然完成；页面只显示“当前环境未配置公开来源旁证”，不在

- 外部资料不进入 `CountryOutageCore`，不改变 Domeye 报告、不替代最低门槛、

- 不以核心 A5 通过替代 E0 至 E2，也不以能力包失败倒推核心报告不合格。

### E0：外部证据能力包合同冻结

#### 入口

- 核心剖面 A5 已完成，或本阶段工作明确处于不影响核心 A0 至 A5 的独立工作面；
- FE-07、RG-09、SCE-05、SCE-06 和所有“能力包启用时”交叉条款可完整回读。

#### 出口

- `ExternalEvidenceProvider.fetch -> EvidenceEnvelope` 和
  `AnnexComposer.compose(report,evidence?) -> DownloadArtifact` 两条应用编排接口、
  Evidence Envelope schema、readiness 状态和能力包认证失效条件已经冻结；
- Provider readiness 公共 API 只允许 `ready`、`not_configured`、
  `self_check_failed`；`checking` 与 `unknown` 只作为浏览器本地过渡状态；
- Evidence Gateway 的通用安全执行层、`country-outage-external-v1` 窄策略、
  Hurricane Electric 适配器和 Cloudflare Radar 适配器职责互不混写；
- 原 2.1 的 URL 数量、授权时效、域名点边界、页面数量、响应大小、重定向、协议、
  私网、登录页、上传、留存和权限细节逐项迁入独立版本化配置，没有删除或放宽；
- 能力包仍为未配置/未验收，不因合同冻结而显示入口可用；
- E0 阶段结束 Hook 结论为“一致”或“已修正”。

#### 边界

- 不修改 `CountryOutageCore`、RRC25 报告正文、事实合同或核心验收配置；
- 不把浏览器、`curl`、测试夹具或旧 Sidecar 直连结果写成能力包通过；
- 不在策略文件实现站点 DOM、数据结构、标题或发布日期提取。

### E1：Evidence Gateway 与应用编排闭合

#### 入口

- E0 出口全部成立；
- 平台提供独立于核心 Agent 的 Gateway 运行边界和候选应用编排位置。

#### 出口

- Domeye 应用编排层分别调用 `CountryOutageCore` 与
  `ExternalEvidenceProvider`，再由 `AnnexComposer` 生成独立附录和下载制品；
- `managed-egress-v1` 只通过 Gateway 访问公开网络；Gateway 每次读取均经过通用
  安全执行层、窄策略和对应来源适配器，任一层失败均返回受控 Evidence Envelope；
- `disabled` 路径不访问网络，核心报告、追问和核心下载仍完成；
- 未完成自检和 E2 认证时，页面入口不可操作并显示“当前环境未配置公开来源旁证”
  或明确未就绪状态；不会在用户发起后才发现整个公网出口不可用；
- Provider、Envelope、Composer、权限、幂等、超时、取消和跨用户隔离具有候选证据，
  但不写成 FE-07、RG-09、SCE-05、SCE-06 已通过；
- E1 阶段结束 Hook 结论为“一致”或“已修正”。

#### 边界

- 不把 Provider 挂入 `CountryOutageCore` 或核心 Agent；
- 不允许 Gateway 绕过窄策略，不允许来源适配器直接建立网络连接；
- 不允许外部附录修改、覆盖或插入 RRC25 报告正文。

### E2：外部证据能力包真实公网认证

#### 入口

- E1 出口全部成立；
- `managed-egress-v1`、Gateway、窄策略、两个来源适配器和 AnnexComposer 在最终
  验收环境具有可核对版本与 readiness 自检结果。

#### 出口

- FE-07、RG-09、SCE-05、SCE-06 和所有“能力包启用时”交叉要求通过；
- 用户确认 1 至 5 个允许 URL 后，由真实产品路径分别取得
  `bgp.he.net` 与 `radar.cloudflare.com` 点边界内页面的 Evidence Envelope；
- 读取成功但不能绑定固定历史窗口时，来源保留 `status=fetched`、
  `evidence_status=insufficient`，独立附录如实说明不足且不改变 Domeye 正文；
- 独立分区、逐项引用、来源状态、快照绑定、附录下载、取消、幂等、跨用户隔离、
  未授权、恶意 URL、重定向、私网地址、登录页和提示注入均有真实产品路径证据；
- 能力包证书绑定 Provider、Gateway、策略、来源适配器、Envelope schema、
  AnnexComposer、验收环境、执行时间和证据摘要；任一绑定项变化或证书到期即回到
  未验收/未就绪；
- E2 阶段结束 Hook 结论为“一致”或“已修正”后，应用编排层才可声明能力包启用。

#### 边界

- 手工浏览器访问、`curl`、测试夹具和模拟 Envelope 不能替代真实产品路径；
- 不因 `evidence_status=insufficient` 伪造支持或冲突，也不因证据不足修改 RRC25
  报告；
- E2 通过不授权通用搜索、来源发现、其他域名、生产切换或新的事件类型。

## 五、阶段封口

Hook 必须同时回读最终验收文档和本计划，核对当前阶段入口、出口、边界以及到期
FE、RG 和 SCE。结构检查通过不等于产品效果通过。

阶段结束调用：

```bash
python3 .codex/hooks/country_outage_agent_review.py --profile core --stage A0
```

核心后续阶段将 `A0` 替换为对应 A 阶段编号。能力包使用：

```bash
python3 .codex/hooks/country_outage_agent_review.py \
  --profile external-evidence --stage E0
```

能力包后续阶段将 `E0` 替换为对应 E 阶段编号。回检结论只允许为“一致”“已修正”、
“无影响”或“存在待处理偏离”；最后一种必须列出 FE、RG、SCE 或能力包边界编号、
位置和原因。核心 Hook 不读取或要求能力包认证证书，能力包 Hook 也不得改写核心结论。
