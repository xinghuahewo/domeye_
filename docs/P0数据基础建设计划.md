## 2. 阶段决策

P0 采用“数据门禁优先”策略：数据基线、数据契约、血缘、缺失语义和质量门禁未通过前，新增前端指标和图表不得进入完成状态。

P0 的完成标准不是页面数量，而是用户能够从一个指标或事件稳定地下钻到：

1. 明确的数据窗口、单位和统计口径；
2. 可定位的业务事实记录；
3. 可复核的路由观测或原始记录引用；
4. 可量化的覆盖范围和缺失原因；
5. 明确的证据限制和不可得结论。

P0 只回答“观测到了什么”和“数据是否足够”，不自动给出网络根因，不将相关性描述为因果关系，不执行路由、数据库或生产配置写操作。

## 3. 当前数据基线

### 3.1 已有能力

- 独立 PostgreSQL/TimescaleDB 只读快照，不依赖原生产数据库。
- `event_table_YYYYMM` 与六类异常事实表可以查询劫持、子前缀劫持、路由泄漏、前缀中断、AS 中断和国家中断。
- `feature_*`、`feature_country` 和 ASN 月度特征表提供报文量、资源量和并发中断等时序数据。
- 当前 `evidence_bundle_v1` 已提供稳定 `incident_id`、稳定 `evidence_id`、事实表定位、前/中/后阶段覆盖、证据限制和 `observation_only` 分类。
- 数据档已统一固定窗口、快照时钟和 `Asia/Shanghai` 业务时区。
- 国家工作台和 ASN 工作台已能返回样本数量、最近观测时间和运营对象范围说明。

### 3.2 部分具备

| 能力 | 当前状态 | P0 处理 |
| --- | --- | --- |
| 事件前/中/后证据 | 六类事实表字段不一致，部分类型只有单阶段路径或没有路径 | 建立逐类型覆盖矩阵，所有缺失必须带原因 |
| 路径证据 | 存在 `pre_vp_paths`、`eve_vp_paths`、`next_vp_paths` 或 `as_path` | 只称为 Route Observation / Path Snapshot |
| 样本覆盖 | 部分接口提供 `sample_count` | 增加期望样本数、实得样本数和缺失原因 |
| 时间语义 | 业务时间可按数据档派生 UTC | 补齐来源时间、入库时间、解析时间和检测时间契约 |
| 来源定位 | 可定位到事实表和业务主键 | 增加原始制品、文件偏移或记录哈希引用 |
| 排名 | 国家较完整，ASN 为运营对象集合 | 所有排名必须返回范围、候选数和过滤规则 |

### 3.3 当前关键缺口

- 没有标准化、不可变的 RouteEvent 原始观测索引。
- 多数事实记录没有保留 VP 身份，无法复核逐 VP 覆盖和传播过程。
- 没有原始 BGP UPDATE 的制品 ID、文件哈希、偏移量、长度或记录哈希。
- 没有统一保留 `ingest_time`、`parse_time`、`detect_time`。
- 没有解析器版本、检测器版本、规则版本和输入数据版本血缘。
- `feature_*` 的缺测、真实零值和聚合补零语义没有形成统一机器契约。
- 六类事件的阶段字段、结束时间、持续时间和影响对象语义不完全一致。
- 当前 Evidence Bundle 能复核业务事实表，但不能逐报文重放，也不能证明因果传播。

## 4. P0 数据建设原则

### 4.1 原始数据、事实记录和派生指标分层

必须明确区分：

- **原始观测**：来自 Collector/VP 的 BGP UPDATE 或 RIB 记录；
- **规范 RouteEvent**：对原始记录做无损字段规整后的不可变索引；
- **检测事实**：六类检测器输出的业务事件记录；
- **派生指标**：按国家、ASN、时间窗口聚合的更新量、撤回率、资源量等；
- **调查证据包**：将事实、观测、质量和限制组装为 Evidence Bundle。

业务事实表不是原始 BGP 证据，`BGPRib` 是可变检测状态，路径快照不是因果链路。

### 4.2 不修改历史源记录

- 现有二三月快照和 `public` 业务表保持只读。
- 规范化、纠错和补充信息写入独立 `evidence`/`data_mart` 旁路层或独立数据制品。
- 不允许以补全页面为目的直接覆盖历史字段。
- 任何纠错必须记录 `correction_id`、来源记录、修改前后值、原因、执行版本和审核状态。

### 4.3 缺失不等于零

所有可空数据至少区分：

| 状态 | 含义 |
| --- | --- |
| `observed_zero` | 已观测，值确实为 0 |
| `not_observed` | 该时间点未获得样本 |
| `not_retained` | 处理时未保留该字段 |
| `not_applicable` | 该事件类型不适用此字段 |
| `source_unavailable` | 原始制品不可用 |
| `parse_failed` | 原始记录存在但解析失败 |
| `legacy_unknown` | 历史数据无法判断缺失原因 |

前端不得将后六种状态绘制为 0。

### 4.4 观测结论与因果结论分离

- P0 只允许 `observation_only`。
- `causal_conclusion` 必须为 `null`。
- 可以展示支持证据、反向证据、覆盖缺口和限制。
- 不允许根据 AS_PATH 快照推断真实转发路径、全网传播或根因。

## 5. 目标数据架构

```text
批准的原始 BGP 制品
        │
        ▼
不可变 RouteEvent 索引 ─────────────┐
        │                           │
        ▼                           │
既有离线检测核心 ── 六类事实表       │
        │                           │
        ├── 事件规范化视图           │
        ├── MetricSeries            │
        ├── EntitySnapshot          │
        └──────────────┬────────────┘
                       ▼
             只读 API 与前端调查台

所有层同时进入 Data Quality Report
```

旁路导入和规范化代码必须位于 `backend/core/` 之外。现有核心检测文件继续通过 `backend/core.sha256` 校验。

## 6. 核心数据契约

### 6.1 RouteEvent

每条可追溯路由观测至少包含：

| 字段组 | 必需字段 |
| --- | --- |
| 身份 | `route_event_id`、`schema_version` |
| 来源 | `source`、`collector_id`、`vp_id`、`vp_asn` |
| 时间 | `event_time`、`source_timezone`、`ingest_time`、`parse_time` |
| 路由 | `action`、`afi_safi`、`prefix`、`as_path`、`origin_asn` |
| 原始引用 | `artifact_id`、`file_sha256`、`record_offset`、`record_length`、`record_hash` |
| 处理血缘 | `parser_name`、`parser_version`、`import_run_id` |
| 质量 | `lineage_status`、`quality_flags`、`missing_reasons` |

约束：

- `route_event_id` 由稳定规范字段生成，相同输入重复导入必须得到相同 ID。
- 原始载荷不直接重复写入事件事实表；通过 `raw_ref` 定位并校验。
- `as_path` 保留规范化值，同时保留原始引用，不覆盖原始文本。
- `lineage_status=raw_traceable` 时，VP、原始引用和处理版本不得为空。
- 无法追溯的历史记录标记为 `legacy_untraceable`，不得伪造 VP 或原始偏移。

### 6.2 Incident 与检测事实映射

- 保留当前 `incident_id_v1`，冻结生成规则并加入稳定性回归测试。
- 每个 Incident 必须记录 `event_type`、源事实表、源主键、开始时间、结束时间、影响对象和检测版本。
- `event_table_YYYYMM.detail_url` 与事实表主键必须一一可解析。
- 同一业务事件跨总表、事实表和 Evidence Bundle 的 ID 必须一致。
- 事实表孤儿记录和总表悬空引用均为阻断项。

### 6.3 MetricSeries

所有前端图表指标统一为 MetricSeries：

```text
metric_name
subject_type / subject_id
collector_scope
window_start / window_end
granularity
unit
aggregation
formula_version
expected_sample_count
observed_sample_count
coverage_ratio
points[{time, value, value_state, missing_reason}]
source_refs[]
generated_at
```

指标公式至少冻结：

- `update_total = announce + withdraw`
- `withdraw_rate = withdraw / update_total`，分母为 0 时返回 `null`，不能返回虚假的 0%
- 变化率的基线窗口必须与当前窗口等长；基线无样本时返回 `null`
- IPv4 地址量、IPv4 `/24` 等价值和 IPv6 `/48` 等价值不得混用同一字段名或单位
- ASN 排名必须声明 `scope_kind=operational_asn_cohort`，除非完成全量 ASN 扫描

### 6.4 调查数据读取

现有 `evidence_bundle_v1` 仅作为历史兼容接口保留，不重新解释已有字段。新增调查能力直接读取 Incident、RouteEvent、原始记录引用、MetricSeries、逐字段质量和阶段状态，不再引入新的事件级聚合证据包。

调查接口必须返回支持当前观测描述的数据、反向观测、不可用字段和缺失原因，以及数据快照、时区、来源和处理版本。
- 明确的 `observation_only` 结论边界。

### 6.5 Data Quality Report

质量报告不能只给一个总分，必须分别报告：

- 完整性；
- 唯一性；
- 引用一致性；
- 时间一致性；
- 原始可追溯性；
- 样本覆盖率；
- 指标可复现性；
- 六类事件阶段覆盖；
- 固定窗口越界情况；
- 未知缺失原因数量。

报告同时生成机器可读 JSON 和中文 Markdown 摘要。

## 7. 历史数据兼容策略

### 7.1 两级数据身份

| 等级 | 定义 | 可提供的结论 |
| --- | --- | --- |
| `legacy_compatible` | 可定位到业务事实表，但没有完整原始报文、VP 或处理血缘 | 可展示业务事实、路径快照和明确限制 |
| `raw_traceable` | 可从事实记录定位到规范 RouteEvent 和校验通过的原始记录 | 可逐记录复核和重放，但仍不自动证明因果根因 |

### 7.2 原始数据可用性门禁

阶段 D0 必须确认二三月原始 BGP 制品是否存在、是否获准读取、是否具备稳定校验信息：

- 若原始制品存在：P0 必须完成全窗口 RouteEvent 索引与哈希校验。
- 若只存在部分原始制品：逐日、Collector、VP 报告覆盖，不得将部分覆盖描述为全量。
- 若原始制品不存在：历史数据只能验收为 `legacy_compatible`；即使前端完成，也不能宣称 P0 数据最终完成。
- 新导入数据必须从第一条记录开始满足 `raw_traceable` 契约，禁止继续生成新的不可追溯历史债务。

## 10. 六类事件最低数据要求

| 事件类型 | 事件身份 | 影响对象 | 阶段证据最低要求 | 当前重点缺口 |
| --- | --- | --- | --- | --- |

## 11. 数据修改与发布规则

P0 数据工作涉及数据库 schema、视图、索引、制品或数据范围时，属于高风险边界：

1. 日常盘点和质量检查必须只读，可在现有开发数据库上执行。
2. 新 schema、RouteEvent 导入或历史规范化必须在候选数据库/旁路制品中完成。
3. 健康候选 PGDATA 和已完成检查点必须复用，不因脚本或报告失败重建。
4. 只有数据源、一致性、schema 或数据窗口无法修复时才允许重建候选库。
5. 候选制品必须包含 inventory、manifest、schema hash、质量报告和 SHA256。
6. 大型数据和验收报告归档到：

```text
/home/bgpdata/Domeye-Core-artifacts/releases/<release-id>/data-quality/
```

7. Git 仓库只提交文档、契约、查询、导入器、测试和小型 fixture，不提交真实数据库、原始报文或敏感配置。

## 14. P0 完成定义与本轮达到等级

同时满足以下条件才可宣布“P0 数据完成”：

1. 数据字典、机器契约和六类字段覆盖矩阵已冻结并进入版本控制。
2. 二三月数据基线有可重复生成的 inventory、schema hash 和质量报告。
3. 总表、六类事实表、指标和 RouteEvent 之间引用一致，无未解释孤儿。
4. 所有前端指标具备来源、公式、单位、窗口、范围和缺失语义。
5. 调查接口能区分历史兼容事实和原始可追溯记录。
6. 对宣称 `raw_traceable` 的数据，VP、原始引用、哈希和处理版本全部可复核。
7. 六类异常的阶段覆盖、反向证据、数据缺口和限制可以机器读取。
8. 数据质量门禁可只读重复执行，并产生可归档报告。
9. 前端不再把缺测显示为 0，不把路径快照描述为因果传播。
10. `backend/core/` 哈希保持不变，固定数据档没有连接原生产库或执行生产激活。

如果二三月原始 BGP 制品不可获得或只部分覆盖，只能宣布“P0 历史数据兼容完成”，不能宣布“P0 原始证据数据完成”。这是数据事实边界，不通过页面文案或推断规避。

本轮达到的正式等级是 `P0 历史数据兼容准入`：事实、指标、缺失语义和质量数据可以复核，页面能够诚实显示固定窗口与缺口。尚未满足第 6 项的全窗口原始追溯，也没有完成全量跨运行语义复现；RouteEvent 仅为 pilot。因此不得使用“全量原始证据完成”或“生产已发布”等表述。
