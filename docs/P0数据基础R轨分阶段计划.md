# P0 数据基础 R 轨分阶段计划

版本：1.1（2026-07-27 整体合理性审查后修订）  
约束：只定义阶段入口、阶段出口和实施边界  
最终效果基准：[P0 数据基础 R 轨最终验收文档](./P0数据基础R轨最终验收文档.md)  
上游计划：[P0 数据基础建设计划](./P0数据基础建设计划.md) 第 15 节

## 一、整体合理性审查与修订结论

原方案以 R0/R1/R2 分别处理来源身份、独立语义和遗留风险，以 R3 → R4 → R5
串行处理原始覆盖、事件闭合与语义复现，技术依赖总体合理。审查后修正三处治理问题：

1. Markdown 完成声明不再构成阶段出口；阶段出口必须由机器清单、校验结果和归档证据共同证明；
2. 项目方拒绝补取仍可得源属于 `scope_stopped`，不是 `unrecoverable`，也不等于 R3 `passed`；
3. 阶段工作完成、阶段出口通过、R 轨最终通过和生产激活使用四个独立状态，不再互相替代。

当前执行状态：

| 对象 | 状态 | 说明 |
|---|---|---|
| R0 | `passed_after_correction` | 37 表机器清单与校验器已补齐 |
| R1/R2 | `recorded_pass` | 保留既有只读测量结论；本次未重跑 |
| R3 | `scope_stopped` | 60.24% 被接受为范围决定；标准出口未通过 |
| R4/R5 | `not_run` | 不满足入口条件 |
| R 轨最终状态 | `not_passed` | 只保持 `P0 历史数据兼容` |

## 二、总入口

- 固定数据档 `feb-mar-2026` 已达到 `P0 历史数据兼容准入`；
- 二三月事实与特征数据来自原 Domeye 在 `bgp_project` 中已产生的结果，
  Core 只做快照、裁剪与旁路规范化，未重跑旧检测器；
- 数据库转储身份已记录，但未绑定生产该批历史行的代码身份与算法版本；
- 源精确对账已成立，独立语义对账尚不存在；
- 遗留语义风险 F2、S2、S4 已登记，污染未确认；S6 规则日期晚于数据窗口；
- RouteEvent 仍为 pilot，全窗口原始追溯未达成；
- 全量跨运行语义复现为 `not_run`。

## 三、总出口

- 二三月每张事实表与特征表具备可解析或显式不可得的生产者身份；
- 源精确对账与独立语义对账各自具名、各有报告、互不替代；
- F2、S2、S4 均由只读数据测量或有界原始重算结案；
- 全窗口槽位覆盖为已知实测值，未准入槽位均有登记原因；
- 声明范围内 RouteEvent 完成闭合，不再是 pilot；
- 全量语义复现已执行且结果已归档；
- RFA-01 至 RFA-12 全部通过；
- 每个阶段留下防偏离回检结论。

## 四、全局边界

- 本计划不修改 `backend/core/` 业务逻辑，差异通过影子对账呈现；
- 本计划不改写二三月历史事实行，只让其状态成为已知量；
- 本计划不连接原生产数据库，不恢复实时发布；
- 本计划不执行生产激活，激活属于独立授权；
- 本计划不扩大到实时管线改造，实时接入债务另行立项；
- 未达到本阶段出口时不得进入下一阶段；
- 每个阶段结束必须调用 P0 数据基础 R 轨最终验收防偏离 Hook；
- 后续阶段不得通过降低最终验收要求消除前序偏离。
- `scope_stopped` 可以结束资源投入，但不能被换名为 `passed`；
- 只有 `DOMEYE_P0_R_TRACK_STAGE=R0` 至 `R5` 被显式声明时，R 轨 Stop Hook 才介入，
  避免无关任务被本轨阻塞。

## 五、阶段入口、出口与边界

### R0：生产者身份补绑

#### 入口

- 转储制品记录数据库身份，未绑定原项目代码标识与算法版本；
- 无法按行或按表回答"该结果由哪个版本的检测器产生"。

#### 出口

- 机器清单逐条列出且只能列出 37 张目标表，不得以表族通配符代替逐表记录；
- 每条记录绑定数据时间范围、生产者组、代码身份、算法版本及证据引用；
- 不可恢复部分登记为 `unrecoverable` 并写明原因，留空数为 0；
- 原系统没有独立算法版本号时，以进程启动时绑定的完整 Git 内容 SHA
  作为 `git_commit_content` 算法版本；无法证明时显式 `unrecoverable`；
- `dev/data_quality/p0_producer_identity.py` 校验返回
  `table_count=37`、`blank_identity_count=0`、`verdict=passed`；
- RFA-01 成立。

#### 边界

- 只读；不重跑旧检测器；不改写任何历史行；
- 不以数据库转储身份代替代码身份；
- 不因身份缺失而推断数据正确或错误。

### R1：独立语义对账门禁

#### 入口

- 源精确对账差异为 0，仅证明旁路忠实复制原表；
- 不存在以独立基准重算的正确性门禁。

#### 出口

- 独立语义对账门禁具名存在，以独立基准重算，只读可重复执行并产出可归档报告；
- 文档、报告与接口中不存在以无限定词"对账"指代正确性的表述；
- RFA-02 成立。

#### 边界

- 本阶段只定义并运行门禁，不修复门禁发现的问题；
- 零写操作；
- 不以源表自身作为正确性基准。

### R2：遗留语义风险测量与结案

#### 入口

- F2、S2、S4 为已登记的 legacy semantic risk，污染未确认；
- R0 已提供生产者身份，可对异常做归属。

#### 出口

- F2、S2、S4 各自取得确认或排除结论，确认项附受影响指标与量级；
- 结论来自只读测量或有界原始重算，来自代码推断的结论数为 0；
- S6 明确排除于二三月论证之外；
- RFA-03 成立。

#### 边界

- 只测量，不修复；
- 有界重算只在候选或旁路环境执行；
- 不修改冻结核心，不改写历史行。

### R3：原始槽补齐与解析修复

#### 入口

- 6,720 个 `source_unavailable` UPDATE 槽与 70 个缺失 RIB 槽未补齐；
- 34 个 UPDATE 与 3 个 RIB 处于 `parse_failed`。

#### 出口

- 全部槽位或准入、或经源端复核确认为不可得并写明原因；
- 覆盖率为实测值，未登记原因的未准入槽数为 0；
- RFA-04 成立。

若源仍可得但项目方拒绝补取：

- 登记 `backfill_declined_scope_decision`，保持事实与范围决定分离；
- R3 状态为 `scope_stopped`，不得写成 `passed`；
- R 轨停留在 `P0 历史数据兼容`，R4/R5 保持 `not_run`。

#### 边界

- 候选或旁路环境；不执行生产激活；
- 不改写已准入行；
- 健康候选 PGDATA 与已完成检查点必须复用，不因脚本失败重建。

### R4：全窗口 RouteEvent 闭合

#### 入口

- RouteEvent 为 pilot，原始制品清单部分覆盖；
- R3 标准出口已通过，不存在以 `scope_stopped` 替代通过。

#### 出口

- 声明范围内 RouteEvent 具备语义解析、稳定 VP、原始偏移与记录哈希；
- Incident、RouteEvent 与原始引用互相可达；
- 范围之外明确标注未闭合；
- RFA-05 成立。

#### 边界

- 只在明确声明的事件范围内闭合；
- 不扩大到其他异常类型；
- 不把完整 RouteState 常规写入在线查询数据库。

### R5：全量语义复现与发布评审

#### 入口

- 全量跨运行语义复现为 `not_run`；
- R0 至 R4 标准出口均为 `passed`，不存在 `scope_stopped` 替代通过。

#### 出口

- 复现已执行，结果与差异解释已归档；
- 等级声明与实际证据一致；
- 发布评审完成；
- RFA-06、RFA-10 成立，RFA-01 至 RFA-12 全部通过。

#### 边界

- 只做复现与评审；
- 生产激活属于独立授权，不由本阶段结论自动触发；
- 复现未通过时保持未达成状态，不部分声明达成。

## 六、阶段依赖

- R0 是 R2 的前置：无生产者身份时可发现异常但无法归属；
- R1 与 R0、R2 相互独立，可并行；
- R3 → R4 → R5 串行；
- R3 为 `scope_stopped` 时依赖链终止，不进入 R4/R5，也不改变最终合同；
- 任一阶段偏离必须在本阶段修正，不得顺延。
