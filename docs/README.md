# Domeye Core 文档索引

## 使用规则

文档按“当前说明、机器合同、设计材料、计划和历史证据”分层。阅读顺序为：

1. 先看[前后端总览](DomeyeCore前后端总览.md)；
2. 再看对应组件 README；
3. 对 API、数据档、路由和部署路径，以机器合同和源码为准；
4. 设计、计划、基线、验收和回检记录只解释当时目标与证据。

历史验收记录不得作为当前生产运行身份依据。标题包含“最终验收”“联合验收”或
“已通过”也只表示该文档记录的合同和时点；当前生产身份必须通过
[`deploy/inventory/collect-production-runtime.py`](../deploy/inventory/collect-production-runtime.py)
在目标机器上实时采集。

## 文档状态的解释

- `当前架构说明`、`当前开发说明`、`当前流程说明` 和`当前运维说明`需要与当前
  机器合同持续对齐；
- `产品合同`、`API 合同`和`设计目标`表达约束或目标，不能单独证明已经实现；
- `阶段计划`只说明计划；
- `历史基线`记录当时起点；
- `验收记录`和`阶段回检`只对其固定版本、合同和证据范围负责；
- `风险批准记录`只覆盖明确批准的依赖、版本和有效期。

文档相关 Pull Request 运行 `make check-docs`，校验索引覆盖、链接、数据档、路由、
API、部署路径和失效能力描述。
