# Domeye 数据层 224-310 最终验收文档

版本：1.0  
状态：最终效果合同  
适用范围：RRC25 2026 年 2 月 24 日至 3 月 10 日全球 BGP 控制面数据

## 一、文档定位

本文只设计最终效果，不规定建表语句、代码结构、任务编排、进程数量、部署拓扑、
迁移命令或具体实施顺序。

最终效果不是把现有文件机械搬入 PostgreSQL，也不是把现有 PostgreSQL 月表重新命名，
而是形成一条能够持续接收新数据、确定性重放、受控订正、快速查询和冻结报告的统一数据链：

```text
RRC25 原始证据
→ 完整 RouteEvent
→ 可恢复 RouteState
→ 国家 / ASN 五分钟指标
→ 质量状态与连续水位线
→ 事件生命周期
→ 不可变 Observation Publication
→ 不可变 Analysis Publication
→ 页面读模型与报告快照
```

底层证据和发布历史不可变；派生状态和在线读模型可以从已登记事实重建；
`current` 指针可以推进，但不得改写其曾经指向的 Publication。

“国家中断”始终是 Domeye 已有事件类型名称。本合同只描述 RRC25 单采集器所见的
BGP 控制面观测，不据此认定全国断网、用户或业务影响、原因、攻击、政策行为、
责任主体或完全恢复。

## 二、冻结验收数据身份

本合同中的“224-310”唯一指以下数据身份：

| 项目 | 冻结值 |
|---|---|
| collector | `rrc25` |
| 源窗口 | `[2026-02-24T00:00:00Z, 2026-03-11T00:00:00Z)` |
| 时间粒度 | 5 分钟 |
| 状态点语义 | `(t - 5min, t]` |
| 第一个状态点 | `2026-02-24T00:05:00Z` |
| 最后一个状态点 | `2026-03-11T00:00:00Z` |
| 预期状态槽 | 4,320 |
| 国家及显式未知桶 | 241 |
| 预期国家摘要 | 1,041,120 |
| 原始修复制品 | 2 个，必须保留替代来源和摘要，不覆盖原坏文件 |

241 个桶和 1,041,120 条国家摘要必须绑定同一 mapping 身份。mapping 变化时不得沿用
上述人口身份冒充同一版本，而应形成新的 dataset、projection 和 publication 身份。

源窗口使用半开区间；状态点使用五分钟槽结束时刻。事件 URL 中的历史时间、事件首次
检测时间和数据窗口是不同概念，任何页面或 API 都不得用事件 URL 推断数据窗口。

## 三、用户最终获得的效果

新数据进入系统后，用户最终看到的是一个逐步向前、历史可回看的事件，而不是一份被
反复覆盖的文件：

1. 数据到达、缺失、隔离、补齐和订正状态可以区分；
2. 每个页面数字能追溯到指标、状态检查点、RouteEvent 和原始 RRC25 制品；
3. 事件可以从刚检测到、发生中、恢复候选推进到观测结束；
4. 每次推进形成新的不可变 Publication，旧页面快照和旧报告保持可复现；
5. 页面读取已编译的在线读模型，不在请求时扫描原始 gzip 或重算整场事件；
6. 正式报告冻结观测版本、分析版本、窗口、事实和证据引用；
7. 224-310 可以完整重放，也能证明检查点恢复、重复执行和受控订正不会污染历史结果。

## 四、最终效果要求

### DLAE-01：RRC25、窗口和统计人口形成唯一身份

- 所有原始制品、RouteEvent、RouteState、指标、事件、Publication、页面和报告都绑定
  `collector_id=rrc25`；
- `source_system`、旧 `source_code=r` 和 `collector_id=rrc25` 保持不同字段语义，
  不再互相代替；
- 224-310 的半开源窗口、状态点语义、4,320 槽、241 桶、mapping 和最终性贯穿全链；
- 任一层出现 collector、窗口、槽位、mapping 或统计人口冲突时失败关闭，不拼接数据。

### DLAE-02：原始证据不可变、可验证、可定位

- 原始 RIB、UPDATE、修复制品及其清单以不可变对象保存，不把二进制原文写入 PostgreSQL；
- 每个对象具有稳定 URI、SHA-256、字节数、观测时间、来源和完整性状态；
- 两个修复制品不覆盖旧坏文件，替代关系和校验结果可审计；
- 已被 dataset、publication 或 report 引用的对象不得静默覆盖或删除；同路径内容变化必须
  形成新对象和新身份。

### DLAE-03：完整 RouteEvent 成为一次解析、长期复用的权威事件层

- 每条 RouteEvent 保留 collector、VP/peer、事件时间、动作、prefix、完整 AS_PATH、
  状态计算所需属性、原始记录坐标、原始对象摘要和解析质量；
- 稳定事件身份使相同输入重复摄取不会产生重复事实；
- 现有只满足状态计算的紧凑 RouteDelta 不冒充完整 RouteEvent；能力不足保持显式；
- 新投影器能够直接复用 RouteEvent，不因新增国家、ASN、趋势或审计指标再次解析 MRT。

### DLAE-04：RouteState 可从 Seed RIB、事件序列和检查点确定性恢复

- RouteState 由明确的 Seed RIB 与严格有序的 RouteEvent 投影得到；
- 检查点具有输入水位、投影器版本、mapping、状态人口、摘要和内容身份；
- 从头重放与从任一合法检查点继续到同一 `data_through` 时，状态和指标内容摘要一致；
- 检查点损坏、版本不兼容或事件序列不连续时停止推进，不读取不完整状态继续发布。

### DLAE-05：文件证据层与 PostgreSQL 在线层职责清楚且闭合

- 原始 MRT、完整 RouteEvent、高基数 Prefix×VP 状态和 RouteState 检查点保存在不可变
  证据文件层；PostgreSQL 保存其身份、索引、质量和血缘；
- 国家、ASN 和 collector 五分钟指标进入 PostgreSQL/TimescaleDB 的统一在线时序层；
- 事件、生命周期、事实、Publication、当前指针、审计摘要和报告快照进入 PostgreSQL
  事务层；
- 任意跨层引用都能由数据库身份定位到文件对象并校验摘要，不存在只有路径、没有版本，
  或只有数据库行、无法回到证据的孤儿数据。

### DLAE-06：五分钟指标具有统一结构，不再按国家和月份增殖物理表

- collector、国家和 ASN 指标使用统一时间语义、UTC `timestamptz`、单位、分母、
  地址族、质量状态和投影身份；
- 224-310 的每个合法五分钟槽都能按国家、ASN、地址族和时间范围稳定查询；
- 新国家、新月份和新数据到达不要求应用运行时创建 `feature_<country>_<yyyymm>`、
  `event_table_<yyyymm>` 一类业务表；
- 指标缺失、未知、不适用和真实零值保持不同语义；缺失不得以零值落库。

### DLAE-07：质量状态和双水位线决定数据能否向前发布

- `attempted_through` 表示已尝试处理位置，`data_through` 表示连续、完整并通过质量门的
  最后位置；
- 缺槽、哈希变化、解析失败、顺序错误、人口不守恒或 mapping 冲突会阻止
  `data_through` 越过问题槽；
- 缺口以明确区间、原因和处置状态保存，不删除、不补零、不伪造完整窗口；
- 224-310 最终接受时必须为 4,320/4,320、missing=0、`data_through` 等于窗口末端，
  且最终性明确为 final。

### DLAE-08：任意派生事实具有端到端血缘并可确定性重建

- 页面上的一个数值可以反查 publication、projection、算法版本、mapping、RouteState
  检查点、RouteEvent 分区和原始对象；
- 同一冻结输入、同一配置和同一算法版本重复执行时，语义结果与内容摘要一致；
- 算法、mapping 或输入改变时产生新版本，不借用旧摘要或旧最终性；
- 删除可重建缓存后，系统能从不可变证据和登记血缘恢复同一读模型。

### DLAE-09：事件生命周期追加演进，不覆盖历史观察

- 国家中断事件至少能区分 `detected`、`ongoing`、`recovery_candidate`、
  `recovered_observation` 和 `final`；
- 每次阶段变化都绑定观测时刻、数据水位、检测算法、证据和未知限制；
- 后续数据可以推进或撤销恢复候选，但只能追加新事实和新 Publication；
- `recovered_observation` 和 `final` 仅描述 RRC25 控制面观测，不升级为真实服务恢复。

### DLAE-10：Publication 不可变，当前指针可原子推进

- 每次可发布数据推进生成新的 `publication_id`；已经发布的窗口、事实、文件和摘要不修改；
- 正常追加保持同一 revision 语义；已发布历史范围发生订正时生成新 Publication、提升
  revision、保存订正原因和被替代关系；
- `current_observation_publication_id` 只在新 Publication 完整校验后原子切换；
- 旧链接、旧下载和旧报告仍能解析到原 Publication，不被当前指针重定向成新事实。

### DLAE-11：观测发布和分析发布各自推进并公开延迟

- Observation Publication 只依赖确定性观测、指标、质量和事件事实；
- TrendProfile 等分析结果形成独立 Analysis Publication，并明确
  `derived_from_observation_publication_id`；
- 当前观测可以领先当前分析，页面必须显示各自 `data_through` 和分析滞后；
- 需要统一口径的正式输出只绑定时间一致且通过校验的观测与分析组合。

### DLAE-12：页面和 API 只读取预计算读模型

- 事件详情、质量、审计、紧凑 4,320 点序列和趋势摘要在发布时编译完成；
- 在线请求不扫描原始 MRT、不遍历 RouteEvent 分区、不解压全量 ASN 状态，也不重复计算
  同一 Publication；
- 同一验收环境下，事件快照冷读 P95 不超过 2 秒、热读 P95 不超过 500 毫秒；
- 4,320 点紧凑序列压缩响应不超过 1 MiB，P95 不超过 2 秒；数据快照接口不得因
  Sidecar 的 5 秒预算而超时；
- ASN 和 Prefix×VP 明细按需下钻，不作为事件首页和报告快照的强制全量载荷。

### DLAE-13：报告冻结一个可重现的数据快照

- 报告数据入口一次返回 incident、observation publication、analysis publication、revision、
  window contract、fact set、trend profile、evidence refs、limitations 和 snapshot hash；
- 报告生成期间当前指针继续推进，不改变已经绑定的报告输入；
- 用户请求更新报告时生成新报告版本，不修改原报告；
- 模型只能叙述已经通过合同校验的事实，不能补写缺失数据、修改数字或提升因果结论。

### DLAE-14：旧 Domeye 数据以影子迁移方式进入统一语义

- 旧 PostgreSQL 表冻结只读，保留源表、源主键、时间解释和导入批次；
- 新结构在独立候选区域形成，不原地重写旧表，不让应用启动时创建新的国家/月度表；
- 新旧读取对同一窗口的标准化结果能够对账，差异具有字段级原因和处置状态；
- 切换后在线产品只读取统一层；旧表仅用于追溯和回退，达到独立退役条件前不删除。

### DLAE-15：写入权、读取权、完整性和回收边界可执行

- 发布者与运行时使用不同身份；运行时只能读取正式证据和 Publication；
- 已完成对象和 Publication 对运行时只读，内容摘要在消费前可校验；
- 未完成、隔离、候选和正式对象具有不同状态与路径身份，未完成数据不能被 API 选中；
- 回收只处理没有 dataset、publication、report 或保留策略引用的对象；
- 数据库、证据对象、发布指针和报告之间不存在部分切换：失败时保持上一个完整版本可用。

### DLAE-16：224-310 以同一候选身份完成端到端验收

- 4,320 个状态槽、241 个国家及显式未知桶、1,041,120 条国家摘要在同一候选身份下闭合；
- 原始校验、RouteEvent 完整性、RouteState 重放、指标人口、缺口、水位、事件、Publication、
  API、报告快照和恢复演练均具有可复核证据；
- 至少验证重复摄取不重复、检查点接续、缺槽失败关闭、迟到数据订正、当前指针原子切换、
  旧报告不变和缓存删除后重建；
- 只有数据效果、查询效果、恢复效果、迁移对账和权限边界共同通过，才能宣布数据层最终通过；
- 文档、Hook、测试数量、单个 API 200、静态截图或历史生产记录均不能单独构成通过。

## 五、最终阅读与查询效果

任何事件详情和报告都按以下顺序暴露数据身份：

1. incident、国家、collector 和事件类型；
2. Observation Publication、revision 和最终性；
3. 源窗口、状态点窗口、4,320 槽和 `data_through`；
4. mapping、统计人口、单位和质量状态；
5. 事件阶段、五分钟指标和 Analysis Publication；
6. 原始证据、RouteEvent、检查点、算法和公式血缘；
7. limitation、unknown、订正历史和旧版本入口。

系统不得只给一个“当前结果”而隐藏它来自哪个版本，也不得要求用户从 URL、文件名、
数据库月份表或服务器目录推断数据时间范围。

## 六、明确不产生的效果

本合同不得被解释为交付以下能力：

- rrc25 之外的 collector 选择、聚合或交叉验证；
- 224-310 之外数据的生产完成声明；
- DNS、HTTP、流量、Probe 或外部业务遥测融合；
- 全国断网、用户影响、业务损失、原因、攻击、政策、责任或传播因果；
- 把对象文件系统当作在线查询数据库，或把 PostgreSQL 当作原始 MRT 文件仓库；
- 把缓存、当前指针或可重建读模型当作不可替代的原始事实；
- 以扩大超时、增加内存或重复重试代替预计算读模型；
- 在本设计任务中读写生产数据库、迁移数据、重跑 224-310、构建候选或切换生产。

## 七、不构成最终通过的情况

以下任一情况存在时不得宣告通过：

- 原始文件、指标、事件或报告缺少统一 dataset/publication 身份；
- 仍以国家或月份创建新的业务物理表；
- 五分钟国家或 ASN 指标只保存在文件中，导致在线查询继续扫描制品；
- 将原始 MRT、完整 RouteEvent 或全量 Prefix×VP 状态作为 PostgreSQL 热表堆放；
- 把现有紧凑 RouteDelta 宣称为包含完整 AS_PATH 和全部属性的 RouteEvent；
- 缺槽后 `data_through` 仍越过缺口，或缺失被写成零；
- 新数据覆盖旧 Publication、旧报告或被引用证据；
- 页面与报告使用不同 publication、revision、window 或 fact set；
- API 冷请求仍需解压、扫描和重复计算全量 224-310 证据；
- 旧表被原地改写，迁移差异没有来源和回退路径；
- 只证明代码存在或 Hook 通过，没有 224-310 的端到端结果证据；
- 把 RRC25 控制面观测写成真实网络中断、用户影响、原因或完全恢复。

## 八、最终判定

- **通过**：DLAE-01 至 DLAE-16 全部具有同一候选身份的可复核证据；
- **有条件通过**：没有已知偏离，但明确列出的外部验收条件尚未到期；
- **不通过**：任一到期要求失败，或通过降低、删除、改写本文规避失败；
- **未知**：证据缺失或无法重现；未知不得解释为通过。

本合同冻结目标效果，但不授权修改 `backend/core/`、读写生产数据库、删除旧表、
重跑或改写 224-310 制品、扩大时间范围、增加 collector、部署或切换生产运行时。
