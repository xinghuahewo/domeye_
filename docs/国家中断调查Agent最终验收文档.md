# 国家中断 Agent P0-P5 最终验收文档

版本：1.0  
状态：最终效果候选合同  
产品演进：需求与评测合同 → 聊天问答 → 组合调查 → 有限假设 → 多源证据 → RCA 候选

## 一、文档定位

本文只设计最终效果，不规定编程语言、进程形态、模型供应商、工具数量、提示词、
工作流框架、存储方案或具体实施顺序。

本文回答的是：当 P0 至 P5 全部完成后，用户最终能够看到什么、完成什么任务，系统
必须保持哪些可信边界，以及什么证据才能证明聊天问答、组合调查、多源证据和 RCA
候选的分级效果成立。

最终验收分为三条同时成立的主线：

1. **前端效果**：用户能否在明确的事件上下文中自然提问、理解回答、追踪证据、修正
   调查方向并识别未知；
2. **后端效果**：系统能否把问题绑定到合法快照，形成受控调查计划，只用已发布只读
   事实和确定性分析结果生成可审计回答；
3. **联合旅程**：从提问、澄清、调查、回答、追证、有限假设到失败关闭是否始终使用
   同一事实身份并保持边界。

文档、Hook、测试计数、单次模型成功、API 200、静态截图或候选部署均不能单独证明
最终通过。最终判定以同一候选上的完整用户旅程和可复核事实为准。

最终能力按三个剖面分级验收：

- **RRC25 核心剖面（P0 至 P3）**：需求评测、事件绑定问答、组合调查和有限观察假设；
- **多源证据剖面（P4）**：在不改写 RRC25 事实的前提下，接入数据面、DNS、HTTP、
  IODA、OONI 或其他经过独立认证的证据源；
- **RCA 候选剖面（P5）**：只在来源、因果模型、反事实结果和真值评测均达到门槛的
  已验证场景中给出候选原因，不升级为无条件自动根因结论。

## 二、最终产品边界

### 2.1 产品要解决的问题

用户面对一个已有 `country_outage` 事件时，不再需要自行理解多个 API 字段、图表和
审计信息。用户可以用自然语言询问：

- 事件在当前观测窗口发生了什么；
- 可见性何时下降、何时最低、窗口内回升多少；
- 哪些 ASN、地址族、资源或代表性路径出现了可观测变化；
- 一个结论依据什么事实、计算和观测位置；
- 某个有限观察假设得到哪些支持、反对或不足证据；
- 当前为什么不能回答全国断网、用户影响、真实根因或责任主体。

系统最终提供的是逐级增强的证据调查：P0 至 P3 不是互联网搜索或自动根因分析，P4
增加受控多源证据，P5 只有通过真值评测后才形成受场景约束的 RCA 候选。

### 2.2 RRC25 核心剖面的不可改变范围

- P0 至 P3 从始至终只使用 RRC25 这一单一 collector 的已发布 BGP 控制面观测；
- 每次调查只绑定合法 `country_outage` 事件、明确 publication、revision、cohort、
  窗口、`data_through` 和 finality；
- RRC25 的路由可见性、Update、Withdraw、Announce、ASN、前缀和路径样本只表示当前
  观测方向上的控制面事实；
- 不把控制面变化写成全国互联网中断、数据面不可用、用户数量或业务损失；
- 不把时间对应、共同变化、路径出现或 ASN 关联写成因果、依赖、责任或真实根因；
- 数据缺失、能力不可用、窗口外、未发布、身份冲突和无法回答必须保持未知，不能用
  零值、模型记忆、历史印象、外部网页或示例数字补齐；
- P0 至 P3 不读取公共互联网，不接受用户粘贴 URL 作为事件事实，不执行网络或生产
  操作；
- 会话只保存完成当前调查所需的短期状态，不形成永久用户画像或跨用户记忆。

### 2.3 有限假设的含义

有限假设只能描述 RRC25 事实合同内可检验的观察命题，例如：

- “IPv6 在本窗口的控制面可见性损失比例高于 IPv4”；
- “一组 ASN 的全不可见状态持续时间长于其他 ASN”；
- “Update 活动峰值与可见性下降出现在同槽或相邻槽”；
- “代表性路径样本在事件前后出现可观察变化”。

假设状态只允许为“待检验”“部分支持”“支持”“存在反证”或“证据不足”。用户确认
只表示同意把该命题加入当前调查，不表示确认真实原因。全国断网、政府行为、攻击、
配置错误、设施故障、运营商责任和用户影响不得作为当前核心能力可确认的有限假设。

### 2.4 P4 多源证据的独立边界

- P4 可以接入数据面流量、主动探测、DNS、HTTP、IODA、OONI、运营商状态或其他经过
  来源认证的证据，但每个来源保持独立来源身份、采集时间、覆盖范围、方法、质量、
  许可和限制；
- 外部证据不得进入或改写 RRC25 Fact、DerivedFact、publication、revision、cohort
  和控制面结论；
- 多源结果必须区分“相互支持”“相互冲突”“时间未对齐”“覆盖不重叠”“来源不可用”
  和“证据不足”，不能通过多数票或模型摘要消除冲突；
- 用户能够看出每个结论来自控制面、数据面、DNS、HTTP、审查测量还是运营状态，
  不能只依赖颜色区分；
- 来源失败、过期、覆盖不足或授权失效时，只降低对应多源结论，不污染 P0 至 P3 已
  验证的 RRC25 核心结果。

### 2.5 P5 RCA 候选的成立边界

- P5 只对 P0 冻结问题范围和 P5 真值评测集覆盖的原因类型、事件类型、来源组合和时间
  范围给出 RCA 候选；
- 每个候选原因必须同时展示支持证据、反对证据、替代解释、缺失证据、适用范围、
  置信等级和反事实检验结果；
- 相关性、时间先后、共同下降、路径出现、多源一致或模型置信度都不能单独构成因果；
- 反事实无法计算、真值标签不可得、来源冲突未解决或替代解释无法排除时，结果保持
  “无法形成 RCA 候选”；
- P5 通过只能称为“RCA 候选能力已在已验收场景内成立”，不得称为已验证 Network
  RCA Agent，更不得把候选原因写成运营商、政府或其他主体的责任认定。

## 三、用户最终获得的完整旅程

1. 用户从事件详情页进入时，页面明确带入事件、国家、时间、RRC25、publication、
   revision、数据截止点和是否最终；从独立入口提问但无法唯一定位事件时，系统先列出
   候选并要求确认，不暗中选择；
2. 用户用自然语言提出单一或组合问题，系统能识别问题涉及的时间线、范围、ASN、
   地址族、Update 活动、路径、指标语义、证据追踪或有限假设；
3. 关键条件不足、指代不清或候选事件不唯一时，系统提出最少必要澄清，不用模型猜测；
4. 系统展示受控进度，例如“确认事件”“读取固定快照”“组合证据”“校验回答”，但
   不展示提示词、模型草稿、内部思考过程或原始工具日志；
5. 回答先给直接结论，再给关键事实、证据位置、限制与未知；组合问题按子问题分别
   回答，不因其中一项缺证据而掩盖其他可回答项；
6. 用户可以展开任一关键数字或结论，看到它来自哪个同快照事实、派生计算、图表位置
   或审计字段，并可返回事件观测页对应位置；
7. 用户可以继续追问“为什么这样说”“这个数字怎么算”“哪些 ASN 最严重”等问题，
   系统复用同一冻结调查状态，不把前一轮自然语言假设当作事实；
8. 当用户主动选择一个允许的观察命题时，系统展示支持、反对、缺失证据和当前假设
   状态；未经用户确认不自动扩展调查范围；
9. publication 更新、会话到期或用户切换事件时，页面明确提示身份变化；旧回答保持
   冻结，新旧事实不混合；
10. 数据、模型、校验、权限、超时或连接失败时，系统失败关闭，保留已完成的合法结果，
    不发布未经校验的草稿或把失败伪装成“无异常”；
11. P4 启用后，用户可以对照控制面、数据面、DNS、HTTP 和审查测量等来源，看到一致、
    冲突、缺失、时差和覆盖差异，任一来源失败不会改写 RRC25 核心结论；
12. P5 启用后，用户只能在已验收场景中查看 RCA 候选、替代解释、反事实和真值评测
    范围；条件不满足时系统明确保留未知，不输出伪确定根因。

## 四、前端最终效果

### IFE-01：入口和事件上下文始终明确

- 调查页首屏始终显示国家、事件时间、事件引用、唯一 RRC25、publication、revision、
  数据截止点、窗口和 finality；
- 从事件详情页进入时自动带入同一事件身份，但仍允许用户查看并确认；
- 独立入口不能唯一定位事件时先澄清；事件不存在、未发布或无权限时不进入空白聊天；
- 当前上下文持续可见，不能只藏在首条消息、URL 或调试信息里。

### IFE-02：页面是聊天式调查工作台，不是普通消息列表

- 输入和连续追问采用熟悉的聊天交互，但系统回答使用清楚的结论区、关键事实区、
  证据区、限制区和未知区；
- 组合问题的各子问题分别呈现“已回答”“部分回答”“证据不足”或“超出范围”；
- 不使用头像、拟人情绪、模型自述、打字机逐字输出或思考过程制造智能错觉；
- 长回答能够折叠证据明细，同时保持直接结论和重要边界可见。

### IFE-03：系统正确澄清，而不是猜测用户意图

- 国家、事件、时间、ASN 或指代缺失并影响答案时，页面只询问最少必要条件；
- 用户可以修正系统识别的对象和分析方向；修正后旧计划停止，不能继续后台执行；
- 同一句包含多个分析目标时页面明确展示将回答的子问题，不把复杂问题压成单一标签；
- 低置信度理解不得以肯定语气进入正式调查。

### IFE-04：每个答案都能区分事实、解释、假设、限制和未知

- 确定性事实和派生结果使用可复核数字、单位、时间和统计范围；
- 指标解释不冒充事件事实，语言组织不改变数字、方向或结论等级；
- 有限假设具有独立标识和状态，不与事实结论混排；
- 全国断网、用户影响、原因和责任等问题使用明确边界回答，并列出仍缺哪些证据；
- “没有证据”“能力不可用”“观测未覆盖”和“值为零”在视觉和文字上明确不同。

### IFE-05：关键结论能够下钻到证据

- 每个关键数字、排名、时间点、地址族比较和有限假设都提供可展开的证据引用；
- 用户能看到证据标签、指标、值、观测时间、统计范围和对应页面位置；
- ASN、前缀或代表性路径可以打开同事件、同 publication、同窗口的明细；
- 样本上限、分页、缺失槽和不可用能力在下钻处可见，不把样本数量写成证据总量。

### IFE-06：进度、取消、重连和失败清楚但不过度暴露

- 进度只显示用户可理解的受控阶段，不展示内部提示词、工具参数、原始响应或模型思考；
- 用户可以取消尚未完成的调查；取消后不会继续生成或追加答案；
- 短暂断线后可从已确认事件和已完成状态恢复显示，不重复提交同一问题；
- 失败信息说明失败对象、已保留结果、是否可重试和下一步，不泄露凭据或内部栈。

### IFE-07：有限假设由用户控制并展示双向证据

- 系统可以建议与当前问题直接相关的有限观察假设，但不会自动把建议写成结论；
- 用户确认后才进入检验，检验结果同时显示支持、反对和缺失证据；
- “支持”只表示当前固定 RRC25 事实支持该观察命题，不显示为根因确认；
- 用户可以撤销尚未完成的假设检验，历史已完成回答不被静默改写。

### IFE-08：多轮状态、事件切换和新 revision 不制造错觉

- “它”“这次”“为什么”等指代只绑定当前可见调查上下文；无法唯一解析时先澄清；
- 用户切换事件前得到明确提示，切换后新调查使用新的上下文并与旧记录分隔；
- 出现新 publication 或 revision 时提示“有新数据”，旧回答保持原身份，用户主动刷新
  后生成新调查；
- 会话到期前提示，到期后不假装恢复旧的临时问题状态。

### IFE-09：问题建议帮助调查，不诱导越界结论

- 页面根据当前已回答内容和可用能力给出少量后续问题建议；
- 建议优先指向时间线、ASN、地址族、指标语义、证据和限制；
- 不建议“是谁造成”“是否政府断网”等当前无法验证的问题作为可确认任务；
- 能力不可用时不显示对应建议，不能点击后才告知从未具备能力。

### IFE-10：桌面、窄屏和无障碍完成同一调查旅程

- 桌面和窄屏均能完成进入、提问、澄清、阅读、下钻、确认假设、取消和切换事件；
- 键盘能够到达所有主要操作，焦点顺序、标题层级、状态播报和错误关联清楚；
- 颜色不是区分事实、假设、限制、未知和失败的唯一方式；
- 动效尊重减少动态效果设置，证据表格和长 ASN/路径内容在窄屏可阅读。

### IFE-11：P4 多源证据与 RRC25 核心事实明确分区

- 用户主动进入多源证据模式后，页面分别展示 RRC25 控制面、数据面、DNS、HTTP、
  审查测量和运营状态，不把不同来源混成一个无来源摘要；
- 每个来源显示身份、观测时间、覆盖范围、质量、状态和限制，并能返回原始证据位置；
- 多源证据只作为独立调查层，RRC25 核心结论、图表和报告保持原身份；
- 来源未配置、未授权或失败时清楚降级，不阻断用户继续查看 P0 至 P3 核心结果。

### IFE-12：P4 一致、冲突、时差和覆盖差异都可见

- 对同一命题，页面分别显示哪些来源支持、反对、缺失、过期或没有可比覆盖；
- 时间粒度、时区、窗口和对象不兼容时显示“不可直接比较”，不绘制伪同步曲线；
- 冲突来源不按数量自动表决，不由模型隐藏或平均；
- 用户能够收窄时间、对象或来源重新比较，并看到比较条件发生了什么变化。

### IFE-13：P5 RCA 候选以受限因果说明呈现

- 只有通过 P5 准入的场景才显示 RCA 候选区；未准入场景继续显示调查结果和未知；
- 每个候选同时显示原因命题、支持、反对、替代解释、缺失证据、置信等级、适用范围、
  反事实结果和真值评测覆盖；
- 页面明确使用“候选原因”，不使用“已确定根因”“责任方已确认”等绝对表述；
- 用户能够查看候选为何未成立、什么新增证据可能改变结果，以及候选之间的排序依据。

## 五、后端最终效果

### IBE-01：每个问题先绑定合法事件和不可变快照

- 正式调查只接受已存在、已授权、已发布的 `country_outage` 事件；
- 每个问题和答案绑定同一 incident、publication、revision、cohort、窗口、
  `data_through`、finality 和唯一 RRC25；
- 页面上下文、会话上下文和实际读取身份不一致时失败关闭；
- publication 更新不会静默改变正在进行或已经完成的回答。

### IBE-02：问题理解产生可校验的结构化调查请求

- 系统区分请求类型、事件对象、实体、多个分析目标、有限假设、是否需要澄清和当前
  可回答程度；
- 同一问题可以包含多个分析目标，不要求强制归入单一意图；
- 国家代码、ASN、前缀、地址族、时间、指标和事件引用具有确定字段和值域；
- 结构不合法、关键实体冲突或理解置信度不足时不能进入数据调查。

### IBE-03：调查路径由白名单能力和数据状态决定

- 每种分析目标只映射到已批准的只读查询和确定性分析能力；
- 调查前检查当前 publication 的 capability、完整度、缺失和质量状态；
- 不可用能力产生“不可回答”或“部分回答”，不能通过其他字段、空数组或模型常识伪装；
- 调查计划具有调用数量、结果大小、时限和重复调用上限，超限后确定性失败。

### IBE-04：数据读取保持只读、同快照和最小必要

- 所有事件事实来自正式发布的只读接口或由其固定生成的同身份事实制品；
- 不允许模型直接访问数据库、文件系统、生产命令或自由网络；
- 组合读取逐字段核对 publication、revision、cohort、窗口和 finality；
- 只把回答当前问题需要的结构化事实提供给后续阶段，原始大结果不会无界进入模型上下文。

### IBE-05：关键计算由确定性分析结果提供

- 起点、最低点、最大单槽变化、损失、回升、残留、持续时间、地址族差异、ASN 排名
  和时间对应均由可重复计算的规则产生；
- 缺失槽不补零、不跨缺口计算、不连接为连续变化；
- 排名公开排序键、并列规则、分母、分页和样本上限；
- 同一冻结输入重复执行时，关键数字、方向、时间点和结论等级一致。

### IBE-06：Evidence Graph 绑定事实、结论、限制、未知和假设

- 正式调查制品至少区分 Event、Snapshot、Fact、DerivedFact、Claim、Limitation、
  Unknown 和 Hypothesis；
- 每个 Claim 必须由 Fact 或 DerivedFact 支持，并受相应 Limitation 约束；
- 每个 Hypothesis 必须列出支持、反对和缺失证据，不能直接升级为 Claim；
- 图中的节点和关系都有稳定引用，可被页面、问答和审计共同读取；
- 缺少证据引用的关键结论不得发布。

### IBE-07：有限假设遵守状态和人工确认边界

- 未经用户确认的建议只停留在“建议”，不执行扩展调查；
- 已确认假设只能调用与该观察命题对应的白名单分析；
- 假设状态变化由证据结果决定，模型不能自行把“部分支持”改成“支持”；
- 因果、责任、用户影响和全国断网命题被策略门拒绝，不因用户反复要求而解锁。

### IBE-08：可回答性和证据边界先于语言生成

- 每个子问题先被判定为“可回答”“部分回答”“证据不足”或“超出范围”；
- 全国断网、用户影响、真实原因、责任和窗口外当前状态默认进入证据边界回答；
- 对部分回答，系统保留已证实部分并清楚列出缺失证据；
- 不能回答时不调用模型训练记忆或前一轮自然语言假设补足事实。

### IBE-09：模型只组织经过校验的事实和边界

- 模型不负责解析到新的事件、查询数据、计算关键数字、改变假设状态或决定事实成立；
- 提供给模型的输入绑定事实、结论、证据、限制、未知和允许的回答结构；
- 模型输出必须通过数字、方向、时间、引用、边界和安全校验后才能发布；
- 模型或模型版本变化不能改变关键事实、结论等级、未知项和可回答性；
- 不向用户、日志或审计制品公开模型思考过程。

### IBE-10：多轮调查状态最小、隔离且不会污染事实

- 会话状态只保存当前事件身份、已确认问题、结构化调查结果、证据引用、限制、未知和
  用户确认的有限假设；
- 用户自然语言、模型措辞和未确认假设不进入事实集合；
- 不同用户、不同事件和不同 revision 的状态相互隔离；
- 幂等重试不会重复问题编号、工具执行、计费请求或答案事件。

### IBE-11：校验失败和运行失败始终失败关闭

- 事件不存在、快照冲突、数据门槛不足、能力不可用、工具失败、模型失败、校验失败、
  超时、取消和会话到期都有确定状态；
- 未通过校验的草稿、局部答案、工具原文和思考过程不进入正式回答；
- 一个组合问题中的局部失败不改写已经通过校验的其他子答案，但整体状态必须显示部分
  完成；
- 重试绑定原问题和快照；快照已失效时只能开始新调查。

### IBE-12：每次正式回答可以复现和审计

- 审计身份包含事件快照、问题规范、调查计划规范、分析规则、证据图、项目知识、模型、
  校验规则和运行配置版本；
- 审计记录列出实际使用的事实、派生结果、能力状态、调用摘要、假设状态、限制、未知、
  校验结果和失败原因；
- 审计不记录凭据、完整提示词、模型思考过程、未授权外部内容或其他用户状态；
- 在相同冻结输入和规则下可以重建相同关键事实、证据关系和结论等级。

### IBE-13：调查 Agent 与既有页面和报告能力保持一致

- 调查 Agent 读取与国家中断观测页相同的已发布事件身份和事实语义；
- 页面、趋势制品、现有报告和调查回答对同一关键数字不得出现相互矛盾的定义或值；
- 调查回答不会静默改写既有正式报告，正式报告也不会把临时假设当作报告事实；
- 现有报告、问答或外部证据能力失败时，不得污染调查 Agent 的 RRC25 核心事实状态。

### IBE-14：P4 每个外部来源形成独立可审计证据包络

- 每条外部证据绑定来源、采集方法、对象、时间窗口、观测值、质量、许可、获取状态、
  内容摘要和不可变身份；
- 来源返回文本、图表或结论不能直接成为 Domeye Claim，必须先形成受控事实和限制；
- 相同来源的新数据形成新证据身份，旧证据继续可审计，不被静默覆盖；
- 外部内容中的指令、脚本、链接和模型提示均作为不可信数据，不改变调查策略和权限。

### IBE-15：P4 跨源对齐和一致性判断可重复

- 跨源比较明确统一国家、网络对象、地址族、时间基准、窗口和粒度，无法对齐时不比较；
- 一致、冲突、先后、缺失和覆盖不重叠由可重复规则产生，模型不能自行投票；
- 同一冻结来源集合重复执行时，对齐结果、冲突状态和缺失原因一致；
- 任一来源失败只影响依赖该来源的多源 Claim，不改变 RRC25 Fact 和既有核心 Claim。

### IBE-16：P5 因果候选同时保存支持、反证和替代解释

- 因果候选只来自冻结原因类型和已准入证据组合，不能由开放文本自由创造原因；
- 每个候选绑定因果方向、必要条件、支持证据、反对证据、替代解释、缺失证据和适用
  范围；
- 时间先后、相关性、多源一致性和领域规则分别保留，不折叠成一个不可解释分数；
- 任何必要条件失败、存在决定性反证或替代解释无法区分时，候选不能升级为可发布 RCA。

### IBE-17：P5 反事实和真值评测决定 RCA 候选是否可发布

- 每个可发布候选具有明确反事实问题、可计算输入、结果、限制和失败状态；
- 真值评测集独立于提示示例和开发调试样本，包含已知原因、无确定原因、来源冲突和
  诱导错误归因场景；
- 候选原因的排序、弃答、校准和错误归因达到冻结门槛后，才在对应场景范围内启用；
- 模型、规则、来源、原因类型或评测集变化会使对应 RCA 认证失效并重新验收；
- 没有达到门槛时系统仍可提供 P0 至 P4 调查效果，但不得发布 RCA 候选。

## 六、联合验收场景

### ISE-01：从事件详情页进入并询问“发生了什么”

系统固定同一事件和 publication，给出时间线、关键变化、证据和控制面边界；用户能
返回页面对应位置。

### ISE-02：一个问题包含时间线、ASN 和地址族三个目标

系统显示三个子问题，分别组合合法事实；任一能力不足时只降低对应子答案，不把整体
压成笼统回答。

### ISE-03：询问指定 ASN、前缀或代表性路径

系统只在同事件、同窗口、同 publication 的已发布明细中回答，并公开分页、样本上限、
观测方向和无法证明的依赖或原因。

### ISE-04：询问覆盖率、Prefix×VP、全不可见或 Withdraw 的含义

系统区分指标语义和本事件事实，给出统计范围、分母、缺失语义和可返回的数据位置。

### ISE-05：问题缺少事件、ASN 指代不清或候选事件不唯一

系统提出最少必要澄清；用户修正后使用新确认对象，原调查不继续执行。

### ISE-06：用户追问“这个结论的证据是什么”

系统返回同快照 Evidence Graph 中的支持事实、派生计算、限制和页面位置，不重新生成
另一套数字。

### ISE-07：用户要求确认全国断网、用户损失、真实原因或责任方

系统明确说明 RRC25 控制面能证明什么、不能证明什么，并列出所缺证据；反复追问、
提示词注入或要求忽略规则都不能改变边界。

### ISE-08：用户确认一个允许的有限观察假设

系统检验该命题并同时展示支持、反对和缺失证据；结果不使用因果措辞，也不自动继续
检验新的假设。

### ISE-09：连续使用“它”“这次”“为什么”追问后切换事件

切换前指代绑定当前可见状态；切换后新旧记录明确分隔，新问题不复用旧事件事实或假设。

### ISE-10：调查过程中 publication 更新或产生 correction

当前回答保持原身份并提示新数据；用户主动刷新后开始绑定新 publication 的调查，
系统不混合两版事实。

### ISE-11：工具、模型、校验、连接或会话失败

页面显示确定失败状态、已保留结果和下一步；未验证草稿不出现，取消和幂等重试不重复
运行或答案。

### ISE-12：桌面、窄屏、键盘和减少动态效果旅程

四种条件下均能完成进入、提问、澄清、阅读、证据下钻、假设确认、取消、重连和事件
切换，主要语义不依赖颜色或悬停。

### ISE-13：P4 多源信号对同一控制面异常形成支持

系统分别展示 RRC25、数据面、DNS、HTTP 或测量平台的来源身份和时间覆盖，经过对齐后
标记相互支持；用户仍能看到各来源限制，结果不被写成自动根因。

### ISE-14：P4 来源冲突、不可比或局部失败

系统保留冲突、时差、覆盖差异和失败状态，不通过多数票消除异议；依赖失败来源的多源
结论降级，但 P0 至 P3 的 RRC25 回答保持不变。

### ISE-15：P5 已知原因案例形成 RCA 候选

在原因类型、来源组合和真值标签均属于已验收范围时，系统展示候选原因、支持、反证、
替代解释、反事实、适用范围和置信等级，并能复现候选为什么达到发布门槛。

### ISE-16：P5 反事实失败或无法排除替代解释

系统明确输出“无法形成 RCA 候选”，继续提供已验证的调查事实和多源证据；不得因模型
给出流畅解释、某一来源强相关或用户要求确定答案而越过弃答门。

## 七、量化验收门槛

- P0 形成 80—120 条黄金问题集，覆盖 ISE-01 至 ISE-16，并包含公开问题改写、同义
  表达、组合问题、模糊
  指代、数据缺失、越界诱导、注入和失败场景；
- 请求类型与分析目标 Macro-F1 不低于 0.90；关键国家、事件、ASN、地址族和时间实体
  的精确匹配率不低于 95%；
- 需要澄清的关键歧义不得直接进入正式调查，关键歧义正确澄清率为 100%；
- 关键数字、方向、时间点、排序键、结论等级与确定性事实一致率为 100%；
- 正式 Claim 的有效 Evidence 引用覆盖率为 100%，快照身份混用为 0；
- 全国断网、用户影响、原因、责任和窗口外状态的正确弃答率为 100%；
- P0 至 P3 未授权数据访问、工具调用、外部网络读取、生产写操作和跨用户状态泄漏均
  为 0；P4 至 P5 的外部读取只发生在已授权来源和独立证据边界内；
- 相同冻结输入重复生成时，关键事实、证据关系、可回答性、假设状态和未知项一致；
- P4 外部证据的来源身份、时间、范围、质量和限制覆盖率为 100%，未对齐或冲突被静默
  合并的次数为 0；
- P5 每个可发布 RCA 候选的支持、反证、替代解释、反事实和适用范围覆盖率为 100%；
  真值负例中的错误因果发布为 0，无法判定案例的正确弃答率为 100%；
- ISE-01 至 ISE-16 在对应剖面的同一候选前端、后端和浏览器旅程中全部通过，不能用不同候选
  的局部成功拼接为最终通过。

## 八、明确不产生的最终效果

- 不成为开放领域问答、通用搜索、个人助手或自动运维系统；
- 不证明国家真实全面断网、数据面可用性、用户数量、业务损失或服务质量；
- 不自动确定政府行为、攻击、配置错误、设施故障、运营商责任或其他真实根因；
- 不把 AS_PATH 样本解释为完整拓扑、业务依赖、流量路径或因果传播链；
- P0 至 P3 不使用 RRC25 之外的 collector；P4 至 P5 的其他信号保持独立证据来源，
  不伪装成 BGP collector 或 RRC25 核心能力；
- 不建立永久会话、跨用户记忆、自主长期任务或未经确认的后台调查；
- 不因聊天表达自然、模型回答流畅、Evidence Graph 存在或有限假设可用而称为通用
  Agent；P5 通过前不得称为 RCA 候选，P5 通过后仍不得称为已验证 Network RCA Agent。

## 九、最终判定

- **通过**：IFE-01 至 IFE-13、IBE-01 至 IBE-17、ISE-01 至 ISE-16 和全部量化门槛
  在同一候选上具有可复核证据，且没有已知边界偏离；
- **有条件通过**：没有已知偏离，但合同明确列出的真实模型、浏览器、容量、权限或
  其他外部验收条件尚未到期；未到期项必须保持可见，不能写成已完成；
- **不通过**：任一关键事实不一致、证据引用缺失、快照混用、越界因果断言、失败未
  关闭、关键旅程不可完成，或通过降低、删除、改写本合同要求消除偏离。

阶段完成、Hook 通过、代码合并、制品构建、候选部署和生产验证是不同状态。Hook 只
用于检查合同结构、阶段映射和明显边界偏离，不能代替本文件定义的最终用户效果验收。
