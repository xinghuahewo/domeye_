## 一、审查说明

本文不是对 P2 已实现能力的声明，而是供产品、BGP 与证据语义逐题审查的问答草案。

每道题包含：

- **当前拟答**：按照当前 publication、Tool、Operator 和底层数据能力，系统此刻应如何回答；
- **证据等级**：答案来自已发布事实、确定性派生、后端未发布数据，还是需要外部证据；
- **所需执行单元**：对应 Tool、Operator 或待建设能力；
- **限制与禁止表述**：防止把控制面观察升级为因果、商业关系或用户影响；
- **人工审查栏**：审查者可以选择通过、修改或退回，并填写意见。

证据等级统一为：

| 等级 | 含义 |
|---|---|
| A | 当前 publication/API/Tool 已直接发布的事实 |
| B | 仅使用同一 publication 数据，经登记的确定性 Operator 派生 |
| C | 后端数据已经存在，但当前调查 Tool 尚未发布 |
| D | 需要外部、版本化、可审计的数据或知识来源 |
| E | 当前证据域不能支持，应拒绝给出事件结论 |

审查建议：先检查“问题本身是否成立”，再检查答案、证据等级和边界。若问题包含“影响、导致、客户、恢复、全国”等词，应优先检查是否暗含无法证明的关系。

### Q15　前缀不可见伴随的是显式 WITHDRAW、替代 ANNOUNCE、路径变化、origin 变化还是观察缺失？

**当前拟答**

该问题适合作为 P2.1 的变化分类能力，不应在 P2 v1 中由模型自由解释。

- 不得把会话失败伪造成路由撤销；
- 机制分类仍然不是事件原因或责任判断。

### Q17　“新出现前缀”是否表示互联网中新分配或新接入的前缀？

**证据等级**：E；若继续验证则需要 D
