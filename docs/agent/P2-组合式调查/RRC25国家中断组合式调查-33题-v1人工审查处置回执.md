## 三、审查后形成的横向产品规则

### 1. 预览与完整导出

所有可能产生海量结果的问题统一采用：

```text
先计算 total 和稳定排序
  → 聊天返回前 N 项、总数、排序口径和是否截断
  → 询问用户是否导出完整结果
  → 用户确认后，从同一冻结 result_set 生成 Markdown/CSV/JSON
```

建议默认预览限制：

| 结果类型 | 默认预览 |
|---|---:|
| ASN 排名 | 10 |
| 前缀成员 | 20 |
| 路径样本 | 5 |
| downstream origin | 10 |
| 集合交集成员 | 10 |

完整导出必须绑定 incident、publication、revision、collector、查询参数、排序、总数、完整性、生成时间和内容摘要。

### 2. AS 严重性排序

人工审查确认：中断事件中的 AS 默认排名先按“不可见程度”从高到低排序；不可见程度一致时，再按“完全不可见前缀峰值数量”从高到低排序。按照当前数据字段，不可见程度映射为 `peak_invisible_direction_count`。排名只表示该产品口径下的不可见严重程度，不表示网络拓扑关键性、业务重要性或因果作用。

建议冻结为：

```text
peak_invisible_direction_count DESC,
peak_complete_prefix_count DESC,
asn ASC
```

现有实现的默认顺序还优先使用 `route_interrupted` 分类，然后比较完全不可见前缀数量，并在数量并列时使用 downstream 数；它既没有把不可见方向峰值作为第一排序项，也没有采用本次确认的稳定尾项，需要在进入实现阶段前完成兼容与影响评审。

### 3. 路径展示分层

- P2 v1：至少 5 条真实路径样本、路径位置、直接邻接摘要、总体计数和完整导出；
- P2 后续：围绕指定 AS 的有界路径邻域图；
- 独立大能力：类似 BGPView 的交互拓扑图、缩放、聚合、过滤和路径展开。

不得为了路径图而将路径包含、直接邻接和商业关系混成一种边。

## 四、Q08 算子成本答复

Q08 的确定性计算本身不高，主要成本是读取和解码逐 ASN 状态，而不是排序或除法。

以当前 525 个 ASN、3,455 个五分钟槽位估算，最直接的全量扫描约为 181 万个 `ASN×slot` 状态单元：

- 峰值比例：每个 ASN 一次除法和排序，成本低；
- 最早变化：每个 ASN 顺序找首次满足阈值的槽位，成本低至中等；
- 持续时间：需要合并连续异常区间，成本低至中等；
- 如果每次聊天都重新读取压缩状态文件，I/O 与解码会造成不必要的重复成本。

推荐在 publication 构建或投影阶段预计算每个 ASN 的：

- `first_changed_at`；
- `last_changed_at`；
- `affected_duration_slots`；
- `longest_contiguous_duration_slots`；
- `peak_complete_prefix_ratio`；
- `peak_partial_prefix_ratio`。

查询时只扫描约 525 行摘要并排序，无外部模型费用，预计属于低成本确定性 Operator。阈值、断点和缺失处理策略必须进入版本化合同。
