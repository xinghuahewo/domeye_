# W1/W2 实现勘误与结构绑定合同

文档版本：`country-outage-p2-s1-w1-w4-implementation-errata-v2`  
文档状态：待独立影响审查  
绑定设计候选：`country-outage-p2-s1-s1d-6-04135cee55b39ce5d574f7e4`

## 一、目的

W1/W2 实现期间发现三个不能通过“按常识补值”解决的闭合缺口。本文只允许语义保持的离线投影和
结构绑定验证，不增加 Tool 人口、不增加 Operator 业务变换，也不改变产品边界。

W1/W2 代码中的结构上下文只是离线测试夹具，不是运行时受信 Host。Registry 的执行授权固定为空；
普通调用方即使能在 Python 进程内构造同型对象，也不能经 Registry/dispatcher 执行。W5 必须从
Host-owned Store 解析相同摘要并实现真正的受信 dispatcher，才可以向 Operator 提供结构回执。

在本合同通过独立影响审查、Schema 正反例和阶段 Hook 之前，W1/W2 不得标记为通过。

## 二、缺口与裁决

### 2.1 TOOL-12 路径状态字段

W0 窗口路径行把权威源的路径存在状态写为 `path_parse_status=known`，而冻结 TOOL-12 合同要求
`path_parse_status=ordered|unordered|ambiguous|invalid`，并要求它与 `common_path_status` 对齐。

裁决：在 W0 离线物化阶段产生两个不同字段：

- `source_native_path_status=known`：保留权威源的存在/已知状态；
- `path_parse_status=ordered`：冻结规范路径结构状态；
- `common_path_status=ordered`：登记公共状态；
- `ordered_sequence_eligible=true`。

物化器只有在 typed `AS_SEQUENCE`、路径摘要、origin 尾端和 anchor 严格在 origin 之前全部验证后，
才能发布上述投影。TOOL-12 必须原样读取已验证行，查询期不得解析路径或重新映射状态。

### 2.2 complete-empty 人口的 Evidence

冻结 Operator 输出信封要求至少一条 Evidence，但若完整输入人口为空，部分冻结输入 Payload 没有
人口级 Evidence 字段。Operator 不得凭空生成 Evidence，也不得把人口摘要伪装成 Evidence。

裁决：W1/W2 离线夹具验证由未来 Host 从受信 Store 解析 ResultSet/query/freeze 或上游完整人口回执后生成的零业务变换
`population_evidence_binding` 回执。回执绑定完整人口、成员数、输入摘要和人口 Evidence。Operator
只继承该 Evidence；未来 Host 不得筛选、排序、构造或聚合成员。

### 2.3 OP-12、OP-13、OP-14 的结构投影与 ASN 绑定

冻结 OP-13 消费 OP-11 回执，但 OP-11 输出没有 ASN；OP-13 又必须输出按 ASN 的时长排名。模型、
Operator 名称或 Evidence 文本都不能用来猜 ASN。

裁决：离线夹具验证未来 Host 为每个已提交 OP-11 输出生成的 `asn_bound_op11_receipt`，绑定原 Plan 节点的冻结 ASN
输入、OP-11 输入/输出摘要和节点结果摘要。未来 Host 不读取或计算 `duration_seconds`；OP-13 仍是唯一
执行时长排名的业务 Operator。

实现期继续发现 OP-10→OP-14 与 OP-36→OP-12 存在同型结构差异：上游完整 OutputEnvelope 的
`result` 包含完整 Operator 输出字段，而冻结下游 receipt 只允许闭合投影视图。调用方不得自行裁剪
后再自报 ASN 或输出摘要。

裁决：

- OP-14 只消费冻结 `op10Receipt` 投影视图；离线夹具验证未来 Host 通过 `asn_bound_op10_receipt` 将它绑定到受信
  内容寻址 Store 中的完整 OP-10 OutputEnvelope，逐字段验证 `asn/numerator/denominator/ratio_exact/outcome`；
- OP-12 只消费冻结 flat `op36Receipt`；离线夹具验证未来 Host 通过 `asn_bound_op36_receipt` 将它绑定到完整 OP-36
  OutputEnvelope 与来源 Plan ASN；
- 两类绑定均验证完整输出摘要、输入摘要、节点结果摘要、ASN 绑定摘要、identity 和设计候选；
- 未来 Host 只做字段相等与引用解析，不计算比例、阈值穿越、时长或排名；
- Operator 对缺失、重复、ghost、跨 identity、摘要篡改、投影视图篡改和 ASN 换绑一律失败关闭。

### 2.4 OP-33 左右完整人口与合法空侧

OP-33 是两个完整人口的精确时间连接。左侧新前缀状态人口、右侧 exact-time RouteState 人口都可以
合法为空；输入 Schema 不得用 `minItems=1` 拒绝空人口。同时，空数组摘要只能证明“提交的是空数组”，
不能证明“权威人口确实为空”。

裁决：未来 Host 必须为左右人口分别生成一份零业务变换 `population_evidence_binding`。每份回执绑定：

- 同一设计候选与完整 Operator identity 摘要；
- 固定输入名、完整输入人口摘要、成员数和成员键摘要；
- 受信来源人口、manifest、completeness receipt 与人口 Evidence；
- `set_completeness=complete` 和 `business_transform_count=0`。

左右回执缺一不可，左空、右空和双空均不得豁免。另一侧行 Evidence、另一侧人口回执或调用者自由
Evidence 不能替代当前侧完整性证明。OP-33 仍只执行一次登记的连接变换，不在结构绑定阶段过滤、
补行、取最近时点、聚合或推断。

## 三、原子性结论

上述结构回执的 `business_transform_count` 固定为 0。它们只验证现有字段之间的相等、引用、
Schema 和摘要关系：

- 不读取新的 BGP 事实人口；
- 不产生新的时间、路径、集合、计数或排名事实；
- 不调用 Tool、Operator 或模型；
- 不改变输入成员人口；
- 不替代 InvestigationPlan 的组合职责。

因此，每个 Tool 仍只读取一个事实人口，每个 Operator 仍只执行一个确定性业务变换。

## 四、必须拒绝的攻击

1. TOOL-12 在查询期把 `known` 临时改写成 `ordered`；
2. 删除 `source_native_path_status` 后仍发布路径行；
3. unordered/ambiguous/invalid 路径被投影为 ordered；
4. 空人口没有受信人口回执却发布空结果；
5. `population_evidence_ref.source_digest` 与 completeness receipt 不一致；
6. 非空人口借用另一人口的 Evidence 回执；
7. 调用方自签或跨 publication/candidate 重放结构绑定回执；
8. OP-13 缺少某个 OP-11 输出的 ASN 绑定、重复绑定或加入 ghost 绑定；
9. ASN 绑定来自非祖先 Plan 节点或未提交结果；
10. Host 在绑定阶段重算时长或排名；
11. Operator 在没有通过结构绑定校验时猜测 ASN 或伪造 Evidence；
12. 以本勘误为由扩张 Tool/Operator 输入人口或加入第二业务变换。
13. OP-10 或 OP-36 投影视图未解析到受信完整 OutputEnvelope 仍进入 OP-14/OP-12；
14. 调用方自报 `asn_bound_op10_receipt` 或 `asn_bound_op36_receipt`，未由 OfflineStructuralFixtureContext
    的内容寻址解析器确认；
15. 投影视图字段与完整输出不一致、完整输出摘要不可重算或 ASN 与来源 Plan 绑定不一致。
16. OP-33 左右人口缺少任一独立完整性回执，或空侧借用非空侧行 Evidence；
17. OP-33 人口回执的输入名、identity、人口摘要、成员数或成员键摘要漂移；
18. 调用者自由 Evidence、自签回执或跨 candidate/publication 回执被用于发布空连接结果。

## 五、通过条件

- W0 物化 Schema、构建器、fixture、Store 白名单和摘要链一致；
- `w1-w2-structural-binding.schema.json` 通过 Draft 2020-12 自检；
- 两种结构回执均有正例、摘要篡改、跨身份、ghost、重复和缺失攻击测试；
- TOOL-12 与 OP-13 运行时使用受信回执，不使用自由文本或隐式字段；
- OP-33 左空、右空和双空均通过 Draft 2020-12 与运行测试，且两侧人口回执缺失、借用、篡改、
  跨 identity/candidate 攻击全部失败关闭；
- W1/W2 Alignment Hook 绑定合同文件原始 SHA-256、实现摘要和测试回执；
- 独立 BGP/原子性审查确认业务语义未改变且没有隐藏复合。

通过只表示 W1/W2 可继续实现和离线验收，不表示生产部署或用户流量可用。

## 六、阶段交付边界

W1/W2 只交付可在离线 harness 中单独调用的原子 Tool/Operator 与不可变 Registry dispatch binding。
它们尚未交付受信 Python dispatcher、InvestigationPlan、跨页冻结 ResultSet、Evidence Graph、导出器或
用户回答链。因此：

- Registry 回执只能写“整波 dispatch binding 已准入”，不得写“真实 handler 已激活”或“执行已授权”；
- `execution_allowed_unit_ids` 必须为空，任意 caller callback seam 必须 fail closed；
- Tool 首次响应只有在全部成员一次返回时才能声明 `set_completeness=complete`；通过 continuation token
  到达的末页仍是 `partial_page`，必须由 W5 Host 汇集全部分页并冻结后才能形成完整 ResultSet；
- W1/W2 的 `effect_verified` 只表示结构化原子结果在固定 fixture 的离线 harness 中可重放，不表示页面、
  API、模型、真实 publication 全量运行、性能验收或生产流量可用；
- 受信 dispatcher、跨页提交与运行时执行授权属于 W5；真实 publication 回放、性能和取消验收属于 W6。
