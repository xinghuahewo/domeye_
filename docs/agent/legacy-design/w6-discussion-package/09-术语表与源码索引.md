# 术语表与源码索引

> 文档口径：源码链接指向2026-08-14本地W6 v3工作树；历史Worktree、当前候选和生产身份不可混用。

## 1. 产品与工程阶段

| 术语 | 含义 |
|---|---|
| P0 | 系统能力、数据人口、语义和边界发现 |
| P1 | 单事件、单publication的受控问答 |
| P1.1 | 开放SemanticPlan、闭合Host Grounding |
| P2 | 组合式、有状态、可恢复的调查 |
| P2-S0A/S0B | 为P1执行单元补统一Registry治理的建设阶段 |
| S1D-0～6 | P2-S1设计合同阶段 |
| W0～W6 | P2-S1实现和离线认证波次 |

## 2. 规划术语

| 术语 | 定义 |
|---|---|
| UserGoalPlan | P1中保留用户目标、实体和歧义的开放目标结构 |
| SemanticPlan | 模型生成的非可执行语义计划 |
| Grounding | Host把语义目标映射到受信能力、参数和输入来源 |
| GroundingPlan | P1闭合执行计划；当前与P2结构不同 |
| Grounded Execution Recipe | P2中由冻结模板和语义Capability形成的可验证执行配方 |
| InvestigationPlan | 绑定身份、Registry、节点、依赖和执行规则的不可变DAG合同 |
| Common Plan IR | 目标架构中的统一计划中间表示，当前尚未正式存在 |
| Question Template | 将一个问题或能力族映射为静态DAG骨架、输入来源和Oracle的模板 |
| Profile | 对同一内核施加的编排、预算、持久化和状态约束 |

## 3. 执行单元术语

| 术语 | 定义 |
|---|---|
| Capability | 面向语义和产品结果的受控能力 |
| Tool | 读取一个事实人口的只读执行单元 |
| Operator | 对完整类型化输入做一次确定性业务变换的纯执行单元 |
| Gate | 验证身份、Evidence、完整性、边界或权限的Host控制单元 |
| Renderer | 将冻结制品转换为Markdown、CSV或JSON表示，不改变事实 |
| Delivery | 提交和交付已验证导出制品 |
| Structural Adapter | 只做类型、字段和人口绑定的Host结构层，不得包含业务变换 |
| Dispatcher | 根据已准入Registry绑定调用静态handler的运行时 |

## 4. 数据与证据术语

| 术语 | 定义 |
|---|---|
| incident | 产品事件身份 |
| publication | 一组不可变发布数据及其身份 |
| revision | publication或调查制品的版本序号 |
| collector | 采集器；当前固定为RRC25 |
| cohort | publication绑定的固定成员人口 |
| data-through | 数据处理截止时间，不等于事件结束 |
| finality | 事件结束是否已知 |
| ResultSet | Host冻结的完整或显式不完整成员人口 |
| Evidence Bundle | P1每个子目标的事实、派生结果、证据和限制集合 |
| EvidenceGraph | 已提交事实、派生、限制、未知和失败关系图 |
| Evidence ref | 指向可核验来源或制品成员的引用 |
| Receipt | 对准入、执行、冻结、验证或提交动作的内容绑定回执 |
| content digest | 内容寻址摘要，用于重放、绑定和漂移检测 |

## 5. 状态与控制术语

| 术语 | 定义 |
|---|---|
| DialogState | P1已提交、可供后续对话继承的状态 |
| EvidenceState | P1独立于聊天文本的证据状态 |
| Turn | P2一次追问及其回答制品 |
| Investigation revision | 调查每次可变提交后的新版本 |
| CAS | 比较expected revision/current digest后原子更新current指针 |
| idempotency key | 保证同一逻辑请求重复提交不会重复产生不同状态 |
| local failure | 单个节点失败，不强制抹掉全部已成功调查结果 |
| impact closure | 重跑一个节点时受其影响的后代节点集合 |

## 6. 模型术语

| 术语 | 定义 |
|---|---|
| Sol Teacher Planner | 生成开放SemanticPlan的gpt-5.6-sol逻辑角色 |
| Sol Teacher Reference | 在已验证Evidence上生成参考答案结构的逻辑角色 |
| DS Student | 根据同一Evidence和已验证Teacher Reference生成答案的逻辑角色 |
| Model Capability View | 从Registry派生、过滤后的模型可见只读能力元数据 |
| tool_selection_authority=false | 模型无权选择最终具体执行单元 |
| executable_plan=false | 模型输出不能直接被Dispatcher执行 |
| fixture replay | 无外部provider、脚本化输出的本地受信回放 |

## 8. 常见误解对照

| 误解 | 正确理解 |
|---|---|
| 文件名有P2就是P2运行时 | P2-S0A Registry文件可能登记P1单元 |
| 多个P1子目标就是P2 DAG | P1子目标主要独立执行，不共享完整调查图 |
| Registry active就一定能被所有Dispatcher执行 | 还需要对应运行时binding和Plan Admission |
| Operator代码存在就表示问题支持 | 还需要上游完整输入、Adapter、Plan和Answer Oracle |
| 168个case通过等于28题通过 | 当前只是168个disposition分类符合预期 |
| fixture模型链通过等于真实模型认证 | 当前外部provider调用数为0 |
| API存在等于端到端能力存在 | API只能证明合同和产品壳存在 |
| Tool返回20行等于完整集合 | 必须看ResultSet完整性和分页闭包 |
| Trace等于Evidence | Trace证明调用过程，EvidenceGraph约束事实发布 |
| Host可信所以可以做任何计算 | Host只能按合同控制、验证和提交，业务变换必须显式登记 |
