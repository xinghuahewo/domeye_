## 一、目标

本 revision 不先假定系统能力边界，而是从当前产品表面向下实测：

1. 当前详情页实际展示和实际请求了什么；
2. 正式 API 当前发布了什么，当前事件是否可读；
3. publication/read model 绑定了什么运行与数据身份；
4. 仓库中还存在哪些后端候选、确定性推导和中间数据；
5. 哪些能力只是源码存在、尚未发布、当前不可用、语义未冻结、越界或仍未知。

最终形成系统表面清单、Capability Discovery Ledger、unknown ledger、最小只读
feasibility/Oracle seed、35 个能力映射案例和 P1 `adopt/defer/reject` 回执。

## 二、证据层与判定规则

每项能力分别记录以下事实，不允许互相替代：

- `source_exists`：当前仓库存在实现；
- `tests_exist`：当前仓库存在相关测试；
- `runtime_includes`：当前运行态可通过只读探针证明路由或响应存在；
- `data_available`：当前 publication 对该事件返回合法数据；
- `api_published`：正式 API 合同登记该能力；
- `page_consumes`：当前页面实际请求并呈现该能力。

能力成熟度只允许：

- `page_visible`
- `api_published`
- `backend_available_unpublished`
- `deterministically_derivable_unproductized`
- `semantics_unfrozen`
- `unavailable`
- `out_of_scope`
- `unknown`

源码、测试、数据或 feasibility 任一单项为真，都不能单独推出 `page_visible` 或
`api_published`。

## 三、执行范围

允许：

- 浏览当前详情页并读取可访问性树和网络请求；
- 对正式 GET/HEAD/OPTIONS 入口进行只读探测；
- 读取仓库中的页面、路由、服务、合同、测试和数据 schema；
- 对同一不可变 publication 进行纯函数式极值、差值、筛选和身份一致性验证；
- 记录失败关闭、缺失、冲突和未知。

禁止：

- 触发报告生成、追问、取消、发布或其他会改变状态的请求；
- 修改前后端、数据库、数据管线、合同、生产配置或运行时；
- 连接 RRC25 以外的数据源补齐事实；
- 把路径相邻关系解释为依赖、传播或原因；
- 把控制面可见性解释为真实用户影响、全国完全中断或闭环恢复；
- 原地改写旧 `p0-v1`、`P1-v1` 或 `P1.1 S0` 候选。
