版本：1.2

状态：最终效果候选合同

上位边界：[国家中断 Agent 建设总纲](../国家中断Agent建设总纲.md)

历史入口：[P1 原入口回执](../P0-需求与评测/P1入口回执.md)

## 一、文档定位

本文只设计 P1 聊天问答产品工程完成后的最终效果，不规定具体框架、模型供应商、代码
目录、人员排期、开发步骤或部署方案。

P1 的产品定位是“RRC25 事件绑定聊天问答”：用户从一个合法 `country_outage` 事件进入，
在同一 incident、publication、revision 和观测窗口内询问 P0 已实测且被 P1 正式采用的
事实、指标语义、证据边界和证据不足，并进行短期连续追问。采用项可以来自当前页面、
正式 API 或后端已有但尚未发布的能力，但后两者进入执行前必须完成 P1 工具合同化和稳定
只读端口，不得把 feasibility 结果直接暴露为产品能力。

既有 P0 revision `p0-v1-20260808-ir-r1` 和 35 个案例继续作为历史回归与迁移输入，但只
证明原页面/API 合同，不自动满足 P0 v1.3 的系统能力勘探要求。本文 v1.2 的正式建设入口
必须引用新的 P0 Capability Discovery Ledger、分层证据、feasibility/Oracle seed、35 个
案例和 P1 `adopt`/`defer`/`reject` 候选处置回执。新回执形成前，P1 可以设计合同但不得
宣称新版 S0 出口成立。

P1 不是开放式通用聊天机器人，也不是让模型自行决定调用哪些工具的调查 Agent。P1
允许多标签而不是单一意图分类，但每个子目标只能进入冻结的 P1 问答能力；复杂调查、
假设、多源证据和原因分析必须保留为未建设能力。

P1 明确区分“用户目标语义”和“可执行 grounding”：前者必须尽量完整保留用户使用同义、
省略、口语、指代和多意图表达的真实目的，即使目的超出当前能力；后者只能引用已经登记、
版本化并有测试 Oracle 的 P1 capability 和只读算子。不能因为没有现成工具就误解、截断或
强行改写用户目标，也不能因为模型理解了一个目标就自动获得对应工具和执行权限。

在冻结可执行语义映射或接入混合意图模型之前，必须先接收并裁决 P0 能力账本，复核采用项
仍绑定相同运行与数据身份，再依次冻结 P1 产品与 RRC25 证据边界、Capability Catalog、
Typed Tool/Operator Contract 以及完整算子 Oracle。这里的“先定义工具”是先定义业务
能力、输入输出、证据、缺失和失败语义，不要求先完成全部运行时代码，更不要求提前实现
P2 至 P5 的工具。

本文 v1.2 是修订后的目标合同，不追溯改写既有 `p1-candidate-61354911c7793d75` 的历史验收。
该候选继续按其原 P1 合同保持有效，但不自动满足 UserGoalPlan、GroundingPlan、
Typed Tool/Operator Contract 和算子 Oracle 等新增要求；新要求必须由新的合同 revision、
候选身份和符合性回执证明。

P1 通过只能称为 RRC25 事件绑定聊天问答，不表示具备 P2 组合式调查、Evidence Graph、
P3 有限假设、P4 多源证据或 P5 RCA 候选能力。

## 二、最终产品效果总览

用户看到的是一个绑定事件的聊天页面或聊天工作区，而不是空白通用输入框：

```text
事件与证据身份栏
  ├─ 国家 / 事件 / publication / revision / data_through / finality
  └─ 身份变化、过期或冲突提示

对话区
  ├─ 用户问题、系统回答和处理状态
  ├─ 关键事实、证据引用、限制和未知
  ├─ 澄清、部分回答、不支持和失败关闭
  └─ 取消、重试、继续追问和会话到期

上下文状态
  ├─ 当前事件、主题、ASN、地址族和指标
  └─ 继承、覆盖、清除、事件切换与 revision 切换
```

系统的核心价值不是生成一段流畅文字，而是确保每一轮回答都能说明：当前绑定了什么、
用户实际提出了哪些目标、其中哪些被映射到什么受控能力、使用了哪些事实、哪些部分不能
回答、证据在哪里、下一轮会继承什么。

## 三、前端需求最终效果

### P1-FE-01：入口必须绑定合法事件

- 用户从合法 `country_outage` 事件进入聊天，不默认猜测国家、最新事件或任意事件；
- 首屏持续显示国家、事件、publication、revision、`data_through`、finality 和 collector；
- 事件没有唯一 publication、身份未闭合或事件类型不合法时，聊天不可进入可回答状态；
- 用户能够回到原事件详情页，且往返后仍能看见当前对话绑定身份。

### P1-FE-02：聊天页面具有清楚的工作层级

- 页面清楚区分事件身份栏、消息区、输入区、处理状态和证据/限制区域；
- 空会话提供与当前事件相关的建议问题，但不暗示系统能够分析原因或访问外部网络；
- 用户消息、系统回答、澄清问题、限制说明和错误状态具有不同视觉语义；
- 长回答不挤压输入区，用户能够定位当前轮、上一轮和引用的证据。

### P1-FE-03：每一轮都有真实且可理解的状态

- 提交后立即进入排队、理解问题、读取事实、生成回答、校验或完成中的明确状态；
- `answerable`、`partial`、`clarify`、`unsupported` 和 `invalid_data` 具有可理解的用户文案；
- 不以无限加载、空白消息、HTTP 状态码或“出错了”替代具体失败原因；
- 处理中可以取消；失败后只有在输入和身份仍有效时才提供重试。

### P1-FE-04：回答先给结论，再给证据与限制

- 可回答内容先给直接结论和关键数字，再展示单位、时间点、统计范围和证据入口；
- 关键事实能够下钻到当前 publication 的页面区域或 API 字段级证据；
- 指标解释能够显示分母、窗口、地址族、样本或分页限制；
- 回答中的限制、未知和禁止断言不是折叠到不可见角落的免责声明。

### P1-FE-05：复合问题按子目标显示局部结果

- 一个问题同时包含事件概述、时间、范围、ASN、地址族、指标或证据时，不强制压成一个
  单一意图；
- 每个子目标分别显示“已回答、部分回答、需澄清、当前不支持或数据无效”；
- 某个子目标失败不抹掉其他已经通过同快照校验的局部事实；
- 任一身份冲突或阻断级数据错误发生时，不发布拼接后的完整答案。

### P1-FE-06：短期多轮追问自然且可见

- 用户可以使用“它、这个峰值、刚才那个 AS、那 IPv6 呢”等指代继续追问；
- 页面能够让用户知道当前继承的事件、ASN、地址族、指标或主题；
- 用户修正对象后，新对象覆盖旧对象，回答不继续夹带旧 ASN、旧地址族或旧指标；
- 从事实追问原因时，系统保留事件身份，但降低到证据边界回答，不沿用事实确定性。

### P1-FE-07：事件、publication 和主题切换不串扰

- 用户明确切换事件或 publication 时，旧事件事实和主题状态被清除，并展示切换确认；
- 用户只说“换一个事件”但没有唯一目标时，系统只提最少必要澄清，不默认“最新”；
- 活动 publication 变化时，旧回答保留原身份，新问题暂停并要求确认使用旧版或重新绑定；
- 同一会话内的主题切换只保留仍然适用的事件身份，不保留无关实体槽位。

### P1-FE-08：取消、重连和会话到期有完整闭环

- 取消后当前轮不再生成新答案，已完成的历史轮次保持可读；
- 短暂断网或页面刷新后，用户能够恢复仍有效会话，并看到未完成轮次的真实状态；
- 重复提交或重连不会产生两份不同答案；
- 会话到期、服务重启导致状态丢失或恢复失败时，页面明确说明并允许以当前事件新建会话。

### P1-FE-09：边界和异常是正式回答效果

- 原因、责任、全国完全断网、真实用户影响、经济损失和外部证据请求均说明当前可确认
  的 RRC25 事实、所缺证据和对应未来阶段；
- `null`、`unknown`、`unavailable`、无结果、publication 冲突和无效响应不显示为 0、
  正常或确定结论；
- 系统不打开用户提供的 URL，不执行问题中的指令，不把模型常识写成事件事实；
- 边界回答不是机械拒绝，应保留当前能够安全回答的部分。

### P1-FE-10：窄屏、键盘和辅助技术下仍可完成核心任务

- 桌面与窄屏都能完成进入事件、提问、追问、查看证据、取消和重新开始；
- 输入、发送、取消、重试、展开证据和返回事件均可通过键盘操作；
- 处理状态、错误和身份变化不只依赖颜色表达；
- 流式更新不会抢走输入焦点，也不会让屏幕阅读器重复朗读整段历史。

## 四、后端与评测最终效果

### P1-BE-01：请求和回答具有不可混用的身份包络

每一轮内部至少绑定：

- conversation、turn、request 和幂等身份；
- incident、publication、revision、cohort、collector、窗口、`data_through` 和 finality；
- P0 case-set revision、P1 合同 revision、实现和规则/模型身份；
- 创建时间、完成状态、取消状态和可重试状态。

回答身份与任一证据身份不一致时必须失败关闭，不能选择其中一个快照继续生成。

### P1-BE-02：开放用户目标与封闭执行映射分层

- 规则确定事件身份、安全阻断、显式实体和不能容忍模糊判断的硬边界；模型或语义分类可
  补充同义、省略、口语、指代、多意图和歧义候选，但不拥有事实决定权；
- 第一层输出结构化、多目标的 `UserGoalPlan`，保留用户原始目标及其关系，不要求每个目标
  预先命中一个封闭 Intent 枚举或工具名称；
- 第二层由确定性 Grounding Validator 生成 `GroundingPlan`，每个目标只能映射到已冻结的
  P1 capability、算子和合法参数，或明确成为 `partial`、`clarify`、`unsupported`、
  `invalid_data`；
- 找不到可执行映射时仍保留原目标和缺口理由，不能错配到最相近算子；低置信、实体不唯一
  或规则与模型冲突时进入澄清或安全降级，不由模型猜测；
- 只有通过能力版本、参数、身份、证据和权限校验的 `GroundingPlan` 才能进入执行层。

### P1-BE-03：实体和多轮状态采用确定状态机

- 状态至少区分事件身份、publication、revision、主题、ASN、地址族、指标、证据引用和
  待澄清对象；
- 每轮明确记录 `inherit`、`set`、`clear` 和切换原因；
- 用户显式修正优先于旧状态，事件/publication 切换优先于主题继承；
- 原始模型对话历史不能直接成为事实或系统状态，状态只能由校验后的结构化转换更新。

### P1-BE-04：P1 只执行从 P0 验证候选中正式采用的白名单事实算子

P1 允许的算子限定为 P0 Capability Discovery Ledger 已证明、P1 明确标为 `adopt` 并完成
工具合同化的事件摘要、窗口和关键点、范围、ASN 排名与明细、地址族比较、资源变化、
路径样本、指标解释、证据下钻和身份读取。P0 中的 `defer`、`reject`、unknown、语义未
冻结或只有数据存在的条目不能进入白名单。

在任何可执行语义映射冻结前，P1 必须形成版本化 Capability Catalog 和 Typed
Tool/Operator Contract。每项至少声明：用户结果、业务语义、输入与前置条件、输出事实
和单位、事件/publication/revision/collector 绑定、证据引用、`null`/无结果/未暴露/
冲突/无效响应语义、禁止推断、只读权限、状态副作用、组合限制和合同版本。每个可执行
算子必须有独立 Oracle 或等价 fixture，证明给定输入、同一快照和异常条件下的预期事实、
回答等级与证据；只有 API 字段而没有上述合同，不构成可供语义层调用的 P1 工具。

若采用后端已有但尚未发布的能力，P1 必须先建立稳定、只读、身份化的服务端口或适配器，
冻结其输入输出和错误语义，并通过完整 Oracle；P1 不直接向模型暴露数据库、任意内部路由、
临时脚本或原始中间数据。P0 feasibility spike 和 Oracle seed 只能作为合同输入，不能替代
P1 工具实现与完整 Oracle。

P1 不生成开放式调查计划，不动态发现或调用新工具，不执行跨来源搜索，不创建 Evidence
Graph，不进行假设检验或因果推断。Update/Withdraw 轨道在当前事件 API 未暴露时必须
返回 `unsupported`，不能生成 0 或模拟结果。

### P1-BE-05：事实计算和语言生成严格分层

- 事件绑定、数据读取、筛选、比较、极值、差值、排序和证据引用由确定性逻辑完成；
- 模型只负责受约束的意图补充和对已验证回答草稿的语言改写；
- 模型不能新增数字、单位、时间、ASN、前缀、原因、责任、外部事实或证据引用；
- 模型不可用、超时、输出无效或改写越界时，系统返回确定性草稿或明确失败状态。

### P1-BE-06：可回答性按子目标判定并失败关闭

- 每个子目标独立判定 `answerable`、`partial`、`clarify`、`unsupported` 或
  `invalid_data`；
- 可安全保留的局部事实与阻断整轮发布的身份/数据错误明确分开；
- 缺失能力、缺失证据和查询无结果是不同状态，不能统一映射为空数组或 0；
- 任一关键身份冲突、证据不可解析或参考事实校验失败时，不发布有效答案。

### P1-BE-07：回答包络可校验、可重放、可追溯

- 回答包含结构化子目标结果、用户可见文本、事实值、证据引用、限制、未知和状态变化；
- 相同输入、相同会话状态和相同证据快照产生相同事实计划和幂等结果；
- 语言可以变化，但关键事实、回答等级、证据身份、限制和禁止断言不能变化；
- 旧回答保留创建时身份，新 publication 不静默改写历史回答。

### P1-BE-08：会话生命周期和并发语义明确

- 会话具有创建、活动、提醒到期、到期、取消和不可恢复状态；
- 同一会话只允许一个活动写入序列，乱序完成不能覆盖较新的状态；
- 幂等键防止重复问题和重连重复生成，取消信号能够传递到正在处理的轮次；
- P1 只承诺短期会话；进程重启后的长期持久化、跨设备永久历史和用户知识库不在 P1。

### P1-BE-09：安全、隐私和提示注入边界成立

- 浏览器不能直连模型或 Sidecar，内部凭据不进入前端、日志或回答；
- 输入长度、并发、超时、响应大小、证据引用格式和请求字段采用白名单限制；
- 用户问题、引用文本和 URL 均是不可信数据，不能改变系统边界、工具权限或事件身份；
- P1 不调用外部网络，不保存公开账号、联系方式或无关个人信息，不使用对话训练模型。

### P1-BE-10：运行状态和候选身份可观测

- 每轮能够关联会话、请求、规则/模型、输入快照、阶段、耗时、取消和最终状态；
- 日志记录结构化状态和错误分类，不记录内部提示、凭据或不必要的完整问题正文；
- 健康检查、模型可用性、数据 API 可用性和当前 publication 状态分开表达；
- `implemented`、`tested`、`accepted`、`deployed` 和 `production_verified` 不互相替代。

### P1-BE-11：P0 基线成为 P1 候选的硬门禁

P1 候选必须引用同一 P0 能力与评测 revision，并在同一候选身份下执行 P0 的 35 个案例：

- 20 个直接问题逐项达到规定的回答等级和参考事实；
- 5 个多轮旅程的继承、修正、切换和隔离全部正确；
- 5 个越界问题禁止断言命中数为 0；
- 5 个异常问题中补零、猜测、快照混用和无效答案发布次数为 0；
- 事件绑定、publication/revision 绑定、事实一致和证据可解析均为 100%。
- 所有可执行 capability 都来自 P0 `adopt` 集合，`defer`、`reject` 或 unknown 条目被执行
  的次数为 0；
- P0 能力成熟度、P1 工具合同与当前运行身份之间不存在静默升级。

不得用平均准确率、文本相似度、响应速度或模型语言质量抵消任一硬门禁失败。

此外，每个被判定为可执行的子目标必须能够追溯到已登记 capability、工具/算子合同版本
和通过的 Oracle；每个不可执行目标必须保留用户目标语义和明确的能力缺口，不得通过改写
Intent、删除子目标或调用未登记工具制造通过结果。

### P1-BE-12：P2 获得正式且有限的入口

P1 出口形成 P2 正式入口回执，至少交付：

- 已验收的会话、用户目标计划、Grounding Plan、实体、回答包络和证据引用合同；
- P1 Capability Catalog、白名单工具/算子合同、Oracle 及其输入、输出、缺失和失败语义；
- 被正确拒绝或降级的组合调查问题清单；
- P0/P1 revision、候选实现、规则/模型、测试和运行环境身份；
- 不随交接转移的外部网络、假设、因果、写操作和生产权限。

P2 不能把 P1 的聊天历史当作 Evidence Graph，也不能通过继承 P1 会话绕过新的调查合同。

## 五、联合验收场景

### P1-SCE-01：从事件进入并完成首轮概述

用户从伊朗事件进入，首屏身份与 P0 固定事件一致；询问“发生了什么”后，回答使用同一
publication 的概述、关键数值、限制和证据，不默认切换事件或 collector。

### P1-SCE-02：时间、峰值、末端状态和恢复追问

连续询问观测窗口、检测时间、不同峰值和是否恢复；回答区分检测时间与真实起点、中断
前缀峰值与完全中断峰值、窗口末端与事件结束。

### P1-SCE-03：ASN、地址族和路径子主题

用户查看前五 AS、指定 AS48715、修正为 AS49556、切换 IPv4/IPv6 并索要路径样本；系统
正确覆盖实体、清除不相关状态，并说明路径关联不是依赖或原因。

### P1-SCE-04：指标语义和证据下钻

用户询问中断前缀、完全中断前缀、不可见方向、可见地址规模和 publication 身份；回答
给出定义、单位、统计范围和可解析证据，不混用峰值时点或分母。

### P1-SCE-05：复合问题局部成功

一个问题同时询问峰值、ASN、IPv6、Update 和原因；系统保留多个子目标，回答当前事实，
将 Update 标为当前能力未暴露，将原因标为证据不足，不用一个总状态掩盖差异。
系统不得为了让全部子目标落入工具白名单而删除“Update”或“原因”，也不得把它们错配为
峰值、事件概述或其他已有算子。

### P1-SCE-06：指代、继续追问和证据边界

用户使用“这个峰值”“它”“那现在呢”继续追问，系统继承正确对象；随后询问原因时保留
事件身份但转换为边界回答，不把上一轮事实确定性传递给原因结论。

### P1-SCE-07：修正、主题切换和事件切换

用户修正 ASN、从地址族切到路径，再请求切换事件；旧实体按规则覆盖或清除。事件目标
不唯一时先澄清，切换完成后旧 publication 的事实不得进入新回答。

### P1-SCE-08：全国断网、用户影响、责任和外部证据

用户询问全国是否完全断网、谁负责、影响多少用户，并要求读取 OONI 或 URL；系统只保留
RRC25 控制面可确认事实，说明所缺证据，不联网、不归责、不生成用户影响数字。

### P1-SCE-09：空值、无结果、快照冲突和响应无效

事件结束为空、Update 能力缺失、ASN 无结果、跨 API publication 冲突和时序长度无效时，
分别得到正确状态；阻断级冲突不得发布看似完整的答案。

### P1-SCE-10：取消、重复提交和并发顺序

用户取消活动轮次、重复点击发送或在旧轮未结束时发起新轮；系统不产生幽灵回答、不重复
计数、不让较晚返回的旧轮覆盖当前状态。

### P1-SCE-11：断线重连、会话到期和 revision 漂移

短暂断线后恢复同一有效会话；到期或进程重启无法恢复时明确新建会话。活动 publication
变化时暂停新回答，旧回答保留旧身份，用户确认后才以新 revision 继续。

### P1-SCE-12：模型失败、提示注入和 P2 请求

模型超时、输出新增事实或用户要求忽略边界、执行 URL、开展组合调查时，确定性事实不被
改写；系统返回安全草稿、明确失败或 P2 能力说明，不伪装完成调查。

## 六、量化验收门槛

- P0 的 35 个案例必须在同一 P1 候选上全部执行，四类数量保持 20、5、5、5；
- 事件、publication/revision、事实一致和证据可解析硬门禁均为 100%；
- 5 个多轮旅程的状态继承、覆盖、清除和隔离正确率为 100%；
- 5 个越界案例禁止断言命中数为 0；
- 5 个异常案例的补零、猜测、快照混用和无效答案发布次数为 0；
- 重复提交产生不同事实答案、已取消轮次继续发布、旧轮覆盖新状态和跨会话串扰次数为 0；
- 用户操作提交后应立即得到本地处理状态，不出现无状态的静默等待；
- 关键身份变化、会话到期、模型不可用和数据 API 不可用均具有独立可见状态；
- 正式回答中的事件事实必须 100% 来自当前绑定的 Domeye 页面/API 证据；
- 可执行子目标引用已登记 capability、工具/算子合同版本和通过 Oracle 的覆盖率为 100%；
- 未映射用户目标被删除、误配为已有能力或触发未登记工具的次数为 0；
- 不设置一个可以抵消硬门禁的总分、Macro-F1、语言风格分或平均响应时间分。

## 七、P1 最终交付和验收证据

P1 最终交付包至少包含：

1. 本最终验收文档、分阶段计划和 P1 防偏离 Hook 配置；
2. 聊天入口、事件身份栏、消息状态、证据下钻和窄屏效果的浏览器证据；
3. 会话、轮次、UserGoalPlan、GroundingPlan、状态转换、回答和错误 Schema；
4. P1 产品/证据边界、Capability Catalog、Typed Tool/Operator Contract、算子 Oracle、
   事实来源和证据解析机器合同；
5. P0 35 案例在同一 P1 候选上的逐案例结果；
6. 取消、重连、到期、幂等、并发、模型失败和提示注入测试；
7. 前端、后端代理、Sidecar、规则/模型和执行环境身份；
8. 制品清单、SHA-256、阶段回执、未关闭偏离和 P2 正式入口回执。

文档、代码、离线测试、浏览器、部署和生产验证是不同证据层；P1 是否通过以当前工程
验收包为准，不能由任一单层绿色状态替代。

## 八、明确不产生的效果

- 不形成开放式通用聊天机器人；
- 不允许模型自由规划或调用工具；
- 不以 P1 工具白名单限制用户目标理解，也不把“能理解”误写成“能执行”；
- 不要求为了建设 P1 语义层而预先实现 P2 至 P5 的工具；
- 不读取当前绑定 RRC25 能力合同之外的互联网、DNS、HTTP、流量或用户侧数据；允许读取
  P0 已验证且 P1 正式采用的同域只读后端端口，但不得任意探索内部系统；
- 不把现有报告追问、旧 Sidecar 或一次模型演示直接认定为 P1；
- 不生成 Evidence Graph、调查计划、假设、原因候选、反事实或 RCA；
- 不确认政府行为、攻击、配置错误、设施故障、责任主体、全国完全断网或真实用户影响；
- 不承诺长期对话存储、跨设备永久历史、个性化记忆或对话训练；
- 不因为阶段 Hook、P0 案例、静态页面或本地测试通过就宣称已经合并、部署或生产验证；
- P1 通过不表示 P2 至 P5 已实现，也不授权合并、发布、部署或生产切换。

## 九、Hook 与最终判定边界

P1 每个阶段结束都调用国家中断 Agent 计划防偏离 Hook。Hook 通过只能证明合同结构、
阶段映射、任务路径和冻结核心信号没有发现机检偏离，不能证明聊天体验、数据、模型、
浏览器、部署或生产效果已经通过。

最终判定必须同时回读本文件、分阶段计划、P1 配置、P0 35 案例结果、浏览器证据、机器
合同、候选身份和 P2 入口回执。任一硬门禁失败时，P1 不得判定通过。
