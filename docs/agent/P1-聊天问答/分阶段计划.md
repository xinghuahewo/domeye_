版本：1.2

约束：只定义阶段入口、前端需求效果、后端评测效果、出口和边界

最终效果基准：[P1 事件绑定聊天问答最终验收文档](./最终验收文档.md)

上位边界：[国家中断 Agent 建设总纲](../国家中断Agent建设总纲.md)

历史输入：[P1 原入口回执](../P0-需求与评测/P1入口回执.md)

## 一、总入口

- 既有 P0 revision `p0-v1-20260808-ir-r1`、35 个案例和入口回执只作为历史回归与迁移
  输入；新版 S0 必须等待 P0 v1.3 Capability Discovery Ledger、分层证据、feasibility/
  Oracle seed、35 个案例和候选处置回执形成；
- P0 已实测 `country_outage` 页面、正式 API、publication/read model、相关后端服务和
  可追溯中间数据，并将能力分为已发布、后端未发布、可推导、语义未冻结、不可用、越界
  和未知；
- P1 必须先对 P0 候选作 `adopt`、`defer`、`reject` 裁决，复核采用项身份，再冻结产品/
  证据边界、Capability Catalog、Typed Tool/Operator Contract 和完整算子 Oracle；
- 现有报告追问、会话和代理代码只能作为候选复用基础，尚未经过本计划的事件绑定、多
  标签、多轮和 P0 35 案例验收；
- P1 不等待 P2 至 P5 的数据或能力，也不因后续工程目标扩大自己的首版范围。

## 二、总出口

- 用户能够从合法事件进入一个身份可见的聊天页面，围绕同一事件连续追问；
- 20 个直接问题、5 个多轮旅程、5 个越界问题和 5 个异常问题在同一 P1 候选上通过；
- P1-FE-01 至 P1-FE-10、P1-BE-01 至 P1-BE-12、P1-SCE-01 至 P1-SCE-12 在同一
  P1 revision 上闭合；
- 事实、用户目标、grounding、状态、证据、回答、失败、会话和候选身份均有机器可读合同；
- 取消、重连、会话到期、revision 漂移、模型失败和提示注入均有真实降级效果；
- 形成 P2 正式入口回执，明确哪些复合调查请求在 P1 被正确降级而不是伪装完成。

## 三、全局边界

- S0 至 S3 是四个轻量闭合点，不是四个相互独立的大工程；每个阶段交付一个可以核对的
  纵向产品切片，并继续保持前序出口；
- 未达到当前阶段出口时不得进入下一阶段，不通过隐藏失败状态、删除 P0 案例、降低硬
  门禁或改写最终验收文档消除偏离；
- P1 始终只使用 RRC25 当前绑定能力，不读取外部网络，不引入其他 collector；当前绑定
  能力可以包含 P0 已验证且 P1 正式采用、经稳定只读端口合同化的同域后端能力，但不包含
  任意数据库、内部路由、临时脚本或原始中间数据探索；
- 模型不能选择事件、publication、事实、证据、回答等级或状态转换，不能补造数字；
- 用户目标语义保持开放，不能被 P1 工具名称或封闭 Intent 枚举截断；只有执行 grounding
  保持封闭，并且只能引用已经登记、版本化和通过 Oracle 的 P1 capability 与只读算子；
- “能力与工具合同先行”不要求先完成所有工具运行时代码，也不要求先建设 P2 至 P5 的
  组合调查、假设、多源证据或 RCA 工具；
- 既有 `p1-candidate-61354911c7793d75` 只按原合同保持历史有效，不自动满足本文 v1.2
  新增的 P0 能力账本、UserGoalPlan、GroundingPlan、工具合同或 Oracle；采用新要求必须
  产生新 revision、
  新候选身份和符合性回执；
- 现有报告 Agent、外部证据、模型认证或生产页面不能自动记为 P1 阶段证据；
- 每个阶段结束必须调用国家中断 Agent 计划防偏离 Hook；
- Hook 结构检查通过不等于聊天页面、后端、模型、评测、浏览器、部署或生产已经通过；
- 本计划不授权修改 P0 真值、冻结核心、生产数据、发布配置或执行部署。

## 四、全局建设顺序、阶段入口与效果

P1 的建设依赖固定为：

```text
P0 Capability Discovery Ledger、分层证据与候选处置
  → P1 复核 adopt 项的运行与数据身份
  → 产品与 RRC25 证据边界
  → Capability Catalog
  → Typed Tool/Operator Contract
  → 算子 Oracle
  → 开放 UserGoalPlan
  → 封闭 GroundingPlan
  → 确定性执行、事实/证据校验和状态提交
```

P0 先回答“现有系统有什么、证据成熟度如何”；P1 前六项回答“本产品采用什么、怎样稳定
执行并证明正确”；后两项再回答“用户实际想做什么、其中哪些能够落到当前能力”。建设
顺序是能力发现和工具合同先于可执行语义映射；单轮运行顺序则是先理解完整用户目标，再由
Grounding Validator 映射到冻结工具，两者不得混淆。

没有现成工具的目标仍进入 `UserGoalPlan`，随后得到 `partial`、`clarify`、`unsupported`
或 `invalid_data` 以及缺口理由，不能被删除或错配。新能力只能通过新的 capability/工具
合同、Oracle 和评测增量进入目录，模型不得在运行时自行创造工具。

### S0：能力接收、工具合同与事件会话壳层

#### 入口

- P0 v1.3 正式入口、Capability Discovery Ledger、分层证据、feasibility/Oracle seed、
  35 个案例和候选处置能够由任务读取并校验 SHA-256；
- 旧 `p0-v1-20260808-ir-r1` 只能作为迁移输入，不能单独证明本版 S0 入口成立；
- 当前事件详情入口、publication 解析和 RRC25 页面/API 身份合同可供核对；
- P1 最终验收文档、用户回答状态和会话边界已经形成候选。
- 既有 P1-v1 候选可作为事实算子与失败边界的冻结基线，但不得把旧验收回执当成本版本
  Capability/Tool/Oracle 与开放目标分层已经通过的证据。
- P1 已逐项裁决 P0 候选；`adopt` 项可供合同化，`defer`、`reject`、unknown 和语义未冻结
  项不得进入可执行目录，也尚不接入混合意图模型。

#### 前端需求效果

- P1-FE-01 至 P1-FE-03 到期：用户只能从合法事件进入，持续看见事件身份、聊天层级和
  当前轮真实状态；
- P1-FE-09 的边界壳层到期：澄清、不支持和数据无效具有独立可见样式，不用空白或无限
  加载冒充处理；
- 首屏建议问题只来自 P0 `adopt` 集合和 P1 当前已合同化范围，不展示原因调查、外部搜索
  或 RCA 提示。

#### 后端评测效果

- P1-BE-01、P1-BE-03、P1-BE-04、P1-BE-06 和 P1-BE-09 到期：请求/回答身份、会话状态字段、
  五级可回答性和输入安全边界冻结；
- 形成 S1/S2 的前置合同基线：产品与 RRC25 证据边界、版本化 Capability Catalog、
  Typed Tool/Operator Contract 和每个拟执行算子的 Oracle/异常 fixture；
- P0 的 feasibility/Oracle seed 只作为输入；每个 `adopt` 项必须形成 P1 自身的稳定只读
  端口、完整合同和 Oracle，后端未发布能力不得直接暴露给模型；
- 每项工具合同至少闭合用户结果、输入、前置身份、输出事实和单位、证据、缺失/无结果/
  冲突/无效语义、禁止推断、只读权限、状态副作用与组合限制；
- 事件、publication、revision、cohort、窗口和 collector 任一冲突时，服务不进入有效
  回答状态；
- 即使尚未接入完整问答，壳层也必须返回真实的未建设、澄清或失败状态。

#### 出口

- P1-SCE-01 的事件进入、身份显示和首轮请求包络通过；
- 非法事件、缺少 publication、身份冲突和未配置服务均不能显示为可聊天；
- 前端状态名称与后端回答等级、会话状态和错误分类一一对应；
- Capability Catalog 中每项可执行能力都引用对应工具合同和 Oracle；只有 API 字段、临时
  函数名或模型提示词而没有业务合同的条目不得进入 S1；
- 每项可执行能力都能追溯到 P0 `adopt` 条目，`defer`、`reject` 或 unknown 条目进入目录
  的数量为 0；
- S0 Hook 结论为“一致”或“已修正”。

#### 边界

- S0 只证明入口、身份、状态和壳层合同成立，不证明事实问答、模型或多轮已经完成；
- 可以使用确定性占位结果验收状态流，但不得把占位结果计入 P0 案例通过；
- S0 冻结的是 P1 当前能力的合同和 Oracle，不要求所有工具代码完成，不建设 P2 至 P5
  的未来工具，也不冻结一个封闭的用户表达词表；
- 不要求在 S0 建成长期会话存储、外部证据或完整聊天视觉精修。

### S1：当前事实单轮问答纵向闭合

#### 入口

- S0 的事件身份、会话包络、回答等级和失败状态保持通过；
- P1 `adopt` 集合中的概述、时序、ASN、地址族、资源、路径、证据和身份能够通过正式 API
  或稳定只读后端端口绑定同一 publication；
- P1 Capability Catalog、Typed Tool/Operator Contract 和算子 Oracle 已通过 S0 回检，
  确定性事实算子与证据引用规则可供候选实现读取。

#### 前端需求效果

- P1-FE-04 到期：单轮回答先给结论，再给关键数字、单位、统计范围、证据和限制；
- P1-FE-03 保持：读取、生成、校验、完成、部分回答、不支持和失败状态真实可见；
- 用户能够从回答下钻到当前事件证据，并返回聊天位置继续提问。

#### 后端评测效果

- P1-BE-05 至 P1-BE-07 到期并继续保持 P1-BE-04：事实/语言分层、逐子目标可回答性和可
  重放回答包络闭合；
- 算子实现逐项服从 S0 合同并通过 Oracle；S1 可以使用显式 `GroundingPlan` fixture、
  固定建议问题或窄确定性路由验证执行纵向链路，不以此宣称语义理解已经灵活闭合；
- 20 个直接问题逐项执行，Update/Withdraw 未暴露、检测时间非真实起点、事件结束未知
  等限制保持原真值；
- 模型不可用时仍能返回通过校验的确定性草稿，不以模型流畅度代替事实一致性。

#### 出口

- P1-SCE-04 通过，且 P1-SCE-02、P1-SCE-03 涉及的时间线、峰值、末端状态、ASN、
  地址族、路径、指标和证据等单轮事实切片具有真实结果；完整连续追问留到 S2；
- 20 个直接问题的事件绑定、publication 绑定、参考事实和证据解析达到 100%；
- 直接问题触及原因、外部证据或未暴露能力时，不会进入事实答案；
- S1 Hook 结论为“一致”或“已修正”。

#### 边界

- S1 只验收当前事实的单轮纵向切片，不因能够回答多个子目标而称为组合调查；
- 不在 S1 重新探索 P0 未验证的内部能力；新增发现必须回到新的 P0 能力 revision 或等价
  增量发现合同后再进入 P1；
- 不把多个白名单算子顺序执行生成 Evidence Graph；
- S1 的固定问题或显式计划通过不能证明同义、省略、口语、指代、多意图和开放目标理解
  已通过；该能力在 S2 依据已冻结工具合同验收；
- 单轮通过不能替代多轮继承、修正、切换和隔离验收。

### S2：混合语义与短期多轮状态闭合

#### 入口

- S1 的 20 个直接问题和同快照证据门禁保持通过；
- Capability Catalog、Typed Tool/Operator Contract 和算子 Oracle 保持冻结并可校验；
- `UserGoalPlan`、`GroundingPlan`、实体槽位和状态转换语义已经形成候选，但必须在本阶段
  通过真实语言与多轮真值后才能冻结；
- 会话能够区分活动轮、已完成轮、取消轮和待澄清轮。

#### 前端需求效果

- P1-FE-05 至 P1-FE-07 到期：用户可以提出复合问题、使用指代、修正 ASN 或地址族、
  切换主题和切换事件；
- 页面显示当前继承的事件和关键实体，修正或切换后不再展示已清除状态；
- 原因追问和不唯一事件切换分别得到边界回答和最少必要澄清。

#### 后端评测效果

- P1-BE-02、P1-BE-03、P1-BE-07 和 P1-BE-08 到期：硬规则优先的混合语义、多轮状态机、
  幂等和有序写入语义闭合；
- 语义层先形成开放的多目标 `UserGoalPlan`，完整保留同义、省略、口语、指代、多意图及
  暂无能力的目标；确定性 Grounding Validator 再将每个目标映射到已登记工具，或给出
  `partial`、`clarify`、`unsupported`、`invalid_data`；
- 模型只产生受 Schema 约束的目标/实体候选或改写，确定性规则裁决身份、安全、grounding、
  事实和状态；模型不得创造 capability、operator、参数字段或权限；
- 5 个多轮旅程按完整会话执行，`inherit`、`set`、`clear` 和切换隔离全部达到 100%。

#### 出口

- P1-SCE-02、P1-SCE-03、P1-SCE-05 至 P1-SCE-07 通过：连续事实追问、复合问题、
  指代、证据边界、修正、主题切换和事件切换均符合真值；
- 可执行子目标引用登记 capability、工具合同版本和通过 Oracle 的覆盖率为 100%，未映射
  目标被删除、误配为已有能力或触发未登记工具的次数为 0；
- P1-SCE-10 的重复提交、取消和并发顺序核心语义通过；
- 跨事件、跨 publication、跨会话和被清除实体的串扰次数为 0；
- S2 Hook 结论为“一致”或“已修正”。

#### 边界

- S2 的“混合意图”不是让模型自由规划工具；请求只能落入 P1 白名单算子；
- “只能落入白名单算子”约束执行 grounding，不约束用户目标理解；暂无工具的原因、责任、
  Update 或未来调查目标仍须被正确理解、原样保留并安全降级；
- 短期多轮不承诺跨设备永久历史、长期记忆或进程重启后恢复；
- 多轮状态不是证据，不能把用户或模型上一轮说法写入当前事件事实。

### S3：可靠性、全量候选验收与 P2 入口

#### 入口

- S0 至 S2 全部达到出口，且前序结果在同一 P1 候选身份上仍然成立；
- P0 35 个案例、P1 全部需求和联合场景具有可执行结果；
- 浏览器、前端、控制面代理、Sidecar、规则/模型和执行环境身份可绑定。

#### 前端需求效果

- P1-FE-01 至 P1-FE-10 全部到期并重新覆盖；
- P1-FE-08 和 P1-FE-10 的取消、重连、会话到期、窄屏、键盘和辅助技术效果闭合；
- 用户可以区分服务不可用、模型不可用、数据不可用、会话到期、revision 漂移和问题不
  支持，并获得可执行的下一步。

#### 后端评测效果

- P1-BE-01 至 P1-BE-12 全部到期并重新覆盖；
- P1-BE-09 至 P1-BE-12 的安全、隐私、审计、P0 硬门禁和 P2 交接闭合；
- P0 35 个案例在同一候选上全部通过，取消、重连、到期、幂等、并发、模型失败和提示
  注入测试没有阻断失败；
- P2 正式入口回执只交付已验收的 Capability Catalog、工具/算子合同、Oracle、语义与回答
  合同和正确降级清单，不转移外部网络、因果或生产权限。

#### 出口

- P1-SCE-01 至 P1-SCE-12 在同一候选身份上全部通过；
- P1 最终判定为“通过”，或只存在不影响 P2 入口且被清楚记录的非阻断条件；
- 最终验收包、制品 SHA-256、阶段回执、未关闭偏离和 P2 正式入口回执形成；
- S3 Hook 给出最终“一致”或“已修正”结论。

#### 边界

- 不以 Hook、单元测试、静态截图、HTTP 200、模型演示或部署状态单独冒充 P1 通过；
- P1 通过只能称为 RRC25 事件绑定聊天问答，不称为组合调查助手或 RCA Agent；
- S3 不授权自动合并、构建、发布、部署、生产切换或扩大外部访问权限。

## 五、阶段封口

阶段 Hook 必须同时回读 P1 最终验收文档、本计划、P1 机器配置和当前 TASK.json，核对
阶段入口、前端需求效果、后端评测效果、出口、边界和到期要求。

每个阶段结束调用：

```bash
python3 .codex/hooks/country_outage_agent_program_review.py \
  --project P1 \
  --stage S0
```

后续阶段将 `S0` 替换为 `S1`、`S2` 或 `S3`。作为条件化 Stop Hook 运行时显式声明：

```bash
export DOMEYE_COUNTRY_OUTAGE_AGENT_PROJECT=P1
export DOMEYE_COUNTRY_OUTAGE_AGENT_STAGE=S0
```

回检结论只允许为“一致”“已修正”“无影响”或“存在待处理偏离”。最后一种必须列出
P1-FE、P1-BE、P1-SCE 或边界编号、偏离位置和原因，并停止阶段晋级。

Hook 输出只提出复核问题和机检偏离，阶段负责人仍须检查实际页面、API、会话、模型、
评测和候选身份。Hook 通过不能替代最终验收包。
