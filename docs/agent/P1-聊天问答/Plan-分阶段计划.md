# P1 RRC25 事件问答 Agent Plan（分阶段计划）

版本：`p1-plan-v1`
对应目标文档：`Task-Spec-最终验收文档.md`
状态：路线合同，尚未表示任何阶段完成

## 一、计划定位

本计划不是固定任务清单，只定义阶段入口、前端与使用效果、后端与评测效果、出口和边界。
它把 P1 拆成 S0 至 S4 五个可验收能力台阶，但不规定模型供应商、Agent 框架、Tool
数量、目录结构、UI 布局、人员安排或日历排期。

路线可以调整，阶段可以在风险可控时交叠，Capability 可以重新组合，Tool 可以拆分或
合并，模型和编排实现可以替换；但任何调整都必须保留 `Task-Spec-最终验收文档.md`
中的最终要求、身份门、证据门、权限门、状态门和越界边界。

## 二、路线自由度与不可变约束

### 允许自由选择

- 一个 Tool 支撑多个 Capability，或一个 Capability 由多个 Tool/算子支撑；
- 使用单模型、多模型、小模型、规则或混合语义解析；
- 使用同步、流式或异步回答；
- 使用何种 Agent 编排、缓存、会话存储、前端组件和可观测方案；
- 在阶段出口不变的前提下并行开展原型、评测和工程验证；
- 根据实测失败分布调整语义变体和普通体验指标。

### 不允许自由改变

- RRC25-only、事件/publication/revision 身份和逐事件能力协商；
- 开放 UserGoalPlan 到封闭 GroundingPlan 的职责分离；
- 事实只能来自确定性只读执行和登记 DerivedFact；
- null、unknown、unavailable、not configured 和 0 的区别；
- 权限、执行白名单、状态验证后提交和失败关闭；
- 原因、责任、用户影响、全国中断、恢复、外部数据和 P2-P5 边界；
- P0 v1.3 35 个案例、独立产品语义审核和同候选验收；
- 不能因为实现困难或模型表现不佳而降低最终验收门。

## 三、共同入口

S0 只在以下输入可复核时启动：

- P0 v1.3 Capability Discovery Ledger、8 项 unknown、10 个 Oracle seed；
- `17 adopt / 5 defer / 4 reject` 的 P1 入口处置；
- 不可变 P0 35 案例及其事件、publication、证据和边界真值；
- 当前实现仍不被宣称为 P1 Agent，旧报告追问也未被直接复用；
- 当前 IR publication 只是代表事件，其他事件必须独立协商能力。

## 四、阶段路线

### S0：运行能力与执行合同冻结

#### 入口

P0 v1.3 入口制品完整、身份可复核；团队能够逐项解释 17 个 adopt 候选为什么进入或不
进入首批 P1 范围。

阶段到期映射：

- 用户与前端要求：`P1-UX-01`、`P1-UX-04`、`P1-UX-05`、`P1-UX-09`；
- 确定性合同：`P1-CTR-01`、`P1-CTR-02`、`P1-CTR-03`、`P1-CTR-04`、
  `P1-CTR-05`、`P1-CTR-06`、`P1-CTR-07`、`P1-CTR-09`；
- 联合场景：无新增到期项。

#### 前端与使用效果

允许只形成可评审原型或交互合同，但必须看得出当前事件身份、数据截止、回答状态和
证据入口。事件变化时重新协商能力的用户提示必须明确。

#### 后端与评测效果

从 17 个候选中选择首批 Runtime Capability Catalog；形成版本化 Capability→Tool/算子
映射、Typed Tool Contract、权限范围和完整 Oracle 计划。Tool 可以拆分或合并，但每个
用户结果、身份、单位、null、错误和禁止用途都必须闭合。

#### 出口

每个首批能力都有 adopt/defer 决定、Typed Tool Contract 和可执行 Oracle；未知项有
owner 和下一验证条件；独立专家角色完成产品语义真值审核。调用 P1 Alignment Hook，
对 `P1-CTR-01` 至 `P1-CTR-07`、`P1-CTR-09` 的可达性给出“一致”“已修正”或阻断。

#### 边界

S0 不要求 Tool 已实现，不要求聊天页面可用，也不把 P0 seed 当成完整 Oracle。不得为
追求工具覆盖率接入 defer/reject 能力或把当前 IR 能力外推到所有事件。

### S1：确定性单轮问答垂直切片

#### 入口

S0 选中的最小能力集合已冻结，至少能够支撑一个事件事实问题从身份校验到证据回答的
闭环。

阶段到期映射：

- 用户与前端要求：`P1-UX-01`、`P1-UX-03`、`P1-UX-04`、`P1-UX-05`、`P1-UX-10`；
- 确定性合同：`P1-CTR-04`、`P1-CTR-05`、`P1-CTR-06`、`P1-CTR-07`、
  `P1-CTR-08`、`P1-CTR-09`、`P1-CTR-10`、`P1-CTR-16`；
- 联合场景：`P1-SCE-01`。其他单轮场景可以探索或提前实现，但只在其明确到期阶段或
  S4 形成正式出口，不因 S1 的一条垂直切片提前宣告通过。

#### 前端与使用效果

用户可以在当前事件中完成至少一条真实单轮问答旅程，看到回答状态、关键事实、证据、
限制和错误反馈。具体视觉形态、是否流式以及证据展开方式可以调整。

#### 后端与评测效果

至少一条真实链路闭合事件身份、只读 Tool、确定性算子、evidence refs、回答装配、权限
和失败语义。事实回答可以先使用受控输入或简单语义入口，但不能由模型生成事实。

#### 出口

同一候选上的单轮正常、null、空值、错误 publication、权限拒绝和 Tool 超时均有证据；
关键事实可回查且失败不发布半成品。独立语义审核确认答案符合产品理解后调用 Hook。

#### 边界

S1 不以大量手写 Intent 正则作为最终语义方案，不要求多轮和全部 17 个候选完成，不
允许因为只做垂直切片而绕过身份、证据、权限或失败关闭。

### S2：开放目标到封闭计划

#### 入口

确定性单轮执行链路已经可靠，语义层可以在不改变事实层的情况下替换和比较。

阶段到期映射：

- 用户与前端要求：`P1-UX-02`、`P1-UX-05`、`P1-UX-06`、`P1-UX-08`；
- 确定性合同：`P1-CTR-08`、`P1-CTR-09`、`P1-CTR-10`、`P1-CTR-11`、
  `P1-CTR-12`、`P1-CTR-13`；
- 联合场景：`P1-SCE-06`、`P1-SCE-08`、`P1-SCE-11`。

#### 前端与使用效果

用户可以使用同义、口语、错序和同一事件内的多意图表达。可回答子目标得到事实回答，
困难、越界或歧义子目标保持原意并分别澄清或拒绝。

#### 后端与评测效果

开放 UserGoalPlan、封闭 GroundingPlan、Schema Validator、能力/权限 Validator 和安全
回退链路闭合。允许比较多种模型、规则或混合路线；评价重点是目标保真、合法 grounding、
事实不漂移和失败不执行，而不是固定 Intent 标签准确率。

#### 出口

语义变体集被冻结；同义、省略前置样例、多意图和越界表达可以追溯到原目标、计划、
裁决和证据。模型无效输出、能力创造和目标丢失被机器门拒绝，并通过独立语义审核。

#### 边界

语义理解保持开放不等于执行开放。不得让 Tool 白名单裁剪 UserGoalPlan，也不得让模型
创造 Tool、事实、证据、权限或把 P2 调查目标伪装成 P1 多意图。

### S3：多轮状态与事件切换

#### 入口

单轮语义和确定性执行已经闭合，状态可以作为独立风险面建设。

阶段到期映射：

- 用户与前端要求：`P1-UX-07`、`P1-UX-08`、`P1-UX-09`、`P1-UX-10`；
- 确定性合同：`P1-CTR-02`、`P1-CTR-10`、`P1-CTR-14`、`P1-CTR-15`、
  `P1-CTR-16`；
- 联合场景：`P1-SCE-07`、`P1-SCE-09`、`P1-SCE-10`、`P1-SCE-12`。

#### 前端与使用效果

用户可以自然追问、修正、澄清、取消、重连和切换事件；页面明确显示上下文变化，失败
后可以继续使用。会话到期和 revision 变化不会把旧回答伪装成当前事实。

#### 后端与评测效果

EvidenceState 与 DialogState 分离；继承、覆盖、清除、待澄清、取消、超时、revision
漂移和事件切换具有确定状态迁移。只有计划、权限、执行和回答全部验证成功才提交状态。

#### 出口

P0 的 5 个多轮旅程以及新增事件切换、失败恢复旅程在同一候选通过；不存在 stale
pending clarification、跨事件 ASN/地址族串扰或失败计划污染。独立语义审核后调用 Hook。

#### 边界

聊天历史不能成为事实证据；不得用更长上下文替代状态合同；不得把未验证的模型猜测、
失败 Tool 结果或旧 publication 事实写回当前状态。

### S4：同候选最终验收与 P2 入口

#### 入口

S0 至 S3 的出口证据闭合且没有未处理阻断；候选代码、配置、模型、Prompt、Capability
Catalog、Tool、Schema、数据 publication 和运行环境身份可以唯一绑定。

阶段到期映射：

- 用户与前端要求：`P1-UX-01`、`P1-UX-02`、`P1-UX-03`、`P1-UX-04`、
  `P1-UX-05`、`P1-UX-06`、`P1-UX-07`、`P1-UX-08`、`P1-UX-09`、`P1-UX-10`；
- 确定性合同：`P1-CTR-01`、`P1-CTR-02`、`P1-CTR-03`、`P1-CTR-04`、
  `P1-CTR-05`、`P1-CTR-06`、`P1-CTR-07`、`P1-CTR-08`、`P1-CTR-09`、
  `P1-CTR-10`、`P1-CTR-11`、`P1-CTR-12`、`P1-CTR-13`、`P1-CTR-14`、
  `P1-CTR-15`、`P1-CTR-16`；
- 联合场景：`P1-SCE-01`、`P1-SCE-02`、`P1-SCE-03`、`P1-SCE-04`、
  `P1-SCE-05`、`P1-SCE-06`、`P1-SCE-07`、`P1-SCE-08`、`P1-SCE-09`、
  `P1-SCE-10`、`P1-SCE-11`、`P1-SCE-12`。

#### 前端与使用效果

在桌面和窄屏真实浏览器旅程中，用户可以完成事件概览、时序、地址族、ASN、路径、
证据、多轮、局部回答、事件切换和失败恢复；视觉实现可调整，但关键信息和边界不可丢失。

#### 后端与评测效果

在同一候选上执行 P0 v1.3 35 案例、冻结语义变体、多轮、边界、异常、权限和状态旅程；
形成 manifest、结果、浏览器/API/Tool 证据、独立语义审核和未关闭 unknown 清单。

#### 出口

`Task-Spec-最终验收文档.md` 的全部最终验收门有同候选证据；独立专家角色给出产品语义
PASS 且无阻断；S4 Hook 给出最终“一致”或“已修正”。随后只能交付 P2 入口回执，不能
宣称 P2、RCA、部署或生产验证已经完成。

#### 边界

Hook 结构检查通过不等于 P1 产品效果通过；单元测试、模型离线分数、HTTP 200、截图或
一次演示不能替代同候选联合验收。不得为了按时出口删除失败案例或降低硬门。

## 五、路线调整机制

发生以下情况时可以调整路线：

- P0 ledger 或运行态能力发现真实变化；
- Oracle 暴露 Tool 边界不合理，需要拆分或合并；
- 模型失败分布表明语义方案需要替换；
- UI 原型证明当前交互不能清楚表达身份、证据或 partial；
- 权限、状态或性能风险要求提前建设某项门禁。

调整前必须记录触发证据、受影响要求编号、原路线、替代路线和回归范围。可以改 Plan，
但不能静默修改 Task Spec 消除偏离；若产品目标确实变化，必须单独评审新 Task Spec
revision，并保留旧版本。

未达到当前阶段出口时不得把阶段标记为完成。确需并行时，可以启动不依赖该出口的验证，
但下游验收不能借用尚未成立的上游结论。

## 六、Alignment Hook 调用

每个阶段结束必须调用 P1 Alignment Hook：

```bash
python3 .codex/hooks/country_outage_agent_p1_alignment.py --stage S0
python3 .codex/hooks/country_outage_agent_p1_alignment.py --stage S1
python3 .codex/hooks/country_outage_agent_p1_alignment.py --stage S2
python3 .codex/hooks/country_outage_agent_p1_alignment.py --stage S3
python3 .codex/hooks/country_outage_agent_p1_alignment.py --stage S4
```

Hook 负责检查 Task Spec、Plan、要求编号、阶段映射、当前 TASK 路径边界和冻结核心信号，
并生成产品语义复核问题。Hook 不自动证明真实页面、模型、Tool、数据、浏览器、发布或
生产效果通过。

阶段负责人必须结合实际证据和独立产品语义审核，在结束答复中写出：

```text
国家中断 Agent P1 最终验收回检：Sx 一致 / 已修正 / 存在待处理偏离
```

存在待处理偏离时必须列出要求编号、证据和阻断原因，不得宣告阶段完成。

## 七、计划完成定义

只有 S4 出口全部成立，才能称为“P1 RRC25 事件绑定聊天问答候选已通过验收”。该结论
仍不表示已经合并、部署或生产验证，也不表示具备 P2 组合调查、P3 假设、P4 多源证据
或 P5 RCA。
