# P1 RRC25 事件问答 Agent Task Spec（最终验收文档）

版本：`p1-task-spec-v1.1-page-capability-coverage`
状态：设计合同，尚未表示实现或验收通过
上游入口：`p0-v1.3-20260809-ir-r1`
适用范围：合法 `country_outage` 事件的 RRC25 publication

## 一、文档定位

本文只设计 P1 最终效果，不规定模型供应商、编排框架、Tool 数量、存储方案、UI
布局、人员排期或开发步骤。

P1 的目标是形成一个自然语言体验足够灵活，但事实、证据、权限、执行和状态仍然确定可控的
RRC25 事件问答 Agent。用户可以使用同义、省略、口语、多意图和上下文表达
询问当前 `country_outage` 事件；系统先保留完整用户目标，再把可执行部分约束到当前
事件实际允许的能力和只读执行合同。

P1 的产品名称只能表述为“RRC25 事件绑定聊天问答”。P1 不建设开放式调查计划、
Evidence Graph、有限假设、多源证据或 RCA。

本修订在不改变上述产品边界的前提下，增加“页面能力语义覆盖加固”验收目标。
历史 P1 候选、测试或验收记录不自动满足本修订；必须在新合同下重新提供受影响的同候选
语义、Grounding、Tool、算子、证据、回答和状态回执。

## 二、最终产品效果

用户打开一个合法国家中断事件后，可以在同一页面围绕该事件连续提问。最终效果应当
同时满足：

- 聊天入口明确显示当前事件、publication、revision、RRC25 和数据截止身份；
- 用户不需要记忆指标名、字段名或 Tool 名；
- 系统能理解同义、省略、口语、多意图和上下文表达；
- 每个子目标分别得到 `supported`、`partial`、`clarify`、`unsupported` 或
  `invalid_data` 结论；
- 所有事实来自同一合法 publication 的已验证只读结果或登记的确定性算子；
- 关键数字可以回到证据、指标定义和数据身份；
- 模型不能创造能力、事实、证据、权限或状态；
- 缺失、未知、不可用、未配置和 0 保持不同语义；
- 失败计划、失败工具和失败回答不能污染后续对话状态；
- 对原因、责任、用户影响、全国中断、恢复和外部数据问题诚实降级。

## 三、页面能力覆盖加固目标

### 3.1 覆盖单位是用户结果，不是页面控件

本次改进不以“图表、按钮、页签、分页”为覆盖单位，而以用户能从当前页面与其绑定
API 获得的业务结果为单位。首批 Page Capability Outcome Map 至少覆盖：

1. `PCO-01`：事件身份、观测窗口、数据截止和结束状态；
2. `PCO-02`：事件概览、峰值、当前状态和事实时间线；
3. `PCO-03`：固定 cohort 的 IPv4 与 IPv6 可见地址规模变化；
4. `PCO-04`：窗口内新出现的 IPv4/IPv6 前缀和当前可见规模；
5. `PCO-05`：受影响 AS 范围、列表、搜索筛选和指定 ASN 详情；
6. `PCO-06`：路径观测关联和可核对的真实路径样本；
7. `PCO-07`：指标定义、单位、统计人口和 null/不可用语义；
8. `PCO-08`：publication、dataset、实现与文件摘要身份，以及 RRC25 可证明与不可证明的边界。

每个结果必须映射到页面呈现、已发布 API、确定性推导、限制和当前采用状态，不得从 DOM
文案或函数名反向猜测产品能力。

### 3.2 泛指 IP 问题的产品真值

用户在当前事件中泛问“IP 地址变化情况”、“IP 地址变化趋势”或等价表达时：

- `IP` 默认表示 `IPv4 + IPv6`，不得静默缩窄为 IPv4；
- 主答案分别说明固定 cohort 的 IPv4 可见地址数和 IPv6 `/48` 等价块变化；
- 默认附带窗口内新出现前缀作为独立补充，但不与固定 cohort 合并；
- IPv4 地址数和 IPv6 `/48` 等价块保持不同单位，不直接相加或以原始绝对值判定“哪个更严重”；
- 用户明确限定 IPv4、IPv6、固定 cohort 或“不看新增”时，显式限定优先；
- “趋势”在没有历史、跨事件或跨周期限定时，默认是当前 publication 窗口内时序变化概括，
  不得因为出现“趋势”二字就升级为不可用的正式趋势制品；
- 数据截止、最低点后回升或末值改善不能自动写成恢复。

### 3.3 表达覆盖而非句式枚举

每个页面用户结果都要在标准表达、口语同义、泛指、省略追问、显式修正、复合目标、边界混合和
缺失/异常等表达类型中建立可审核覆盖。覆盖通过结构化的用户目标和回答真值判断，不使用文本
相似度代替，也不通过逐句增加 Prompt 特判获得表面绿灯。

### 3.4 问题探针与独立判卷

P1 应配置一个离线、只读的“页面能力问题探针 Agent”。它从 Page Capability Outcome Map 和产品
边界出发，使用多角色、多表达和多轮上下文生成候选问题，并在隔离会话中进行黑盒提问。

问题探针 Agent 不得同时充当最终判卷者，不得修改黄金问题、Capability Catalog、Tool Contract、
Oracle、Prompt 或运行时状态。独立产品语义 Reviewer 必须在查看系统答案前，根据原问题、已提交
对话上下文和产品合同独立写出预期目标、实体、回答性、必答点和禁止断言，再进行差异审核。

问题资产分为三层：可重新生成的探索池、经独立审核的冻结回归池、来自实际使用的真实失败回放池。
探索问题不经审核不能直接晋级为验收真值。

## 四、最终用户与前端要求

### P1-UX-01：事件身份始终可见

聊天区域必须让用户知道当前回答绑定哪个国家中断事件、publication、revision、
collector 和数据截止时间。事件不是最终态时必须显示“事件结束未知”，不能把窗口末点
写成恢复或结束。

### P1-UX-02：自然语言表达不被固定句式限制

同一目标可以使用指标原名、同义词、口语、错序表达和常见省略提出。用户不需要先从
菜单选择单一 Intent，也不需要用正则能够命中的句式。

### P1-UX-03：回答结构可快速核对

回答应当清楚区分结论、事实、证据、限制和未知。简单问题可以简短回答，复杂问题可以
展开，但不能为了固定模板重复无关内容。

### P1-UX-04：关键事实可以下钻

关键数值、时点、ASN、前缀或路径样本应提供可解析的 evidence ref 或对应页面下钻，
使用户能核对来源，而不是只看到模型叙述。

### P1-UX-05：每个子目标显示真实回答状态

多目标问题不能只返回整句成功或整句失败。可回答部分先回答，越界或缺证据部分单独
说明，用户可以看出哪些是 supported、哪些是 partial 或 unsupported。

### P1-UX-06：多意图问题保持原始目标

系统可以拆分同一事件内的多个 P1 子目标，但不得静默丢弃用户原话中的困难部分，也
不得把一个开放调查问题伪装成几个已经支持的简单问题。

### P1-UX-07：多轮省略和修正自然工作

“IPv6 呢”“峰值什么时候”“那 AS48715 呢”等追问可以继承合法上下文；用户显式修正
地址族、ASN、事件或时间范围时，新表达覆盖相应旧槽位，未被确认的猜测不得进入状态。

### P1-UX-08：必要时澄清，不滥用澄清

只有缺少执行所必需且无法安全推断的信息时才澄清。系统已经拥有当前事件、publication
或明确地址族时，不得重复询问；一句“换”“另一个”也不得在没有合法新引用时切换事件。

### P1-UX-09：事件切换与 revision 变化可理解

切换事件、publication 或 revision 时必须告知用户，清除不再合法的 ASN、地址族、
待澄清和证据上下文，并重新协商新事件能力。旧回答保留旧身份，不被新状态覆盖。

### P1-UX-10：失败后仍可继续使用

工具不可用、模型超时、权限拒绝、网络中断、取消、重连或会话到期时，页面给出可理解
状态，不发布半成品事实；用户可以重试、改问或重新绑定事件。

### P1-UX-11：页面可回答目标不被误拒绝或静默缩窄

只要用户目标可由当前事件已协商的页面/API 事实和登记算子回答，不得因口语、泛指或“情况”、
“走势”、“趋势”等分析用语被误判为不支持。系统不得为了命中已有执行分支，把泛指地址族静默改为
IPv4，把变化概况缩成最大下降，或把事件内时序概括改成跨事件趋势。

### P1-UX-12：地址规模回答人口分层可见

泛指 IP 地址问题的回答必须同时呈现 IPv4 和 IPv6，并将固定 cohort 与新出现前缀分为主答案和
独立补充。页面必须让用户看出各自的单位、窗口和统计人口，不能用一个混合数字掩盖语义差异。

## 五、最终事实、执行与状态合同

### P1-CTR-01：P0 v1.3 是唯一入口能力依据

P1 必须从 P0 v1.3 的 Capability Discovery Ledger、unknown ledger、Oracle seed、35 个
案例和 P1 入口回执选择能力。入口计数固定为 `17 adopt / 5 defer / 4 reject`、8 项
unknown、10 个 Oracle seed 和 35 个案例。`adopt` 只是候选；没有被 P1 明确选择和
冻结的能力不得进入运行时。

### P1-CTR-02：每次事件绑定后协商实际能力

每次事件绑定后必须读取并验证该事件的 capabilities、observation state、incident、
publication 和 revision。当前 IR publication 的能力不得静默外推到其他事件。

### P1-CTR-03：Capability 与 Tool 保持不同层级

Capability 表达用户可获得的业务结果；Tool 表达受控执行接口。多个 Capability 可以由
一个 Tool 支撑，一个 Capability 也可以由多个 Tool 或算子组合，但映射必须版本化、
可审计且不改变用户结果语义。

### P1-CTR-04：Typed Tool Contract 完整闭合

每个进入运行时的只读 Tool 必须具备名称、用途、适用条件、输入、输出、身份字段、
单位、时间语义、分页、null 语义、错误类型、权限、超时、证据引用和禁止用途。只写
函数名或自然语言描述不能视为合同完成。

### P1-CTR-05：每个执行能力具有完整 Oracle

每个已选择能力和确定性算子必须有正常、缺失、空值、错误身份、不可用和边界样例。
P0 的 10 个 Oracle seed 只能作为起点，不能替代 P1 完整 Oracle。

### P1-CTR-06：事件和证据身份先于事实发布

任何事实发布前都必须验证 event type、incident、publication、revision、collector、
窗口、data through、finality 和必要制品身份。计划身份、工具结果身份和回答证据身份
不一致时必须失败关闭。

### P1-CTR-07：指标、单位和缺失语义确定

IPv4 地址与 IPv6 /48 等价块不能合并成一个绝对总量；逐槽峰值不能写成窗口累计人口；
路径相邻不能写成依赖或传播；`null`、`unknown`、`unavailable`、`not_configured` 和 0
不能互换。

### P1-CTR-08：事实只能来自确定性执行结果

模型可以解释用户表达和组织已验证结果，但不能提供数值、ASN、时点、路径、publication
或证据身份。没有工具结果或登记 DerivedFact 的内容只能作为未知或边界说明。

### P1-CTR-09：权限和执行集合由宿主控制

GroundingPlan 只能选择当前事件允许、当前用户获权、已登记并通过 Oracle 的只读能力。
模型不能创造 Tool、扩大参数范围、绕过授权、调用写接口或自行提交状态。

### P1-CTR-10：按子目标失败关闭

多目标请求逐项执行和裁决。一个子目标失败不能污染已经验证的其他子目标，也不能用
常识补齐；系统必须保留局部成功、局部失败、证据不足和越界的区别。

### P1-CTR-11：开放 UserGoalPlan 保留用户原意

语义理解首先形成开放 UserGoalPlan，记录原始目标、子目标、实体、指代、歧义和上下文
依赖。它不受 Tool 白名单裁剪，也不把未支持目标提前改写为 unsupported。

### P1-CTR-12：封闭 GroundingPlan 只表达可执行部分

UserGoalPlan 经能力、身份、权限和边界校验后，才形成封闭 GroundingPlan。每个可执行
节点必须绑定登记能力、输入来源、依赖和预期证据；不可执行子目标保留原意并给出裁决。

### P1-CTR-13：语义失败有确定回退

Schema 无效、目标丢失、实体冲突、越权算子、低可信事件切换或模型不可用时不得猜测
执行。系统可以重试受限解析、澄清或降级到安全答案，但不得回退到会污染状态的脆弱
Intent 正则。

### P1-CTR-14：EvidenceState 与 DialogState 分离

事件事实和证据属于不可由模型改写的 EvidenceState；省略、指代、待澄清和用户偏好
属于短期 DialogState。聊天历史不是事实证据，模型生成内容不能反向写入 EvidenceState。

### P1-CTR-15：验证成功后才提交状态

候选状态只能在计划 Schema、能力、身份、权限、执行结果和回答边界全部验证成功后提交。
状态迁移必须定义事务范围：合法事件绑定和已验证实体修正可以提交；supported 子目标
只能提交获准的 DialogState；失败、unsupported 或证据不足子目标不得写入 EvidenceState
或可执行槽位。共享身份发生冲突时整轮回滚。取消、超时、revision 漂移和事件切换必须
保持旧状态或执行显式清理，不能留下半提交上下文。

### P1-CTR-16：运行轨迹可审计但不暴露隐藏推理

每轮应能审计请求身份、UserGoalPlan 版本、GroundingPlan 版本、Tool/算子版本、结果
状态、evidence refs、状态迁移和失败码；不得要求或保存模型隐藏思维链，敏感输入和凭据
必须脱敏。

### P1-CTR-17：Page Capability Outcome Map 是覆盖入口

覆盖建设必须从版本化 Page Capability Outcome Map 出发。每个用户结果至少记录来源页面/API、身份、输入、
输出、单位、时间语义、null/不可用语义、确定性推导、禁止断言、候选 Tool/算子和采用状态。
DOM 元素、后端函数或模型能不能说出一段话，都不能单独成为可用能力证据。

### P1-CTR-18：用户目标保留分析维度

UserGoalPlan 必须保留用户请求的对象、范围、地址族、统计人口和分析方式等必需维度。具体 Schema
字段可调整，但不得只靠一个粗粒度 Intent 把“变化概况”、“极值”、“事件内走势”和“历史趋势”
压成同一执行语义。

### P1-CTR-19：时序变化概括由通用确定性算子支撑

已登记时序的“变化情况”或“事件内走势”应落到可复用的确定性变化概括算子，不为每个自然语言
短语新增一个 Tool。算子应在原单位内至少给出首值、末值、最小/最大值与时点、净变化、观测点和
缺失状态。只有已登记的指标语义允许时，才可增加从相关极值到数据截止的改变；累计新前缀等指标不得被
套用“下降后回升”语义。更复杂的分段、阈值和波动分类可以迭代，但规则必须版本化、可回放、有 Oracle，
且不得输出因果或恢复判断。

### P1-CTR-20：地址族与新前缀的 Grounding 矩阵显式闭合

Grounding 必须区分 `ipv4`、`ipv6`、`both` 和真正缺少必需实体的情形。泛指 IP 按已冻结产品默认
执行 IPv4 和 IPv6 两条独立轨道，并将新出现前缀作为独立补充节点。`both`、null 或未识别值不得以
“非 IPv6 则 IPv4”的隐式分支通过校验。

### P1-CTR-21：事件内时序与正式趋势产品分离

当前 publication 的已登记 series 可支撑事件窗口内变化概括。只有用户明确要求历史、跨事件、跨周期、
国家间比较或已发布趋势制品时，才进入对应的趋势能力判定。不得使用关键词“趋势”作为单一拒答条件。

### P1-CTR-22：问题探针与语义 Reviewer 权限分离

问题探针 Agent 只能读取审定的页面用户结果、产品边界和测试身份，生成问题、发起隔离黑盒会话并保存原始
回执。它不得修改实现或验收真值，不得把自身解释写成 PASS。独立语义 Reviewer 不使用当前 Planner 输出作为
真值来源，并对探针产生的候选问题和实际回答分开审核。

### P1-CTR-23：探索、冻结和真实失败问题分层治理

探索池可根据模型、页面和失败分布自由扩展；冻结回归池只接收已经独立 Reviewer 确认的问题与语义真值；
真实失败回放池保留实际问题、候选身份、上下文和失败层。不以自动生成数量或文本相似度作为通过依据。

### P1-CTR-24：失败按语义链路归因并定向回归

每个覆盖失败必须至少归因为 Page Capability 真值缺口、Planner、Grounding、Capability、Tool、算子、
回答装配、Evidence、Policy 或 State 之一，并保留原始轨迹。修正后按影响范围重跑冻结用例、同类表达和
边界反例，不因单一句子修正而无差别重跑全部，也不得只添加针对该句的规则。

## 六、最终联合验收场景

### P1-SCE-01：事件概览问答

用户用不同表达询问发生了什么、数据截至何时和事件是否结束；回答绑定同一 publication，
区分完整数据窗口与未知事件结束。

### P1-SCE-02：时序极值和事实时间线

用户询问严重时点、前缀峰值或时间线；系统调用登记的确定性算子，返回有序事实节点、
逐节点证据和未知结束状态，不生成因果边。

### P1-SCE-03：地址族变化与比较

用户询问 IPv4、IPv6 或二者比较；回答保持不同单位，正确给出极值或差值，不能推出
用户数或流量下降。

### P1-SCE-04：ASN 与路径证据下钻

用户查询指定 ASN、受影响 AS 或路径样本；结果绑定真实查询参数和证据，路径相邻只
描述观测关联。

### P1-SCE-05：指标语义与审计身份

用户追问“这个数是什么意思”“数据从哪里来”；系统说明指标人口、单位、publication、
dataset、实现或摘要身份，并区分数据实现和 Web 发布身份。

### P1-SCE-06：同义、口语和错序表达

同一用户目标的同义、口语、简称和错序表达得到等价 UserGoalPlan；措辞可以不同，
GroundingPlan、事实和边界不得因表述变化而漂移。

### P1-SCE-07：省略、指代和修正

连续提问中合法继承地址族、ASN 和事件；显式修正覆盖旧值，模糊指代触发必要澄清，
失败解析不提交状态。

### P1-SCE-08：多意图与局部可回答

“现在还有多少前缀不可见，是不是全国都断了”等问题先回答 RRC25 可观测事实，再拒绝
全国和真实用户推断，不能整题 unsupported，也不能补齐越界部分。

### P1-SCE-09：事件、publication 与 revision 切换

合法切换重新协商能力并清理旧上下文；非法引用、错误 publication 和处理中 revision
漂移失败关闭，旧回答保持原身份。

### P1-SCE-10：缺失、空值、不可用和冲突

缺少轨道、null、空结果、trend 不可用、外部证据未配置和身份冲突分别进入正确状态，
均不被编码为 0、正常或确定结论。

### P1-SCE-11：原因、用户影响和外部数据边界

用户可以自由询问原因、责任、政府行为、全国中断、用户联网、DNS、HTTP 或流量；系统
保留原目标并说明当前证据不能回答，不调用未登记能力，也不把拒答变成事实判断。

### P1-SCE-12：工具、模型、权限与连接失败

工具超时、模型无效输出、权限拒绝、取消、重连和会话到期均不发布半成品、不污染状态；
用户得到可理解的重试、澄清、改问或重新绑定入口。

### P1-SCE-13：泛指 IP 地址变化概况

用户询问“IP 地址变化情况”或等价表达；系统同时读取固定 cohort 的 IPv4 和 IPv6 已登记轨道，
分别返回变化概括，并以独立补充说明新出现前缀。回答不得静默缩为 IPv4 或只回答最大下降。

### P1-SCE-14：事件内 IP 走势与正式趋势边界

用户询问“IP 地址变化趋势”时，系统默认概括当前 publication 窗口内 IPv4/IPv6 轨道；用户明确
要求历史、跨事件或正式趋势制品时，才进入对应能力边界。两者的 UserGoalPlan、Grounding 和用户可见裁决
必须可区分。

### P1-SCE-15：固定 cohort 与新出现前缀分离

默认回答以固定 cohort 为主，新出现前缀为补充；“不看新增”要移除补充，“只看新前缀”要改变主目标。
新路由不得用于抵消或掩盖固定范围的可见性变化。

### P1-SCE-16：问题探针多表达覆盖

问题探针对八类 Page Capability Outcome 生成标准、口语、泛指、省略、修正、复合、边界和异常候选，
以隔离会话执行并保留原始轨迹。独立 Reviewer 盲审用户真值，再对照系统输出；探针不得自行将候选
晋级为冻结回归案例。

### P1-SCE-17：原目标保真与执行适配

对同一可回答用户结果的不同表达，系统可以选择不同合法 Tool 拆分或缓存路径，但不得用固定规范问题
覆盖用户的分析方式。“变化情况”、“最大下降”、“现在值”和“趋势”的共享轨道可复用，但结果装配必须回应
本轮原目标。

## 七、最终验收门

P1 最终候选必须同时满足：

1. 在同一候选、同一配置和同一运行身份上执行 P0 v1.3 的 35 个案例；
2. 事件/publication/RRC25、事实、证据、单位、边界、权限和状态硬门通过率为 100%；
3. 5 个多轮旅程、5 个越界问题和 5 个异常问题全部通过；
4. 核心目标的版本化语义变体集覆盖同义、省略、口语、多意图和上下文表达；
   `UserGoalPlan` 目标保真率不低于 95%。计分单位是参考答案中的单个子目标：只有目标、
   必需实体、指代/上下文依赖和歧义状态全部正确才计为保留；分母为参考子目标数加无
   对应参考目标的新增子目标数，后者一律计为错误，不能通过虚构额外目标抬高保真率，
   也不能以整句平均掩盖目标丢失；
5. `GroundingPlan` 合法性是 100% 硬门。每个请求只能生成能力、身份、权限、参数、依赖
   和边界全部合法的计划，或明确进入不执行状态；任何非法节点到达执行器、发布事实或
   提交状态均判定失败，不能被 95% 的语言理解指标抵消；
6. 任何数值或证据幻觉、未授权执行、错误事件状态提交、原因/责任/真实用户影响越级
   断言均为一票否决；
7. 浏览器旅程、Agent API、计划、Tool 结果、evidence refs 和状态迁移属于同一候选；
8. 至少一个独立专家角色只审核产品语义真值，明确给出 PASS 或阻断项；代码规范审核
   不能替代该审核；
9. 模型、Prompt、Schema、Capability Catalog、Tool、算子、权限或状态合同变化后，
   必须重新运行受影响验收；
10. 性能、超时和重试预算在候选冻结前版本化，并证明不会通过超时后编造答案满足体验；
11. 交付 manifest 能唯一绑定代码、配置、模型、Prompt、评测、数据 publication 和结果。
12. 首批八类 Page Capability Outcome 全部建立页面/API、用户结果、Capability、Tool/算子、证据、限制和
    覆盖问题的版本化映射；
13. “IP 地址变化情况”与“IP 地址变化趋势”作为冻结高风险原问题，必须同时保留 IPv4、IPv6、
    固定 cohort 主答案和新出现前缀独立补充，且不把事件内走势误拒绝为正式趋势制品不可用；
14. 冻结的页面可回答表达集中，误 `unsupported`、静默地址族/人口缩窄、用固定问题改写用户分析方式
    和无证据扩展事实均为一票否决；
15. 问题探针 Agent 与独立产品语义 Reviewer 为分离角色；每个冻结新问题有探针原始回执、先验真值和
    差异结论，不得使用同一输出自问自判；
16. 表达覆盖以用户结果×表达类型的矩阵缺口为主，问题数量可根据风险调整，但不得删除失败反例、
    边界混合、null/不可用和多轮修正类型来获得通过；
17. 每个阶段结束回执必须绑定本 Task Spec 版本、Plan 版本、阶段、候选身份、到期要求、真实制品摘要、
    独立 Reviewer 结论、未关闭阻断和禁止越级声明；Hook 必须拒绝身份不一致、到期要求缺失、制品哈希不匹配、
    Reviewer 不独立或存在未关闭阻断的“阶段通过”。
18. `evidence_refs` 必须指向可读取的原始回执并绑定 SHA-256，不接受任意字符串或只有 PASS 的空壳；
    Reviewer 回执必须绑定不同的出题者与审核者运行身份、被审输入、查看答案前的先验真值、系统输出及时间顺序。
19. S4 同候选证据必须显式绑定前端、后端、运行时、语义 Planner、模型、Prompt、Schema、Capability、Policy、
    Tool Contract、Operator Contract、Oracle 和数据 publication；浏览器、API、UserGoalPlan、GroundingPlan、Tool、
    EvidenceState 和 DialogState 必须以同一旅程身份和原始回执哈希交叉绑定。

## 八、固定边界

- P1 只使用 RRC25 已发布控制面事实，不接入新闻、DNS、HTTP、流量、IODA、OONI 或
  其他 collector；
- P1 只能执行当前事件协商后允许的已登记只读能力；
- P1 内的多意图只表示多个独立 P1 子目标的受控回答，不升级为 P2 开放组合调查；
- 不把相关性、时间先后、共同变化、路径相邻或模型置信度写成因果；
- 不判断政府行为、攻击、配置错误、责任、全国断网、真实用户影响、业务损失或恢复；
- 不把源码存在、合同存在、Oracle 通过、静态页面、HTTP 200 或 Hook 退出码写成产品验收；
- `designed`、`implemented`、`tested`、`accepted`、`merged`、`deployed` 和
  `production_verified` 保持不同状态。
- 问题探针 Agent 只是离线评测角色，不进入生产回答链路，不执行业务 Tool，不写用户会话状态；
- 本次时序概括只描述当前 publication 窗口内已发布轨道，不建设跨事件比较、长期趋势、反事实或调查计划；
- 新出现前缀是组成变化的独立补充，不证明新用户接入、流量迁移或恢复。

## 九、验收证据包

最终验收证据包至少包含：

- 本 Task Spec、分阶段计划和阶段回检记录；
- Runtime Capability Catalog、Typed Tool Contract、完整 Oracle 和权限合同；
- UserGoalPlan、GroundingPlan、回答和状态 Schema；
- P0 35 案例结果及 P1 语义变体、多轮、边界和失败结果；
- Page Capability Outcome Map、表达覆盖矩阵、问题探针角色合同和三层问题资产清单；
- 事件内时序变化概括算子合同、Oracle、空值/身份冲突反例和 IPv4/IPv6/新前缀分层回执；
- 问题探针原始提问与系统轨迹、独立 Reviewer 先验真值、Semantic Diff 和案例晋级记录；
- 同候选浏览器、API、Tool、证据下钻和重连旅程；
- 独立产品语义真值审核结论及已关闭偏离；
- 代码、配置、模型、Prompt、数据、运行环境和制品摘要；
- 未关闭 unknown、限制、风险和 P2 入口回执。

Hook 通过只能证明合同结构、阶段映射和任务路径没有发生已知偏离，不能单独证明上述
最终效果已经实现或通过。
