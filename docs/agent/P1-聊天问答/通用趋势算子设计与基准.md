# P1 通用事件窗口趋势算子设计与基准

版本：`country-outage-p1-event-window-trend-operator-v1.2.0`

算子：`event-window-trend@1.2.0`

状态：精确事实、方向步语义与紧凑聊天输出三层对齐已完成；仍是独立合同和基准制品，未接入现有 P1 的 6 Tool、3 Operator 或 GroundingPlan，不表示合并、发布、部署或生产验收。

## 一、目标与边界

算子把同一 `country_outage` publication 内的已登记 RRC25 时序转换为确定性事件窗口事实。它描述当前窗口中数值怎样变化，不生成原因、责任、恢复、真实用户影响、全国影响或正式历史趋势。

`data_through` 只是数据截止。末值改善、回到窗口基线、累计值停止增长或多个轨道同步变化，都不能证明事件结束或网络恢复。所有跨轨结论保持各自原单位，不生成跨单位总量或绝对严重度。

本轮读取独立专家参考只用于发现可泛化差距。专家分段、转折和叙事优先级属于参考判断，不是 Oracle；真实事件的时间点、数值和模式 id 没有写入算子源码或合成 Oracle。

## 三、输入、登记与失败关闭

每条轨道必须提交完整 source identity、metric、unit、series semantics、严格递增 UTC timestamps、同长 values、五类 source evidence refs 和完整登记 Trend Profile。宿主登记 15 条轨道；调用方、用户或 LLM 均不能临时填写参数。

Profile 同时登记 `display_label_zh` 与 `unit_label_zh`。compact 正文只能使用这两个面向用户的名称，不能回退为 metric id 或原始 unit code。

以下情况失败关闭：错误 event/collector/publication 身份、未登记指标、跨单位或错误语义、修改 Profile、数组不同长、时间非法或乱序、负数/非安全整数、全 null、累计轨道下降、证据引用缺失。多轨分析还要求完整 source identity 与时间轴逐字段一致，且指标不得重复。

## 四、三类 series semantics

`stock` 是每个时间点的状态量，允许上升、下降和往返。中断/不可见类的登记 `semantic_role=interruption_stock`，主事实是最大值；固定可见规模的角色为 `visibility_stock`，主事实是最小值。

`cumulative` 是窗口内累计量，必须非递减。其角色为 `cumulative_new`，主事实是末值；不生成最大下降段、下降后回升或低于基线时长。

`current_supplement` 是“当前仍可见的新补充量”。它允许下降和回升，因此数值内核类似 stock，但产品含义不能写成固定 cohort 状态，也不能把当前值当累计值。其主事实是最大值。

## 五、Profile 参数语义

| 参数 | 确定含义 |
|---|---|
| `baseline_observed_points` | 从开头取 N 个非 null 值的中位数作为窗口基线。 |
| `median_filter_radius` | 同一无缺口连续段内的居中中位数半径；端点不外推。 |
| `change_threshold_absolute` | 本指标单位下的最小显著绝对变化。 |
| `change_threshold_relative_to_baseline` | `abs(baseline) × 登记比例`。 |
| `change_threshold_relative_to_observed_range` | `全窗非空极差 × 登记比例`。 |
| `gap_interval_multiplier` | 相邻时间差超过 nominal interval 的该倍数时切断连续段。 |
| `tail_observed_points` | 尾部方向使用最后一个连续段的 N 个分析点。 |
| `minimum_observed_points` | 少于该数时只报告点事实，形态为 `insufficient_data`。 |
| `cumulative_decrease_tolerance` | 累计轨道允许回退量；当前全部为 0。 |
| `isolated_spike_threshold_multiplier` | 单槽中心偏离两侧均值至少达到变化阈值的该倍数。 |
| `isolated_spike_return_tolerance_multiplier` | 尖峰两侧点差值最多为变化阈值的该倍数。 |
| `display_max_phases_per_run` | 每个连续段展示层最多 6 段；审计层不受限。 |
| `display_max_facts` | 单轨展示层最多 8 个显著事实；机器事实和 lineage 不删除。 |

最终变化阈值取绝对、基线相对、全窗极差相对三个量中的最大值。窗口基线只是当前 series 起点的确定性摘要，不是事件前正常水平或反事实基准。

## 六、通用算法

### 6.1 质量、缺口与原始精确事实

nominal interval 是全部相邻 UTC 差值的中位数。连续 null 形成 `null_run`，过大时间差形成 `implicit_time_gap`；两者都切断阶段、转折和变化段。null 不插值、不向前填充、不按 0 处理。

首末、最小/最大、净变化、最大相邻下降和最大相邻上升都基于原值。最大相邻下降只从严格 `delta<0` 的同段相邻点中选择最小 delta；最大相邻上升只从严格 `delta>0` 中选择最大 delta。`delta=0` 只是持平，不能成为任一方向事实；不存在对应方向时字段为 `null`。方向事实保留两个端点、时间、单位和 evidence。

### 6.2 单槽尖峰与持续阶段分离

stock 与 current_supplement 在连续段内用半径 1 的三点中位数建立持续形态，但原值不被覆盖。若中心槽相对两侧均值达到登记阈值，且两侧回到登记容差内，则输出独立 `isolated_spike`：方向、前/中/后点、偏离、回归差和阈值倍数都有 lineage。

因此单槽脉冲仍会出现在原始极值、最大相邻步长和尖峰事实中，但不会制造持续阶段；连续两个以上槽保持的新水平不会被误报为孤立尖峰。

### 6.3 审计阶段与聊天展示阶段

`phase_sequence` 是完整审计层。每个无缺口连续段使用固定阈值迟滞折线：沿方向更新极值，只有反向达到阈值才确认转折；所有阶段和转折按时间保留。

`display_phase_sequence` 是聊天展示层。它按相邻审计阶段的量纲内幅度、阈值比和持续时间给边界确定性排序，每个连续段最多保留 6 段，并标记 stable、gradual、abrupt、volatile 或 stepwise。展示层压缩不删除审计层，也不声称等同专家主观分段。

### 6.4 形态、变化段、时长与尾部

stock/current_supplement 可输出持平、阈值意义的单调升降、先降后升、先升后降、多阶段和数据不足。cumulative 只输出 flat/growth/insufficient。`maximum_rebound_segment` 是合同兼容字段，实际只表示最大连续数值上升，不表示恢复。

时长使用真实 UTC 毫秒差，不以点数冒充。尾部单独报告是否观测到 data-through、相对窗口基线、近期数值方向、尾部 null，并固定 `event_state_inference=forbidden`。

### 6.5 显著事实排序

排序候选固定为数据质量、末值、Profile 主事实、净变化、最大相邻升降、最大持续下降/数值上升、孤立尖峰和累计平台。排序使用固定基准分、阈值内归一幅度、时间索引和事实类型；调用方不能自由改权重。排序只决定聊天展示次序，不改变事实真值。

### 6.6 多轨同步与反向事实

多轨层在相同 identity 和时间轴内输出三类事实：

1. 同一相邻时间槽至少两轨达到各自阈值，区分数值同向和数值反向；
2. 至少两轨在同一中心槽出现孤立尖峰；
3. 登记的 cumulative/current_supplement 配对中，累计保持而当前值显著变化。

每个 evidence point 保留 metric、unit、semantic role、前后值、差值、索引和原始证据。`normalized_magnitude` 只用于排序，不跨单位求和。机器层保留全部审计事实，聊天层展示前 12 条。本轮真实回放得到 2166 条多轨审计事实和 12 条展示事实。

### 6.7 紧凑聊天输出层

`compact_chat_output` 是与完整审计结果并存的轻量层；`analyzeEventWindowTrendCompact(input)` 可直接只返回该对象。它包含登记中文 label、单位语义、1—3 句正文、结构化 exact cards、单列 limitations，以及每条 card/limitation 的 fact ids 和直接 evidence refs。现有长 `deterministic_description_zh`、阶段、时长与 lineage 原样保留供审计，不进入 compact 正文。

正文按 semantic role 固定生成：

- visibility stock：首值 → 窗口最低 → 截止或最后有效值，并说明是否数值部分回升；
- interruption stock：窗口峰值、峰值是否为单槽尖峰、截止或最后有效值；
- cumulative：累计末值、净增加、最大单槽增加和平台，不产生下降恢复措辞；
- current supplement：明确“当前可见补充量”，报告峰值和截止值，不冒充累计。

正文不得出现内部阈值、审计阶段数、转折数、毫秒、metric id、fact id、分析值或 Profile id。单位/口径和“非恢复、非原因、非真实用户影响”只放在 limitations，避免正文被边界模板淹没。

`fixed-ip-address-change-v1` bundle 只接受同一身份与时间轴的固定可见 IPv4、IPv6 两轨。IPv4 使用 unique address，IPv6 使用 `/48` equivalent，分别陈述且固定 `cross_unit_aggregation=forbidden`。

## 七、Evidence 与确定性

单轨每个可发布事实都有 `fact_id`。`fact_lineage` 记录 source point indexes、原始 evidence refs、`event-window-trend@1.2.0` 和 profile id。compact cards 与 limitations 同时内嵌对应 evidence refs，因此回答装配无需读取完整审计文件才能定位证据。多轨事实进一步列出参与轨道、每条轨道的单位内差值、单轨 fact id 与点证据。

结果不含当前时间、随机数或模型文本。同一输入完整重放逐字段相同。基准先核验 resolver、overview、series 的 13 个身份字段，再绑定三份原始回执和 Profile 注册表 SHA-256。

## 八、合成 Oracle 与测试

Oracle 完全使用合成时间和值，不含真实事件专属常量。除原有方向、阶段、缺口和多轨案例外，新增5个 compact 单轨 Oracle 与1个 bundle Oracle，覆盖 visibility 部分回升、interruption 单槽尖峰、cumulative 平台、current supplement、尾部 null 和 IPv4/IPv6 单位分离。

TypeScript 还测试 Profile label 与实现无漂移、compact 轻量入口、正文长度、必答 cards、零内部词泄漏、cards/limitations evidence、禁止跨单位 bundle，以及冻结 RRC25 全部15轨 compact 覆盖。断言均针对产品语义，不只检查字段存在。

## 十、与独立专家参考的逐项比较

候选结果仍有每轨 12 个字段槽位：unit、semantic type、总点数、有效点数、null 数、首点、末点、最小、最大、净变化、最大相邻下降、最大相邻上升，共 `15 × 12 = 180` 个槽位。但槽位不等于事实：冻结原始数据中有 150 个非方向事实和 25 个真正存在的方向步事实，另有 5 个方向不存在槽位。因此 exact fact precision/recall 的有效事实分母是 175；5 个方向不存在断言单独核对是否为 `null`。

| 候选 | 有效事实正确/非 null 提交/有效事实参考 | exact precision | exact recall | 方向不存在正确 null |
|---|---:|---:|---:|---:|
| 首版算子 | 40 / 40 / 175 | 1.000000 | 0.228571 | 未提交该字段 |
| 最终算子 1.2.0 | 175 / 175 / 175 | 1.000000 | 1.000000 | 5 / 5 |
| 独立专家直接描述 | 175 / 180 / 175 | 0.972222 | 1.000000 | 0 / 5 |

首版没有已提交精确事实错误，但只回放 4 轨且未输出最大相邻步长，所以召回有限。最终算子覆盖全部 15 轨的 175 个有效事实，并正确把 5 个不存在方向置为 null。

独立专家在 5 个不存在方向的槽位提交了 `delta=0` 的步对象：固定可见 IPv6 `/48` 的 up，以及四条 cumulative 轨道的 down。它们是可定位的 Schema 表达差异，不是原始数据中的方向事实。最终算子与专家直接字段对象只在这 5 个槽位不同，即 175/180 槽位一致；这个诊断数不得写成无条件的“180/180 精确事实”。专家文件保持原样，比较文件明确记录这 5 个对象及最终 null 表达。

专家选择的 6 个跨轨模式，第二轮机器事实可逐点覆盖 6/6，包括同槽数值反向、同步单槽尖峰、累计/当前语义分歧和同步累计台阶。这个 6/6 只是对专家已选择集合的覆盖，不把该集合当作跨轨完整性 Oracle。

### 10.1 compact 客观效果

- 单轨 compact 存在：15/15；
- 各 semantic role 必答 exact cards：60/60，全部绑定 fact ids 与 evidence refs；
- 用户可见文本内部实现词泄漏：0；bundle 泄漏：0；
- 单轨正文长度：34—84 个 Unicode 字符，平均 57.8；全部为1—3句且不超过220字；独立专家描述为38—73字、平均60字；
- fixed IPv4/IPv6 bundle：单位分离通过，不跨单位求和；
- 专家比较只记录15轨是否存在及字符长度范围，不计算文本相似度，也不判文本等价。

冻结 bundle 示例：

> IPv4 唯一地址：10,156,800→最低 9,577,728→截止值 10,069,760，较首值减少 87,040；IPv6 /48 等价量：267,292→最低 267,288→截止值 267,288，较首值减少 4。两者分轨计量，不合并。

`alignment-comparison.json` 对每轨分别列出：专家主观阶段/转折数、首版审计数、第二轮审计数、第二轮展示数，以及展示边界/转折与专家参考的集合重合。重合率不计入 exact fact precision/recall，也不标成算法正确性。

## 十一、已知差距

1. 展示边界是通用确定性压缩，仍不会逐轨复刻专家按自然日、主阶段或叙事重点选择的边界。
2. 累计轨道可靠报告精确台阶、末值和平台，但未复刻专家对增长速率时期的自然语言命名。
3. 当前补充小整数轨道会产生大量审计阶段；这是真实阈值切换的完整记录，展示层虽受控，仍可能需要产品侧按问题类型选择事实。
4. 三点中位数与尖峰规则能分离单槽脉冲，但无法仅凭轨道判断脉冲是数据异常还是真实短时控制面变化。
5. 显著事实排序是通用 Profile 规则，可能与专家针对单个事件的叙事优先级不同。
6. nominal interval 以全体相邻间隔中位数估计；采样制度高度不规则时需新增登记 Profile 版本，不能让用户临时调参。
7. 窗口基线不保证是事件前稳定期；算子不接入外部历史或反事实。
8. 多轨同步、反向或语义分歧只表示可复算的同窗数值关系，不解释原因、恢复、影响范围或责任。
9. 独立专家 Schema 没有把“方向不存在”约束为 null，因此本轮必须在外部比较层区分有效事实和零步占位；后续专家 Schema 应明确 `down.delta<0`、`up.delta>0` 或 null。
10. compact 模板能稳定覆盖角色主事实并控制长度，但仍不会复制专家按自然日、主阶段或叙事重点选择的主观阶段边界；这是保留的可读性差距，不是精确事实错误。

后续盲评若继续迭代，应冻结原始回执、当前结果和比较维度；把新发现先归类为“精确事实错误”“通用可读性缺口”“专家主观选择”或“越界叙事”，只有前两类且可用合成数据验证时才进入新算法/Profile/Oracle 版本。
