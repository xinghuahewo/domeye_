# 开发与验收流水线

本项目将日常开发、功能集成和生产发布拆成三个独立环。严格校验仍然保留，但数据库恢复、完整数据检查、Nginx 和生产切换不会进入日常开发路径。

## 项目级默认约束

日常工作默认执行以下短循环：

```text
启动 → 查看报错 → 最小修改 → 定向快速测试
```

仅在下列边界发生变化时升级为严格验收：

- 数据库裁剪、恢复、刷新、数据窗口或快照基准。
- Domeye Core 的后端、前端或 Nginx 部署切换。
- `backend/core/` 迁移基线。
- 生产 `.env`、数据库账号、Screen、端口或其他安全配置。

普通前端页面与样式、脚本解析、清单生成、文档及非生产配置问题只执行受影响测试。纯日常开发不会创建候选 PGDATA；若严格流程此前已经创建候选 PGDATA，后续此类门禁失败时必须保留 PGDATA、Overlay upperdir、状态文件和检查点，从失败门禁续跑，不得重建数据库。

数据库仅在源转储或一致性损坏、PGDATA/裁剪数据不可修复、schema 或表集合完整性无法恢复，或者数据范围与快照基准明确改变时重建。耗时长、查询慢、JQ/清单错误或后置冒烟失败本身都不是重建理由。

## 三层流水线

| 层级 | 命令 | 目标时间 | 主要内容 |
| --- | --- | ---: | --- |
| 快速开发环 | `make check-fast` | 60 秒内 | 自动识别改动风险，执行类型检查、受影响测试、核心哈希或 Shell 语法检查 |
| 集成验收环 | `make check-integration` | 10 分钟内 | 相关前后端全量契约测试、集成测试和前端生产构建 |
| 发布验收环 | `make check-release` | 30–60 分钟 | 全量本地测试、构建、核心哈希和全部发布脚本语法检查 |

`check-*` 的命令语义统一为可重复、无生产副作用。历史入口 `make check-release-full` 已改为失败关闭，不再通过名称为 `check` 的命令恢复数据库或切换线上流量。

候选准备、生产激活与回滚使用独立的 `release-prepare`、`release-activate`、`release-rollback` 命令。`full-acceptance.sh` 只接受 `release-activate` 写入状态文件的一次性令牌和父进程锁，禁止直接执行。

| 命令 | 权限与副作用 |
| --- | --- |
| `make check-release` | 全量本地只读检查，不连接生产环境 |
| `make release-prepare` | 仅发布机；恢复或复用候选数据库、构建候选前端并启动临时栈，不切生产流量 |
| `make release-activate` | 仅发布机、root、明确 release ID；复验候选后切换生产 |
| `make release-rollback` | 仅发布机、root、明确 release ID；消费三个组件回滚日志并恢复 Nginx |
| `make release-gc` | 默认 dry-run；执行时只允许清理一个明确且无引用的 release ID |

当前数据档仍是 `feb-mar-2026`，所有真正改变服务器状态的 `release-*` 操作继续失败关闭。只有未来显式切换为经评审的实时发布档，并完成严格发布验收后才能执行；`release-gc` 的 dry-run 帮助和候选检查不删除目录。

`make check-release` 本身不会连接生产数据库、修改 Nginx 或切换生产服务。

## 主干集成与制品晋级

三层检查解决代码影响面，不能代替主干整合和部署状态。生产链路固定为：

```text
短任务分支
  ↓ postflight、评审与 CI 证明
服务器端保护 Hook 快进 main
  ↓
annotated release tag
  ↓ 最终提交一次构建并冻结摘要
不可变统一候选
  ↓ 同制品晋级
金丝雀 → 生产
  ↓ 身份、接口、边界与效果验证
verified
```

普通任务 Worktree 不能运行生产激活，也不能把本地构建目录直接复制成生产制品。
发布任务从永久 `core-work` 所跟踪的 `main` 最终提交建立正式候选。后端、
Sidecar 和前端分别记录目录与源码绑定，共同绑定源码归档、Git commit、工具链、
批准配置和数据库状态。候选形成后重建任何组件都会形成新候选，不能沿用原候选的
认证或验收结论。

状态必须逐项记录：

| 状态 | 必需证据 |
| --- | --- |
| `merged` | 提交是 `main` 的祖先 |
| `built` | 不可变统一制品和摘要存在 |
| `certified` | 专项认证绑定同一制品；不适用项明确记录理由 |
| `staged` | 候选或金丝雀运行同一制品 |
| `deployed` | 生产指针和实际进程已切换 |
| `verified` | 主干、tag、源码归档、制品、进程、Nginx 和数据库身份一致，生产门禁通过 |

发布归一的身份等式、Worktree 生命周期、服务器端保护和只读归一门禁见
[主干开发与发布归一治理规范](主干开发与发布归一治理规范.md)。保护 Hook 通过只
证明 Git 引用更新合规，归一检查通过才证明它覆盖的生产身份等式成立；二者均不能
替代业务效果验收。

### 固定数据开发 API 性能预算

首页总览、国家工作台、ASN 工作台和事件 Evidence Bundle 的初始性能门槛统一记录在
`config/performance-budget.json`。预算明确区分“服务就绪后的首个样本”和后续暖态 P95；
首个样本不等同于未经预热的进程冷启动，禁止在验收报告中混用这两个概念。

通过只读 SSH 隧道或服务器本机端口测量时执行：

```bash
python3 dev/performance_budget.py --base-url http://127.0.0.1:31629
```

命令只顺序发起 GET，不修改数据库或服务状态；标准输出是可归档 JSON，任一端点超预算时
退出码为 1，请把输出、活动 release-id、数据画像和服务启动耗时一起写入开发环境验收制品。

## 发布状态与续跑

`release-prepare` 将状态原子写入：

```text
/home/bgpdata/Domeye-Core/var/releases/prepared/<release-id>/prepare-state.json
```

状态依次经过 `inputs_verified`、`database_verified`、`code_verified`、`frontend_built` 和 `prepared`。输入指纹包含发布清单、`SHA256SUMS`、数据库配置摘要、Git SHA、数据档、OpenAPI、Mock fixture、核心哈希清单、Nginx 配置及发布机 machine-id。输入不变时可以从下一门禁续跑；任一输入变化都会拒绝覆盖旧候选。

`release-activate` 还会验证：

- 当前用户为 root，当前主机名与 `RELEASE_HOST` 完全一致。
- `CONFIRM_RELEASE_ID` 与清单和候选状态完全一致。
- 数据库 `restore-state.json` 仍为 `verified`，其 SHA256 与 system identifier 未变。
- 候选前端目录树哈希未变。
- 没有其他发布命令持有全局锁。
- 切换前 Nginx 配置和运行状态已经写入候选状态，供显式回滚使用。

激活或回滚失败会保留状态并标记为 `activation_failed` 或 `rollback_failed`，不得自动猜测后续步骤。应先检查线上组件、回滚日志和进程状态，再决定恢复或隔离。

`release-gc` 会保护 active、上一回滚目标、数据库活动链接、未消费的回滚日志、锁定目录、Overlay lowerdir、容器挂载目录及保留期内候选。真正删除必须同时提供 `GC_EXECUTE=1`、单个 `GC_RELEASE_ID`、发布机主机名及相同的 `CONFIRM_RELEASE_ID`；发布制品目录不在 GC 删除范围内。

## 自动风险分级

运行 `make risk` 可以查看每个改动文件的等级和边界。开发者不需要手工选择风险。输出包含以下稳定字段：

```text
RISK_LEVEL=L3
BOUNDARY_FLAGS=db-access,migration-baseline
REQUIRED_CHECKS=check-fast,check-integration,check-release
STATEFUL_RELEASE_REQUIRED=no
```

- L0：Markdown、样式表、SVG 等文案和视觉资源。
- L1：普通 Vue 页面、组件和前端交互。
- L2：API 客户端、类型、归一化、后端服务、构建与开发工具。
- L3：数据库访问、迁移核心、部署脚本和 CI 发布配置。

风险等级到检查命令的映射固定为：

| 风险等级 | 必须执行 |
| --- | --- |
| L0 | `check-fast` |
| L1 | `check-fast` |
| L2 | `check-fast`、`check-integration` |
| L3 | `check-fast`、`check-integration`、`check-release` |

风险等级只决定代码检查范围，有状态边界单独决定是否需要候选数据库或生产发布流程。普通数据库查询代码可以是 L3 和 `db-access`，但 `STATEFUL_RELEASE_REQUIRED` 仍为 `no`；数据窗口、数据库生命周期、部署切换、生产配置、Nginx、安全配置或核心基线变化时才为 `yes`。

分类器覆盖工作区、暂存区、未跟踪文件，以及明确 merge base 后的提交差异。删除文件会参与分类，重命名同时检查旧路径和新路径；未知文件、无效 merge base 或分类器异常一律失败关闭。修改风险规则、Makefile 或 CI 规则自动升级为 L3。

## 一键开发环境

```bash
make dev
```

该命令自动选择两个未占用的本地端口，启动 Vite 热更新和固定开发快照 API，输出前端与 API 地址，并在 `Ctrl-C` 后清理临时进程。默认不读取 `.env`、不连接完整数据库、不启动 Screen 或 Nginx。启动任何 Mock、Vite 或 SSH 隧道子进程前，会显式清除 PostgreSQL、Domeye 数据库、生产后端、邮件和旧采集路径环境变量，同时保留 SSH agent 与专用开发隧道配置。

唯一数据档位于 `config/data-profile.json`。开发数据窗口固定为：

```text
2026-02-01T00:00:00+08:00 <= t < 2026-04-01T00:00:00+08:00
```

业务时区明确为 `Asia/Shanghai`，快照时钟为 `2026-03-31T23:59:59+08:00`。Vite 开发环境、Mock API、固定前端构建和部署公共入口读取或校验同一数据档，不再分别维护时间配置。现有候选数据库管理脚本及裁剪 SQL 内嵌的固定窗口属于已生成数据库的安全断言，`dev/verify_data_profile.py` 会将其反向核对到数据档；修改窗口会先失败关闭，并要求进入严格数据库验收。首页和综合特征默认查询快照前 24 小时，事件页默认查询快照前 7 天。

`feb-mar-2026` 数据档禁用本地真实 Flask 模式，以下命令会失败关闭，避免继承开发者环境中的生产库连接信息：

```bash
make dev API_MODE=real
```

服务器上的两个月真实开发库使用 [OverlayFS 开发数据库流程](../dev/database/README.md)，并通过 `DOMEYE_DATA_SNAPSHOT_TIME=2026-03-31 23:59:59` 让 Top 与仪表盘接口使用同一快照时钟。

日常前端联调真实数据使用：

```bash
make dev API_MODE=remote
```

服务器端必须先完成四文件信息制品的轻量安装，并在开发数据库处于 `verified` 且运行后启动独立 API：

```bash
cd /home/bgpdata/Domeye-Core
./dev/database/manage-dev-database.sh start
./dev/backend/stage-dev-info.sh \
  /home/bgpdata/Domeye-Core-artifacts/releases/<release-id>
./dev/backend/manage-dev-api.sh start
./dev/backend/manage-dev-api.sh health
```

API 固定使用 Screen `domeye_core_dev_api` 和 `127.0.0.1:31629`；启动验收会同时检查 `/healthz` 和固定 3 月 31 日事件查询，以确认只读数据库可查。完整服务器操作见 [服务器真实开发 API](../dev/backend/README.md)。

本地命令会自动建立 `root@10.99.8.16` 到服务器回环开发 API 的 SSH 隧道，仍使用随机本地端口，不开放远端数据库，也不在本机保存数据库密码。可通过 `DOMEYE_DEV_REMOTE_HOST` 和 `DOMEYE_DEV_REMOTE_API_PORT` 覆盖目标。

## 固定开发快照与异常场景

固定快照位于 `dev/fixtures/api-snapshot.json`，覆盖六类事件、事件详情、报文特征、路由资源和中断时序，并包含 2 月 1 日与 3 月 31 日的边界样本。Mock API 每次请求都会重新读取该文件，修改样本后无需重启服务；事件、特征及中断接口会按请求中的日期参数过滤，查询 4 月数据将得到空结果。

只读接口的机器契约位于 `contracts/openapi.json`。执行 `make api-types` 会更新 `frontend/src/types/openapi.generated.d.ts`；快速环和发布环会重新生成到临时目录并比较，防止提交的 TypeScript 类型与 OpenAPI 漂移。前端健康检查已直接使用生成类型，页面内部归一化后的视图模型仍保留在 `frontend/src/types/api.ts`。

可以一键切换四类响应：

```bash
make dev MOCK_SCENARIO=normal
make dev MOCK_SCENARIO=empty
make dev MOCK_SCENARIO=timeout
make dev MOCK_SCENARIO=error
```

`timeout` 默认延迟 3 秒，可用 `DOMEYE_MOCK_DELAY_SECONDS` 调整。

## 本地评审预览

```bash
make preview
```

该命令执行带 `VITE_COMPONENT_PREVIEW=true` 的评审构建，再用随机本地端口启动构建产物和固定 API 快照，适合提交 PR 前的本机评审。它不是普通生产构建；未注入该变量的生产构建不会注册 `/__components`。分支公网预览尚未自动启用；它需要确定 CI Runner、域名通配符、访问控制和过期清理策略，不能仅靠仓库脚本安全推断生产基础设施。

开发栈和本地预览还会开放 `/__components`，用于在不请求 API 的情况下独立检查加载、空数据、错误状态、事件表格和图表。普通生产构建不会注册该路由。

### P0 候选真实浏览器验收

`make preview` 只验证固定 Mock 快照，不能代替 P0 候选数据验收。候选验收必须先在服务器回环地址启动一个明确隔离、未生产激活的只读 API，再通过远程模式建立临时 SSH 隧道：

```bash
DOMEYE_DEV_REMOTE_HOST=root@10.99.8.16 \
DOMEYE_DEV_REMOTE_API_PORT=<隔离候选端口> \
python3 dev/run_local.py preview --api remote
```

隔离端口必须按次分配，不得写成常驻生产配置。验收至少覆盖 1440×900 与 390×844，检查 API 请求状态、控制台错误、横向溢出、固定数据档身份、`legacy_compatible` 限制和 `null` 断线。结束后必须关闭浏览器、预览进程、SSH 隧道和隔离 API，并比较既有服务监听前后完全一致；不得修改 Screen、Nginx 或发布指针。

## 缓存与全量检查

- npm 使用用户级下载缓存，uv 使用用户级依赖缓存；本地命令不会重复创建独立下载目录。
- 快速环依据文件映射选择前端或后端测试；修改 `normalize` 会运行归一化契约测试，修改事件服务会运行事件 API 契约测试。
- 全量测试保留在集成环、发布环和后续的合并前 CI 中。CI 与分支保护尚未启用前，这些仍是本地项目约束，不应描述为强制合并门禁。
- 任一日常检查超过两分钟，都应根据命令耗时输出继续拆分，而不是直接把完整数据库验收塞回快速环。
