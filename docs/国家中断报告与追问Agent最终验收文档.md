# 国家中断报告与追问 Agent 最终验收文档

版本：2.1  
状态：最终效果合同  
适用范围：Domeye 已有合法 `country_outage` 事件的 RRC25 观测报告与报告追问

## 一、文档定位

本文只设计最终效果，不规定 Node.js/Python 进程形态、工具数量、模型供应商、
数据库结构或具体实现步骤。

最终验收只有两个要点：

1. **前端**：用户是否获得一个清楚、可信、可操作的报告研读界面；
2. **报告生成逻辑**：系统是否只根据固定 Domeye 快照生成数字可信、边界正确、
   可追问和可下载的报告。

所有细节都归入这两条主线，不再建立第三套平行合同。

产品不是通用聊天机器人，也不是网络故障归因系统。“国家中断”是现有事件类型
名称；Agent 只能描述 RRC25 观察到的 BGP 控制面现象，不能据此认定全国断网、
用户或业务影响、事件原因、责任主体以及完全恢复。

## 二、前端最终效果

前端采用“技术报告研读工作台”方向：克制、高信息密度、证据可核对，不使用
通用 AI 聊天产品的外观和交互。

### FE-01：入口和上下文始终明确

- 国家中断事件页默认仍是“数据观测”，现有图表、指标和 ASN 阅读路径不被
  Agent 内容打断；
- 同一事件提供清楚的“数据观测”和“报告与追问”切换；
- “报告与追问”未生成报告时，只显示事件、国家、RRC25、窗口、`publication`、
  `revision`、`data_through`、数据门槛状态和用户触发按钮；
- 用户不能在此输入任意国家、任意时间、collector 或其他事件；
- 两个视图相互返回时，事件和快照身份不变；
- 不提供全站悬浮机器人、通用聊天入口或脱离事件的 Agent 首页。

### FE-02：报告是页面主体，不是一条聊天消息

- 宽屏以只读报告正文和追问区并列为主，正文保持适合长文阅读的行宽；
- 超宽屏可以增加章节导航；空间不足时导航收起，不压缩正文；
- 报告页头持续显示 AI 生成、未经人工审核、RRC25、窗口、`publication`、
  `revision`、`data_through`、生成时间、会话状态和下载入口；
- 正文使用清楚的标题层级、连续段落、关键数字表、证据说明和结论边界；
- 长数字、表格、ASN、时间和链接不会遮挡正文或破坏布局；
- 不使用头像气泡、紫色 AI 渐变、打字机逐字输出、token 流或模型思考过程。

### FE-03：问答是报告旁的研读记录

- 普通问题和回答以有编号的研读记录呈现，不依赖头像和左右气泡区分；
- 用户可从报告段落、关键数字、ASN 和时间点发起“就此追问”，输入区明确显示
  当前引用位置；
- 每条回答显示所用证据模式，并可展开事实、数值、时间、统计范围和快照身份；
- 事实入口可以返回“数据观测”的相应位置继续核对；
- 建议问题只根据当前快照实际可用能力出现，不暗示缺失能力已经存在；
- 阅读旧回答时，新内容不能强制把页面滚动到底部；页面提供可感知的“返回最新”
  入口；
- 快速连点、重复发送和多标签页操作不会产生互相覆盖的正式回答。

### FE-04：输入区明确显示证据模式

- 默认模式持续显示为“仅使用 Domeye 数据”；
- 输入提示只承诺回答报告数字、时间、ASN、指标含义和证据边界；
- 发送前能够识别本问题绑定的事件、RRC25 和 `revision`；
- 单独询问原因、全国断网、用户影响或后续恢复不会自动开启联网；
- 外部证据开关与发送动作处于同一可见区域，启用后使用文字和视觉双重提示；
- 当前快照不能回答的问题仍可提交，但回答必须明确说明证据不足。

### FE-05：状态、取消和失败清楚但不过度暴露

- 用户可以区分排队、读取数据、生成报告、校验、完成、失败和取消；
- 进度只显示受控阶段，不展示模型草稿、工具返回、内部提示词或思考过程；
- 用户可以安全取消；取消后页面不会稍后突然出现正式结果；
- 数据不足、快照冲突、模型失败、校验失败、外部搜索失败、PDF 失败、权限失败
  和会话到期使用不同提示，并给出可行下一步；
- 重试不会把旧错误、半成品和新结果混在同一正式报告中；
- 已经完成的报告和回答不会被后续失败覆盖。

### FE-06：短期会话和新 revision 不制造错觉

- 页面显示会话剩余时间，并在量化门槛规定的时间提醒即将到期；
- 短期有效期内，断线后能够恢复进度位置或读取最终状态；
- 到期不会截断已经开始的下载，也不会显示“正在恢复历史会话”；
- 会话清理后只提供基于当前合法快照重新生成，不承诺恢复旧问答；
- 出现新 revision 时，旧报告和旧问答保持冻结；横幅提示有新数据并提供
  “生成新版报告”入口；
- 新版报告具有不同身份，旧问答不会自动迁移。

### FE-07：外部证据与 Domeye 报告严格分区

- 只有用户显式启用外部模式后，界面才说明将访问公开网络；
- 外部内容使用独立标题和边界标识，不只依赖颜色与 Domeye 内容区分；
- 来源标题、发布方、链接、发布时间和检索时间贴近对应说法；
- 直接来源、二级来源和低等级线索在界面上可以识别；
- 来源无法读取、来源冲突或只有低等级线索时直接显示该状态；
- 外部证据不会修改、覆盖或插入 Domeye 报告正文；
- 外部链接按不可信链接处理，页面内提示词、按钮文字和脚本不能改变当前事件、
  快照、工具范围或系统指令。

### FE-08：下载结果适合长期保存

- 页面分别提供 PDF 和 Markdown 下载，并显示各自生成状态；
- 两种文件显示相同的报告制品身份，分别显示可核对的内容摘要；
- 普通问答默认不进入下载文件；
- 用户显式启用且已经完成的外部证据只进入独立附录；
- PDF 失败而 Markdown 成功时，Markdown 仍可下载，PDF 单独显示失败；
- 文件名能够识别国家、事件窗口、revision 和生成时间，不依赖会话继续存在。

### FE-09：桌面、移动端和可访问性完成同一旅程

- 桌面、平板和手机均可完成生成、取消、阅读、追问、证据展开、模式切换和下载；
- 移动端提供“报告”和“追问”两个清楚视图，切换时身份、证据模式、阅读位置和
  未发送输入不丢失；
- 键盘能够完成所有关键操作，焦点顺序、可见焦点和弹层返回位置正确；
- 读屏能够识别标题层级、状态变化、引用位置、来源和错误；
- 状态、证据模式和风险不能只通过颜色表达；
- 支持减少动态效果；缩放、长文本、长链接和中文内容下仍可使用；
- 报告、Markdown 和外部内容均按不可信富文本安全呈现，不执行脚本、事件属性
  或危险链接。

## 三、报告生成逻辑最终效果

模型只负责组织语言，不负责发明事实或自行计算关键数字。正式报告必须建立在固定
快照、确定性事实和发布前校验之上。

### RG-01：只接受合法事件和用户触发

- 只处理当前用户有权访问的已有合法 `country_outage` 事件；
- 从始至终只使用 RRC25，不设计 collector 选择、多 collector 兼容或跨 collector
  聚合；
- 报告只由用户主动触发，不自动生成或定时重写；
- 不接受任意国家、任意时间或其他事件作为临时输入；
- 超范围的通用 RCA、归因、处置、数据修改和系统操作请求被明确拒绝。

### RG-02：一份报告固定绑定一个发布快照

- 快照身份包含事件、国家、RRC25、窗口、统计人口、`publication`、`revision`、
  `data_through` 和最终性；
- 报告、关键数字、追问、外部附录、下载和审计使用同一快照身份；
- 同一批读取结果身份冲突时全部丢弃并重读，持续冲突时失败关闭；
- 不拼接不同 revision、不同统计人口或不同时间截止点的数据；
- 生成后出现新 revision 时不修改原报告，新 revision 产生一份新报告；
- 非法事件、不可发布快照和无法确认身份的输入不生成正式报告。

### RG-03：最低数据门槛和能力状态不可伪造

- 正式报告最低数据门槛包括：可识别快照、RRC25、观测窗口、统计范围、可用的
  路由可见性序列、起点、最低点、结束点和数据质量状态；
- 未达到最低门槛时不发布正式报告，外部资料、模型常识和示例数字不能补足；
- ASN、IPv4/IPv6、UPDATE、资源和正常带等扩展能力可以缺失；
- 不可用、构建中、不适用、未知、缺槽、窗口外和处理失败保持不同语义；
- 缺槽和失败不补零、不连线，也不解释成稳定、恢复、无更新或无影响；
- 非最终事件明确数据截止时间，不推断窗口之后的状态。

### RG-04：事实和派生数字可以重复核对

- 国家、时间、ASN、比例、数量、极值和持续时间都来自具有稳定标识的事实；
- 事实定位能够识别快照、指标、统计范围、观测时间和能力状态；
- 起点至最低点变化、结束差距、不可见规模、回升比例和资源变化等派生数字公开
  操作数、公式、单位、舍入和比较方向；
- 相同冻结输入重复生成时，关键数字和派生结果一致；
- 多个来源口径不能混合计算，无法闭合时标为未知；
- 来源不存在的精确数字不能进入报告；
- Prefix、Prefix×VP、ASN、UPDATE、地址等价资源、IP、用户和业务不能互换。

### RG-05：报告生成稳定的中文叙事

- 报告不是 API 字段罗列、工具调用日志、模型草稿或聊天记录；
- 标题、副标题和开头摘要直接说明观测对象、主要变化和窗口结束状态；
- 正文按以下阅读顺序组织，能力缺失时只省略对应扩展章节：
  1. 标题与一句话结论；
  2. 观测范围、RRC25、窗口与数据截止点；
  3. 最值得关注的数字；
  4. 路由可见性变化过程；
  5. ASN 影响范围与持续状态；
  6. IPv4 与 IPv6 差异；
  7. UPDATE 活动及其时间对应；
  8. 窗口结束状态；
  9. 国家级路由资源变化；
  10. 综合判断、结论与不能回答的问题。
- 专业概念首次出现时用简洁中文解释，数字和解释相邻；
- 观测事实、确定性计算和未知事项清楚区分；
- 文风可以随已认证模型变化，但事实、结论等级和未知项不能变化。

### RG-06：始终保持 BGP 控制面证据边界

- 报告只描述 RRC25 固定统计范围内的路由可见性、ASN、UPDATE 和资源变化；
- 可以表述变化广泛、持续或覆盖多个 ASN，但不能外推为全国数据面事实；
- 路由观测关系不能解释成唯一前缀、IP、用户或业务数量；
- UPDATE 活动与可见性下降时间相邻只能写为时间对应，不能自动写成因果；
- 不能仅凭 Domeye 快照认定攻击、政策行为、配置错误、基础设施故障或责任主体；
- 窗口末尾回升只能写为窗口内部分回升，不能宣告完全恢复或事件结束；
- 未知问题必须保持未知，不用模型训练记忆补充。

### RG-07：追问始终复用原报告事实合同

- 每个问题绑定报告身份、原快照、证据模式和可选的报告引用位置；
- 回答只使用原报告事实集合或同快照内允许读取的细化事实；
- 连续追问不漂移到其他事件或 revision，也不把前轮假设积累成事实；
- 新事件或新 revision 必须生成可区分的新报告，不能静默切换；
- 原快照不能回答原因、用户影响和后续恢复时，明确说明缺少什么证据；
- 建议问题只由实际可用能力生成；
- 幂等请求、并发请求和重复问题不会产生相互覆盖的正式回答。

### RG-08：项目知识替代隐藏记忆

- 基础报告可以在没有 Codex 对话、Codex 项目记忆、现成报告正文和互联网的环境
  中生成；
- 指标语义、术语解释、证据边界、报告结构和表达规范均来自可识别版本的项目知识；
- 项目知识只定义“如何解释”，不包含某个事件的现成数字和结论；
- 模型训练记忆只能辅助语言表达，不能成为事件事实来源；
- 审计能够列出一份报告实际使用的输入类别和版本。

### RG-09：外部搜索只作用户授权的独立补充

- 默认只生成 Domeye 报告；原因、影响或恢复问题本身不构成联网授权；
- 只有用户明确说出搜索、联网、公开 URL，或主动打开外部开关时才允许检索；
- 外部搜索不能替代正式报告最低数据门槛，也不能补造 Domeye 指标；
- 直接来源优先使用官方机构、运营商、测量平台和原始技术公告；有明确来源的媒体
  为二级来源；博客、论坛、社交媒体和转载只能作为线索；
- 多来源时间相符只能表述为相符；只有直接责任方的公开说明才能写成“该来源说明
  的原因”，Agent 不能据此自行确认因果；
- 只读取受控公开 HTTP/HTTPS 页面，并限制地址、重定向、响应类型、大小和数量；
- 不读取内网、本机、云元数据、登录页面、浏览器会话、Domeye 凭据和用户上传
  文件；
- 只提取所需事实、摘要和必要短引文，不复制整篇文章或大段受保护内容。

### RG-10：模型与 API 差异不改变正式结果

- 正式报告记录供应方、模型、模型版本、报告规范和项目知识版本；
- 候选模型必须通过同一事实、语义、安全和阅读效果验收后才能发布；
- 必要的结构化交互、上下文容量、中止、超时和错误语义必须通过验收；
- 已认证模型之间允许措辞不同，但关键数字、事实范围、结论等级和未知项一致；
- 首选模型失败时，只能由已认证备用模型重新生成完整报告或完整回答；
- 不拼接不同模型的部分输出；没有合格备用时明确失败；
- 模型版本无痕变化不进入正式能力，版本变化触发重新验收。

### RG-11：运行、缓存、权限和只读边界稳定

- 相同事件快照、报告规范和模型版本可以在短期窗口复用同一标准基础报告；
- 每个用户的普通问答、外部检索词、来源和临时状态保持隔离；
- 生成、追问、外部搜索和下载继承当前事件访问权限；
- 无事件访问权的用户不能通过报告标识、缓存键、临时会话或下载地址旁路读取；
- 排队、并发、幂等、重试、超时和频率限制具有确定结果；
- 超大问题、异常分页、超大事实量和外部内容不会扩大范围或拖垮正式运行；
- Agent 不能执行 Shell、编辑文件、读取任意路径、执行 SQL、修改 Domeye 数据、
  使用数据库凭据、切换系统指令或任意会话；
- 报告、Markdown 和外部内容中的提示注入不能改变事件、快照或工具权限；
- 日志和审计不泄露密钥、凭据和不必要的敏感提示内容。

### RG-12：机器校验和失败关闭决定是否发布

- 正式发布前校验快照一致性、关键数字、派生公式、事实来源、章节能力和语义边界；
- 接口身份冲突时整批重取，持续冲突时停止，不跨批拼接；
- 校验可以产生受控的整份修订，但不能把连续自我重试表现为多个正式版本；
- 机器校验通过后一次性发布只读报告，并标记 AI 生成、未经人工审核；
- 校验失败、模型失败或取消时不发布草稿、工具返回、局部文本和思考过程；
- PDF 和 Markdown 来自同一通过校验的报告制品，屏幕正文使用同一事实集合；
- 两种文件共享制品身份并分别计算内容摘要；
- PDF 中文字体、标题层级、表格、长链接、分页、页眉页脚和引用完整，不出现
  截断、越界、空白页或缺字；
- Markdown 保持完整标题、表格、证据说明和链接语义；
- 普通问答不进入默认下载；已完成的外部证据只进入独立附录。

### RG-13：结果可以脱离当前开发环境复现和审计

- 报告身份包含事件快照、事实集合、项目知识、报告规范、模型和校验规则版本；
- 干净环境重放不依赖 Codex 记忆、现成正文和默认互联网；
- 相同冻结输入能够重新生成事实等价的报告；
- 审计结果列出使用事实、派生计算、不可用能力、无法回答项、模型和校验结果；
- 结构检查、单元测试、一次模型成功调用或候选环境不能替代完整用户旅程验收。

## 四、联合验收

前端和报告生成逻辑必须一起通过。后端结果正确但界面不可读，或界面漂亮但报告事实
不可信，均判定为不通过。

### 4.1 必须冻结的量化门槛

实现前必须形成版本化验收配置，至少冻结：

- 会话有效期、到期提醒、临时报告、问答、外部内容、下载文件和日志留存；
- 排队、首个状态、报告、追问、外部检索、模型备用和 PDF 超时；
- 单用户问题数、并发运行数、队列长度、重试次数和频率限制；
- 单次事实量、上下文量、回答长度、外部页面数量、大小和重定向次数；
- PDF 最大页数、文件大小、生成时限和 Markdown 大小；
- 桌面、平板、手机验收视口及浏览器版本；
- 事件访问角色、共享报告缓存范围、下载授权和跨用户隔离矩阵。

未冻结、验收时临时修改或只写“合理值”，均不能通过最终验收。

### 4.2 端到端场景

| 编号 | 场景 | 通过结果 |
|---|---|---|
| SCE-01 | 合法事件正常生成 | 前端发布面向人的只读报告，数字和快照可追溯 |
| SCE-02 | 最低数据不足或扩展能力缺失 | 前者不发布正式报告，后者只降级对应章节和问题入口 |
| SCE-03 | 生成中 revision 变化或接口身份冲突 | 整批重读或失败，不混合快照，旧报告不被改写 |
| SCE-04 | 连续追问、就此追问和越界问题 | 回答固定在原快照，越界部分明确证据不足 |
| SCE-05 | 用户显式开启外部搜索 | 独立展示逐项引用、来源分级的外部证据补充 |
| SCE-06 | 未授权原因问题、恶意 URL 或提示注入 | 不联网、不越权、不执行页面内指令 |
| SCE-07 | 首选模型失败或模型版本变化 | 已认证备用完整重生成，或明确失败并重新验收 |
| SCE-08 | 取消、重复请求、断线、到期和新 revision | 无半成品和重复结果，旧报告冻结，状态和下一步清楚 |
| SCE-09 | PDF 或 Markdown 单项失败 | 成功格式仍可下载，失败格式单独标明，制品身份可核对 |
| SCE-10 | 桌面、平板、手机、键盘、读屏和跨用户访问 | 完整旅程可完成，内容不越界，状态不只依赖颜色 |

### 4.3 最终判定

- **通过**：FE-01 至 FE-09、RG-01 至 RG-13 和 SCE-01 至 SCE-10 全部有证据通过；
- **有条件通过**：仅存在书面批准、不会破坏事实、安全、阅读和下载的限期项；
- **不通过**：任一到期要求失败、证据不足、发生越界或依赖当前 Codex 环境；
- **未知**：未执行或证据无法复核，不能写成通过。

最终结论必须记录验收配置版本、事件与快照、模型组合、环境、执行时间、失败项和
证据位置。生产发布、历史数据改写和其他事件类型扩展不属于本文授权范围。
