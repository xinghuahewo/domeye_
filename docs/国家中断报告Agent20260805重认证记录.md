## 三、原因与修正

原协议只要求模型先调用 `country_outage_resolve` 和
`country_outage_get_observation`，并在两项结果齐备后强制 JSON 输出；工具阶段仍
允许可变模型自行选择工具，因此模型重复调用或误调用 ASN 时会触发冻结次数门。
门禁按设计失败关闭，但认证成功依赖模型偶然遵循提示，不具备足够确定性。

第一次修正不放宽任何工具、结果字节、供应商请求或 token 上限，而是在最终 payload
发送前由宿主强制执行三阶段协议：

1. 第一轮 `tool_choice` 固定为 `country_outage_resolve`；
2. resolve 成功后固定为 `country_outage_get_observation`；
3. 两项结果齐备后固定 `tool_choice=none`，并要求 JSON object 语言槽输出。

这样保留 Pi 工具调用和审计，同时把事实读取顺序从提示建议改为确定性协议。

第二次失败说明，即使工具顺序已经确定，叙述层仍不应依赖可变模型完成工具协议。
当前离线修正改为：宿主先完成事实读取、验证和语言槽计划冻结；DeepSeek 只接收
该计划进行受控自然语言渲染。正式 Pi 会话使用 `noTools=all`、`tools=[]`、
`customTools=[]`；每轮最终 payload 都强制 `tool_choice=none` 和
`response_format=json_object`。首轮不合格时最多允许一次整包修复，因此每份报告
最多两次 provider 请求。
