## 3. 当前数据库身份

### 3.1 已确认

- 固定开发数据库是基础发布 `20260717T124354Z` 的 Overlay 派生库。
- `state.json` 状态为 `verified`，固定窗口为二月和三月。
- 数据库只监听服务器回环地址 `127.0.0.1:31627`。
- `public` schema 当前有 37 张表，37 张表均有主键。
- `domeye_core_reader` 配置了 `transaction_read_only=on`。
- 最终 live probe 的全部 SQL 在同一个 `REPEATABLE READ READ ONLY` 事务中以 `domeye_core_reader` 权限执行，结束后回滚。
- live probe 查询时间为 `2026-07-20T12:24:50Z` 至 `2026-07-20T12:27:59Z`。
- 37 张表合计 90,663,138 行；逐表行数、最早/最晚时间、逐列 NULL/空字符串/空集合/零值、主键、索引及 canonical schema SHA256 均已进入机器基线。

### 3.2 基础发布 inventory 不能代替当前基线

基础发布的 `database-inventory.json` 有 109 张表，数据延伸至 2026 年 7 月；例如 `feature_country.max_time=2026-07-17 20:35:00`。当前开发 Overlay 已裁成二月和三月 37 张表。

因此：

- 基础发布 inventory 只能用于证明裁剪来源和 release 血缘；
- 当前 P0 表数量、行数、时间边界、空值和引用一致性必须实时查询固定 Overlay；
- 不得筛选基础发布 inventory 后冒充当前二三月数据库 inventory；
- 现有 inventory 的 32 位 `schema_hash` 是 MD5，不得描述为 SHA256。

### 3.3 live 基线结论

机器基线对 37 张目标表逐一复核后确认：

- 必需表集合精确为 37 张，无缺表和多表；
- 固定窗口外记录数为 0；
- 37 张表均有有效主键，主键保证的重复额外行数为 0；
- 每张表均生成不包含 TimescaleDB 物理 chunk 名和 `num_chunks` 的逻辑 schema SHA256；
- 基础发布 inventory 仅以 `usage=source_provenance_only` 进入基线，不提供当前行数或时间边界；

### 4.1 阶段字段解释

- “字段非空且非空集合”仅证明事实表保留了路径快照，不证明 VP 身份仍在。
- AS 中断的 `next_vp_paths` 在二三月全部为空集合，不能描述为“异常后已恢复”或“异常后没有路径”。
- 前缀中断的 14,773 条空 `next_vp_paths` 与缺结束时间数量相同，需要在规范化时标记为未结束事件的后阶段不可用。
- 前缀劫持的 `next_vp_paths IS NULL` 与缺结束时间数量相同，当前 API 会把 NULL 和空集合折叠，需要在 D2 分离缺失语义。
- 子前缀劫持和国家中断没有物理阶段字段，不能将缺失解释成该阶段“没有路径”。
- 路由泄漏只有事件中 AS_PATH，没有结束时间、持续时间和前后阶段。

### 4.2 `leak_vp` 实际值域

二三月 63,281 条路由泄漏记录的 `leak_vp` 全部非空，共 47 个不同值，全部是纯数字 ASN 字符串。

该字段只能暂时解释为“观测者 ASN token”：

- 它没有保留 peer IP；
- 同一 ASN 可能对应多个观测会话；
- 详情服务和当前 Evidence Bundle 没有暴露该字段；
- 它不能直接提升为稳定 `vp_id`。

### 4.4 指标单位与稀疏表语义

代码和实库联合审计确认：

- `v4Prefix_num` 是 IPv4 `/24` 等效段，不是原始 IPv4 前缀条数；
- `v6Prefix_num` 是 IPv6 `/48` 等效段，不是原始 IPv6 前缀条数；
- `v4IP_num = v4Prefix_num × 256`，全窗口未发现违反该关系的记录；
- 11 类 ASN 月表只在 ASN 发生路由变化时落行，是活动稀疏表；
- ASN 表没有 `announce + withdraw = 0` 的落库行；
- `sample_count` 是实体活动槽数，不是采集源覆盖槽数；
- `/24` 和 `/48` 等效变化不能直接比较大小，当前 `resource_change=max(abs(v4_delta), abs(v6_delta))` 没有有效的统一物理单位。

因此 P0 必须将一个模糊的 `sample_count` 拆为：

- `expected_sample_count`：服务端按半开窗口计算的期望源槽数；
- `source_observed_sample_count`：采集源实际存在的槽数；
- `subject_active_sample_count`：国家或 ASN 实际有活动的槽数；
- `activity_density`：实体活动槽数除以源已观测槽数，不能命名为覆盖率。

### 4.5 当前指标实现中的缺失补零风险

当前后端、API 和前端存在多处语义折叠：

- 撤回率分母为 0 时返回 `0.0`，把“不可计算”表示成“没有撤回”；
- 上一窗口无样本时，部分聚合先 `COALESCE` 为 0；
- outage 查询把分区不存在、查询失败和真实并发为 0 返回成同一零序列；
- 前端归一化把部分空值回退成 0；
- 前端曾按闭区间将 24 小时五分钟槽计算成 289，而半开窗口应为 288；
- 缺失时间点没有统一插入 `value=null`，折线可能跨越缺口直接连接。

这些问题不一定改变底层事实表，但会改变用户看到的数据含义，必须在 MetricSeries 和前端数据准入前修复。

### 5.2 已冻结的两组数据缺陷

#### 5.2.1 劫持事实主键复用与状态混合

以下两个总表事件复用了同一个事实 locator：

```text
hijack/2026-03-04 19:35:43/80.244.11.0-24/1/r
hijack/2026-03-20 14:11:03/80.244.11.0-24/1/r
```

对应事实主键均为：

```text
source=r, prefix=80.244.11.0/24, hijack_eventid=1
```

事实行不是两个独立快照：其 `s_time` 和劫持双方仍对应 3 月 4 日事件，但 `e_time=2026-03-20 18:29:00`、`duration=4:17:57` 和异常后路径来自 3 月 20 日事件。这证明该事实行发生了主键复用/可变状态混合，不能把它完整归属给任一 Incident。

D2 处理结论：保留两个总表 Incident，建立同一 `legacy_collision_group`，冲突字段标记 `legacy_unknown`/`source_fact_collision`，不从混合事实行生成未经限定的阶段结论。D3 处理结论：两天均位于现存 3 月 MRT 覆盖内，使用原始旁路索引尝试分别重建可复核 RouteEvent；仍不得回写原事实表。

#### 5.2.2 空国家反向孤儿与窗口污染

`country_outage_202603` 存在一条反向孤儿：

```text
source=r, country='', outage_id=1, s_time=2026-03-10 16:24:31
```

该行没有总表引用，国家代码和中文名均为空；其 `event_info` 却描述“北京时间 2026-04-26 00:24:38”，超出固定二三月窗口。它不能作为“未知国家中断”正常展示。

D2 处理结论：进入只读 quarantine，缺失原因标记为 `invalid_identity` 与 `legacy_window_contamination`，不生成可见 Incident；对账中作为“已解释孤儿”单独计数，原记录继续保留。

尚待 D2/D4 完成的证明包括：总表与事实表结束时间、持续时间和风险字段的一致性，以及 Incident、RouteEvent 与原始引用之间的稳定关联。

### 5.3 前缀中断结构性风险

`prefix_outage_YYYYMM` 原生主键是：

```text
source + prefix + outage_id + asn
```

当前 `detail_url` 和详情查询只使用：

```text
source + prefix + outage_id
```

实库抽样对整个二三月窗口执行分组后，当前没有发现重复 locator 组，重复额外行数为 0。因此当前窗口未触发实际歧义，但合同仍不完整：未来数据出现同一 locator 下多个 ASN 时，现有服务会静默取第一行。D2 必须补充 ASN locator 或明确一对多 Incident 语义。

### 5.4 outage 原生 ASN 集合键

全量 D2 首次执行补充发现：`prefix_outage_202603` 有 17 行、
`as_outage_202603` 有 11 行把 text 类型的 `asn` 原生键保存为
`{asn,...}`；二月对应计数均为 0。11 条 AS 中断总表 `detail_url` 也使用
同样的花括号 problem。这不是一个 ASN 字符串，而是聚合事件中的 ASN 集合。

D2 处理结论：原生键逐成员执行 32 位 ASN 校验并保留集合键身份；生成影响
对象时展开成多个 ASN，禁止把整个 `{asn,...}` 合成为虚构 ASN，也不将其
隔离为普通非法值。无法逐成员校验或包含重复成员的集合仍失败关闭。
