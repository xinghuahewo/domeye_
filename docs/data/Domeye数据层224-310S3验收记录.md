## 一、固定范围与阶段边界

- collector：`rrc25`；
- 源窗口：`[2026-02-24T00:00:00Z, 2026-03-11T00:00:00Z)`；
- 状态点：`2026-02-24T00:05:00Z` 至 `2026-03-11T00:00:00Z`，共 4,320 个；
- 国家桶：240 个 mapping 国家加显式 unknown，共 241 个；
- 本阶段只闭合国家、ASN、collector 五分钟指标、分层存储、质量、双水位和独立
  候选库；不生成事件、Publication、Prefix×VP Evidence、API 或报告，不切换运行时。

逻辑数据流固定为：

```text
S1 不可变 RouteEvent
  ↓ 按严格顺序提交
S2 唯一 RouteState
  Key = collector + VP/peer + prefix + address_family
  ↓ 同一 ApplyWithTransition 的已提交前后值
S3 确定性指标投影器
  ├─ country 5m（稠密）
  ├─ ASN 5m（首槽快照 + 变化点）
  └─ collector 5m（稠密）
       ↓
不可变日分区装载文件
       ↓ 完整验真后 create-only
独立 PostgreSQL/TimescaleDB 候选库
```

Prefix×VP 只是 RouteState 主键的高基数维度。S3 没有建立平级 Prefix×VP 事实、
第二套 RouteState 或 Prefix×VP Evidence。固定 cohort 只保存 Seed key 与 Seed origin
的不变维度，不能独立推进可见性；所有当前值都由唯一 RouteState 转移维护。

## 三、统一指标语义

### 3.1 主体与物理编码

- country：241 个主体每槽稠密写入；行缺失表示数据缺失，不是零；
- collector：`rrc25` 每槽稠密写入；
- ASN：第一个可观测槽写状态快照，之后只写状态变化或有流量的变化点；在
  `metric_slot_5m` 存在且质量 complete 的槽中，状态列向前承载，无变化点的
  announcement/withdrawal 列是已观测真实零；
- 国家、ASN 和 collector 共用 UTC `timestamptz`、同一 dataset、projection、mapping、
  RouteState 身份和双水位。

### 3.2 数值定义

| 字段组 | 确定性定义 |
|---|---|
| `baseline_route_state_count_v4/v6` | 按 Seed origin 和地址族分组的固定 RouteState key 人口 |
| `cohort_visible_route_state_count_v4/v6` | Seed key 当前可见且 origin 与 Seed 一致的人口 |
| `current_visible_route_state_count_v4/v6` | 按当前 RouteState origin 和地址族分组的可见人口 |
| `announcement_count_v4/v6` | 本槽已提交 RouteState 转移中的宣告数 |
| `withdrawal_count_v4/v6` | 本槽已提交 RouteState 转移中的撤回数；优先归属撤回前 origin |
| `cohort_visibility_state_v4/v6` | 分母大于零为 `observed`，分母为零为 `not_applicable` |

显式整数 0 是真实零；`not_applicable` 不是 0；缺少合法 `metric_slot_5m` 是 missing，
不允许用 0 补齐。unknown 作为显式国家桶参与 country/collector 人口守恒，不会被
丢弃或猜测补全。机器合同为
[`rrc25-metric-store.schema.json`](../../contracts/data/rrc25-metric-store.schema.json)。

## 四、文件层与在线层职责

| 层 | S3 存储内容 | 权威性 |
|---|---|---|
| 不可变文件证据层 | 原始 MRT、完整 RouteEvent、唯一 RouteState 及 Checkpoint、S3 日分区装载文件 | RouteState 逻辑事实只有一套；S3 文件是可验真的装载候选 |
| PostgreSQL 身份/质量层 | candidate、dataset、evidence object、metric subject、槽质量、gap、load receipt | 用 ID + SHA-256 定位文件对象，禁止只存路径 |
| TimescaleDB 统一时序层 | `route_metric_5m` 中的 country/ASN/collector 指标 | 一张统一 hypertable，不按国家或月份增殖表 |
| PostgreSQL 事务层 | S4 后才建立的事件、Publication、current 指针和报告快照 | S3 不提前实现或宣告通过 |

装载器拒绝数据库名 `bgp_project`；目标库必须事前不存在。文件、来源 manifest、
行数、守恒和 4,320 点查询全部通过前，candidate 保持 `loading`；只在同一事务中
改为 `complete` 并写入 load receipt。S3 不建立 current 指针，因此候选库不会被
运行时自动选中。

## 六、双水位、质量与失败关闭

- `attempted_through` 在系统开始处理某槽时前移；
- `data_through` 只在当日 country、ASN、collector 和 slot 四个文件全部 flush、`fsync`、
  重算 SHA-256 并原子改名后前移；
- 每槽与 S2 正式槽账本逐字段对比，包括来源 RouteEvent 文件摘要、转移摘要、
  RouteState 记录数、可见数、状态摘要和双水位；
- 每槽恰有 241 条 country 和 1 条 collector；country 求和等于 collector，collector
  当前可见数和流量等于 RouteState/槽账本；数据库 gap=0，三类守恒 mismatch 均为 0。

正式失败演练均为关闭失败：

- 篡改首个 country 文件后，装载器以“压缩身份不匹配”退出 1，未创建数据库、未写回执；
- 缺少首个 country 文件后，装载器以“文件不是普通文件”退出 1，未创建数据库、未写回执；
- 指向旧 `bgp_project` 被显式拒绝，旧库 166 张表及 schema 指纹
  `1b823a9a236f416f6142fc773076f014e1403c243e0b33e3d6a7c39655e88af9`
  前后一致；
- 对已存在候选库再次装载，在完成文件验真后以 create-only 冲突退出 1，没有新回执；
- CoW reflink 不受远端文件系统支持，保留了隔离演练目录
  `tampered-candidate-reflink-unsupported`；正式候选从未被改写。

### 6.1 装载中发现并修正的两项缺陷

第一次完整装载使用提交 `70030e0`，在装完数据后因证据对象 INSERT 列映射遗漏
`content_sha256` 而触发 `integrity_status` 非空约束，退出 1。失败库
`domeye_dl_s3_70030e0_4523a27b` 保留为 `failed`，没有回执。提交 `4b86b7f` 改为显式列名
和九个值并增加回归测试，随后完整装载成功。

第二次成功装载暴露外部 JSON 回执的规范化顺序缺陷：计算哈希时使用插入顺序，落盘却
使用 `sort_keys=True`，旧回执声明的 `f0722d3a…` 无法由落盘内容复算。旧无效回执和
验证失败日志均保留。提交 `47e38a7` 引入统一的 sorted canonical bytes 并增加回归测试；
更正回执复算得到 `de55682b…`，语义字段与库内 load receipt 完全一致。为避免只用
纸面更正封口，本记录最终只认 `47e38a7` 再次 create-only 全量装载产生的新库与新回执。

### 6.2 验收取证纠错

以下错误只发生在旁路取证命令，不改变候选数据；原错误日志和更正日志同时保留：

- 第一次取旧库表数时把 `bgp_project` 放成额外参数，`psql` 报警并返回 `postgres` 的
  45 张表；使用 `-d bgp_project` 更正后为 166，schema 指纹前后一致；
- 第一次最终 Go 验证误把仅含 Python 装载器的构建目录当作 Go module，并未给
  `gofmt` 绝对路径；在冻结的 `70030e0` Go 源码构建目录重跑后，`-count=1`、`-race`、
  `vet`、`gofmt` 全部通过；
- 第一次最终 Schema 验证调用系统 `jsonschema 3.2.0`，该版本不支持 Draft 2020-12；
  在隔离 venv 固定 `jsonschema 4.25.1` 后，Schema 自检和同一 manifest 实例校验均通过。

最终构建的四个 SOURCE SHA-256 全部复核通过，Python 装载器三个回归测试通过；
`backend/core` 的 14 个冻结摘要全部一致。

## 八、阶段结论与限制

S3 阶段入口、出口和 DLAE-05 至 DLAE-07 已由同一候选身份的文件、数据库、查询、
失败演练和恢复性证据闭合。当前结论等待验收记录提交后执行
`.codex/hooks/data_layer_224_310_review.py --stage S3` 做最后防偏离回读；Hook 通过前
不进入 S4。

即使 S3 通过，也只说明统一指标、分层存储、质量和双水位已完成，不说明：

- S4 事件生命周期、Observation/Analysis Publication、revision 或订正已完成；
- S5 API、Prefix×VP Evidence、页面性能或报告快照已完成；
- S6 旧库影子迁移、权限、回退、候选切换或生产效果已完成；
- RRC25 控制面观测能够证明全国断网、用户影响、原因、攻击、责任或完全恢复。
