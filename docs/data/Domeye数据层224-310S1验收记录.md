## 一、固定范围

- collector：`rrc25`；
- 源窗口：`[2026-02-24T00:00:00Z, 2026-03-11T00:00:00Z)`；
- 输入：1 个 `bview.20260224.0000.gz`、4,320 个五分钟 UPDATE、2 个隔离修复
  artifact；
- 本阶段只到 RouteEvent，不产生 RouteState、指标、事件、Publication、API 或报告。

## 二、逻辑边界

```text
原始 RRC25 MRT
  ├─→ raw MRT record sidecar
  ├─→ 完整 RouteEvent
  └─→ 内容寻址 AS_PATH 字典

S2 才会：RouteEvent → RouteState（Prefix×VP 状态）
```

S1 不建立 Prefix×VP 事实库。Prefix×VP 只是 S2 RouteState 的主键维度；
Checkpoint 只能是同一 RouteState 的快照；Prefix×VP Evidence 只能在 S5 从指定
RouteState/Publication 派生。

## 三、候选实现效果

1. 输入文件只读打开，解析时流式重算压缩字节数和 SHA-256；
   逻辑源根固定为 `domeye://raw/rrc25-global-20260224-20260310-v1`，与 artifact
   `relative_path` 组合成稳定 URI；只有完整校验后才保存
   `input_integrity_status=gzip_passed_and_stream_sha256_verified`；
2. 每个物理 MRT record 保存 ordinal、解压偏移、header+payload 总长度、
   type/subtype 和 record SHA-256；
3. 每个逻辑元素保存由文件 SHA-256、record ordinal 和 element ordinal 确定的
   稳定 RouteEvent ID；
4. RouteEvent 保存 VP peer IP/ASN、prefix、地址族、动作、时间、origin、
   AS_PATH 引用、属性 SHA-256、原始坐标、质量标记和缺失理由；
5. AS_PATH 保留 AS_SEQUENCE、AS_SET、AS_CONFED_SEQUENCE 和 AS_CONFED_SET，
   AS4_PATH 按 RFC 6793 重建，不以 origin 代替完整路径；
6. 同一 artifact 的三类 gzip JSONL 以固定 gzip header 生成，分区级清单绑定行数、
   字节数、文件 SHA-256、artifact role、各类人口、解析告警人口和内容摘要；全局
   内容身份继续绑定窗口、来源、实现、修复血缘、聚合人口与全部分区身份；
7. `ingest_time_utc` 和 `parse_time_utc` 保存在分区清单，逻辑 RouteEvent
   由全局清单、分区清单、事件行、AS_PATH 字典和 record sidecar 确定性组合；
   操作时间不进入语义 content SHA；
8. `--resume` 只复用逐文件大小和 SHA-256 重算一致的已完成分区；任一篡改
   都失败关闭；同一输出目录通过独占写锁拒绝并发写入；完成态 `manifest.json`
   与 `COMPLETE.json` 必须逐字一致，任一副本漂移都失败关闭；
9. 输出根目录逐字保存 `input-selection.json`；全局清单明确保存两个损坏原文件
   与隔离替换 artifact 的大小、SHA-256、完整性状态和不可覆盖关系，修复血缘摘要
   同时进入 import run 身份与全局内容身份；
10. 命令必须接收 `git:<40位提交SHA>` 实现身份；该身份同时绑定 preflight、
    import run、RUNNING 标记和最终清单，续跑不能混入另一份实现代码；
11. 独立审计器先以完成态续跑重算全部分区文件 SHA-256，再确定性选取 100 个
    UPDATE artifact 回到冻结 gzip 逐元素复算；两个修复 artifact 和 withdraw 均为
    强制样本，审计器自身另有 Git 身份与内容摘要。

机器合同为
[`rrc25-route-event-store.schema.json`](../../contracts/data/rrc25-route-event-store.schema.json)。
