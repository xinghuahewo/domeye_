# P0 数据字典

## 1. 文档身份与适用范围

| 项目 | 值 |
| --- | --- |
| 字典版本 | `p0_data_dictionary_v1` |
| 数据档 | `feb-mar-2026` |
| 固定窗口 | `2026-02-01T00:00:00+08:00 <= t < 2026-04-01T00:00:00+08:00` |
| 业务时区 | `Asia/Shanghai` |
| 机器时间 | UTC RFC 3339 秒级时间 |
| 结论等级 | 仅 `observation_only` |
| 当前历史数据等级 | `passed / legacy_compatible` 候选准入；未生产激活 |
| 全窗口原始追溯 | 未达到；UPDATE 制品存在率 60.45%，容器完整性准入率 60.25% |

本字典是 P0 事件、指标、实体、RouteEvent、Evidence 和数据质量字段的统一语义来源。对应机器合同位于 `contracts/data/`。OpenAPI 或前端类型只能引用或投影这些语义，不能重新定义同名字段。

D1 已于 2026-07-20 初次冻结，并于 2026-07-21 随最终 `parse_failed`、质量门禁和时间异常语义显式再冻结：4 个 JSON Schema 在 AJV `strict=true` 下编译通过，10 个正例通过、17 个反例被拒绝，31 个合同 JSON 文件通过重复键与非有限数值检查。复核入口为 `python3 dev/verify_p0_contracts.py`，当前冻结哈希见 `docs/data/P0-D1-SHA256SUMS`；初次与最终文件身份不同，不能混称为同一冻结版本。

## 2. 全局规则

### 2.1 命名与结构

- JSON 字段统一使用 `snake_case`。
- 标识符即使内容为 ASN 或数字，也使用字符串；计数和序号使用整数。
- 所有业务对象都必须携带 `schema_version` 或明确的合同版本常量。
- 机器合同默认 `additionalProperties=false`；历史事实原文只能放入显式的 `legacy_payload` 或原始引用，不得让未知字段静默进入规范对象。
- 数据库 `timestamp without time zone` 只在读取边界按 `Asia/Shanghai` 解释；规范对象只存 UTC RFC 3339 时间，必要时另存 `source_timezone=Asia/Shanghai`。
- 时间窗口统一采用半开区间 `[window_start, window_end_exclusive)`。
- 所有列表在进入稳定 ID 前按合同规定规范化；禁止依赖数据库返回顺序或 Python 集合顺序。

### 2.2 缺失、零值与不可计算

`null` 不是 0。每个可能缺失的观测值必须同时有 `value_state`，需要解释时必须有 `missing_reason`。

| `value_state` | 含义 | `value` |
| --- | --- | --- |
| `observed_nonzero` | 已观测且值非 0 | 必须为数字且非 0 |
| `observed_zero` | 来源完整、查询成功且值确实为 0 | 必须为数字 0 |
| `not_observed` | 目标时点没有取得样本 | 必须为 `null` |
| `source_unavailable` | 对应原始源文件不可用 | 必须为 `null` |
| `processing_gap` | 原始源存在，但派生处理未落出结果 | 必须为 `null` |
| `parse_failed` | 期望槽的源制品已发现，但未通过容器完整性或语义解析准入；具体原因由 `missing_reason` 继续区分 | 必须为 `null` |
| `not_retained` | 历史处理未保留字段 | 必须为 `null` |
| `not_applicable` | 此事件或指标不适用 | 必须为 `null` |
| `legacy_unknown` | 历史数据无法区分缺失原因 | 必须为 `null` |
| `invalid_identity` | 实体身份非法，记录进入 quarantine | 必须为 `null` |
| `legacy_window_contamination` | 内容与固定窗口冲突 | 必须为 `null` |
| `source_fact_collision` | 多个 Incident 复用并污染同一事实主键 | 必须为 `null` |

撤回率等派生指标分母为 0 时是“不可计算”，返回 `null` 与明确原因，禁止返回虚假的 `0%`。查询异常、缺分区、无权限和超时也不能伪装成 `observed_zero`。

### 2.3 观测与因果边界

- `classification` 固定为 `observation_only`。
- `causal_conclusion` 固定为 `null`。
- AS_PATH、阶段路径和 Route Observation 均为特定来源保留的路径快照，不是数据包转发路径、传播顺序或根因证据。
- 可以返回支持当前观测描述的证据、反向证据、覆盖缺口和限制；不得自动生成“全网传播”“根因已证实”“已经全网恢复”等结论。

### 2.4 历史结束时间逆序

源事实中若出现 `end_time < start_time`，规范化层不得交换时间、取绝对值、把持续时间改为 0，或把仍可定位的事件整体隐藏。统一处理为：

- `end_time_utc=null`；
- `duration_seconds=null`；
- `field_quality` 对结束时间和持续时间记录 `value_state=legacy_unknown` 与内部原因 `end_before_start`；
- 对外事件与指标投影保留 `missing_reason=legacy_unknown`，并在限制或逐字段质量中保留逆序事实；
- 指标生成器可使用 `end_time_explicitly_unavailable`、`nonpositive_outage_interval` 等内部对账原因，但不得将其投影为 0 时长或正常恢复。

本轮共识别 12 条历史逆序记录（前缀中断 9 条、AS 中断 3 条），最终 D2 候选的规范时间逆序计数为 0；这表示异常已被显式转为未知，不表示源事实被修复或事件已经恢复。

## 3. 稳定 ID

### 3.1 规范 JSON

所有 v1 稳定 ID 使用 UTF-8 编码的规范 JSON：对象键按 Unicode 码点排序、无多余空白、分隔符为 `,` 和 `:`、布尔值与 `null` 使用 JSON 原生表示。生成过程为：

```text
digest = SHA256(canonical_json(identity))
id = prefix + digest 的前 N 个十六进制字符
```

任何改变 identity 字段集合、规范化规则或截断长度的行为都必须升级 ID schema，不能继续使用 v1 名称。

### 3.2 `incident_id_v1`

现有规则冻结，不得重解释：

```json
{
  "schema": "incident_id_v1",
  "event_type": "hijack | sub_hijack | leak | prefix_outage | as_outage | country_outage",
  "start_time": "数据库业务时间 YYYY-MM-DD HH:MM:SS",
  "problem": "detail_url 第三段的原始规范字符串",
  "event_id": 1,
  "source": "r"
}
```

输出为 `inc_v1_` 加 SHA256 前 24 个十六进制字符。`problem` 对前缀事件沿用 locator 中 `/` 转 `-` 的形式。D0 发现的两个劫持事件因 `start_time` 不同，必须保留两个不同 Incident ID，即使它们碰撞到同一事实主键。

### 3.3 `route_event_id_v1`

RouteEvent 身份只由不可变原始坐标决定，不由可能随解析器修正的 AS_PATH 或 origin 推导值决定：

```json
{
  "schema": "route_event_id_v1",
  "file_sha256": "64位小写十六进制",
  "record_ordinal": 0,
  "element_ordinal": 0
}
```

输出为 `rte_v1_` 加 SHA256 前 32 个十六进制字符。`record_ordinal` 是 MRT 文件中的逻辑记录序号，`element_ordinal` 是该记录解析出的 BGP 元素序号，均从 0 开始。相同文件和版本重复导入必须得到相同 ID、记录数和聚合摘要。

### 3.4 其他 ID

| ID | 前缀 | identity |
| --- | --- | --- |
| 原始制品 | `art_v1_` | `file_sha256`，截断 32 位 |
| 碰撞组 | `lcg_v1_` | 排序后的 Incident ID 集合与源事实主键，截断 32 位 |
| quarantine 记录 | `qr_v1_` | 源表、源主键、quarantine 原因，截断 32 位 |
| 导入运行 | `run_v1_` | 输入 manifest SHA256、parser/importer 版本与配置 SHA256，截断 32 位 |

## 4. Incident 与六类事实

### 4.1 规范 Incident 公共字段

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `incident_id` | string | 是 | `incident_id_v1` |
| `incident_id_schema` | const | 是 | `incident_id_v1` |
| `event_type` | enum | 是 | 六类英文稳定枚举 |
| `source_code` | string | 是 | 当前历史值为 `r`，不等同于完整 collector 身份 |
| `source_table` | string | 是 | 实际月份事实表 |
| `source_primary_key` | object | 是 | 保留原生主键全部字段 |
| `detail_reference` | string | 是 | 原始 `detail_url` |
| `event_time_utc` | date-time | 是 | 从业务时间按 `Asia/Shanghai` 转换 |
| `end_time_utc` | date-time/null | 是 | 缺失时不得合成 |
| `duration_seconds` | integer/null | 是 | 只在开始、结束和历史 duration 一致时填入 |
| `risk_level` | enum/null | 是 | `low/middle/high/unknown` |
| `affected_objects` | array | 是 | 类型化对象，去重且确定性排序 |
| `fact_link_status` | enum | 是 | `matched/legacy_collision/quarantined/unresolved` |
| `field_quality` | array | 是 | 每个缺失、冲突或修正字段的状态和来源 |
| `collision_group_id` | string/null | 是 | 仅主键复用时存在 |
| `quarantine_id` | string/null | 是 | 仅隔离记录存在 |
| `detector_version` | string/null | 是 | 历史未保留时为 `null` + `not_retained` |

### 4.2 六类专属字段覆盖

| `event_type` | 事实表 | 对象/原生键 | 阶段字段 | P0 限制 |
| --- | --- | --- | --- | --- |
| `hijack` | `hijack_YYYYMM` | `source,prefix,hijack_eventid` | `pre/eve/next_vp_paths` | D0 存在 1 组事实主键复用；阶段路径无 VP |
| `sub_hijack` | `sub_hijack_YYYYMM` | `source,prefix,sub_hijack_eventid` | 不适用 | 劫持双方为集合文本，不能伪造阶段路径 |
| `leak` | `leak_event_YYYYMM` | `source,prefix,leak_event_id` | 仅 `as_path` | `leak_vp` 只是 ASN token，不是稳定 VP；无结束时间 |
| `prefix_outage` | `prefix_outage_YYYYMM` | `source,prefix,outage_id,asn` | `pre/eve/next_vp_paths` | locator 未含 ASN；必须持续检测一对多歧义；少量 `asn` 原生键为 `{asn,...}` 聚合集合，需展开为多个对象 |
| `as_outage` | `as_outage_YYYYMM` | `source,asn,outage_id` | `pre/eve/next_vp_paths` | 路径来自代表性前缀，但前缀身份未保留；`asn`/detail problem 允许经逐成员校验的 `{asn,...}` 原生集合键，不得合成虚构 ASN |
| `country_outage` | `country_outage_YYYYMM` | `source,country,outage_id` | 不适用 | 空国家行必须 quarantine；受影响 AS 集合缺生成口径 |

阶段质量只允许：`observed_paths`、`observed_no_path_in_snapshot`、`not_retained`、`not_applicable`、`legacy_unknown`、`source_fact_collision`。其中 `observed_no_path_in_snapshot` 仅说明快照集合为空，不证明网络中没有路径。

## 5. RouteEvent

RouteEvent 是批准原始 MRT 的不可变旁路索引，机器合同为 `contracts/data/route-event.schema.json`。

| 字段组 | 必需字段与语义 |
| --- | --- |
| 身份 | `record_kind`、`route_event_id`、`route_event_id_schema`、`schema_version` |
| 来源 | `source`、`collector_id`、`vp_id`、`vp_asn`；稳定 VP 至少包含 collector、peer IP、peer ASN |
| 时间 | `event_time_utc`、`source_timezone`、`ingest_time_utc`、`parse_time_utc` |
| 路由 | `action=announce/withdraw/rib_snapshot`、`afi_safi`、`prefix`、`as_path`、`origin_asn` |
| 原始引用 | `artifact_id`、`file_sha256`、`record_ordinal`、`element_ordinal`、`record_offset`、`record_length`、`record_hash` |
| 处理血缘 | `parser_name`、`parser_version`、`importer_name`、`importer_version`、`import_run_id`、`schema_version` |
| 质量 | `lineage_status`、`quality_flags`、`missing_reasons` |

`lineage_status=raw_traceable` 时，`record_kind=route_event`，RouteEvent ID、VP、原始引用和处理版本必须完整。`legacy_untraceable` 只允许作为 `record_kind=legacy_observation_stub` 的兼容信封，`route_event_id`、原始引用和稳定 VP 必须为 `null` 并给出缺失原因；它不进入已准入 RouteEvent 索引。不得为了满足非空约束伪造 file hash、偏移或 VP。原始 payload 不复制进事实表，通过 `raw_ref` 定位并复核哈希。

MRT/BGP4MP 的会话 `STATE_CHANGE` 没有路由前缀，不得塞入 RouteEvent 的 `action`；如后续需要保留，应使用独立 `peer_session_event` 合同。

## 6. MetricSeries

机器合同为 `contracts/data/metric-series.schema.json`。所有图表和指标卡必须消费同一合同，浏览器不得下载明细后自行推断覆盖率。

### 6.1 公共字段

```text
schema_version
metric_name
subject{subject_type, subject_id, display_name}
collector_scope{scope_kind, collector_ids, limitation_reason}
window{start, end, boundary="[start,end)", timezone}
granularity_seconds
unit / aggregation / formula / formula_version
expected_sample_count
source_observed_sample_count
metric_observed_sample_count
subject_active_sample_count
coverage{
  source_coverage_ratio,
  metric_coverage_ratio,
  subject_activity_density,
  source_gap_sample_count,
  processing_gap_sample_count,
  classification_complete
}
points[{time, value, value_state, missing_reason, formula_inputs}]
source_refs[]
generated_at
ranking_scope{scope_kind, candidate_count, filter_rules}
```

`source_coverage_ratio = source_observed_sample_count / expected_sample_count`，只表示已经通过来源完整性准入的槽位覆盖，不等同于“目录中存在文件”；`metric_coverage_ratio` 单独表示派生指标成功生成的覆盖。ASN 稀疏表的活动时点只能进入 `subject_active_sample_count` 和 `subject_activity_density`，不能命名为 coverage。ASN 的 `subject_id` 使用不带 `AS` 前缀的十进制字符串，国家使用 ISO alpha-2 大写代码。

### 6.2 冻结指标公式

| `metric_name` | 公式 | `unit` | `formula_version` |
| --- | --- | --- | --- |
| `bgp_announce_record_count` | `sum(feature_country.announ_num)` | `bgp_update_record` | `announce_count_v1` |
| `bgp_withdraw_record_count` | `sum(feature_country.withdraw_num)` | `bgp_update_record` | `withdraw_count_v1` |
| `bgp_update_record_count` | 上述 ANNOUNCE 与 WITHDRAW 之和 | `bgp_update_record` | `update_total_v1` |
| `bgp_withdraw_ratio` | `withdraw / (announce + withdraw)` | `ratio_0_1` | `withdraw_ratio_v1` |
| `ipv4_24_equivalent_count` | `last_observation(feature_country.v4prefix_num)` | `ipv4_24_equivalent` | `ipv4_24e_v1` |
| `ipv6_48_equivalent_count` | `last_observation(feature_country.v6prefix_num)` | `ipv6_48_equivalent` | `ipv6_48e_v1` |
| `ipv4_equivalent_address_count` | `last_observation(feature_country.v4ip_num)` | `ipv4_equivalent_address` | `ipv4_address_v1` |
| `anomaly_incident_count` | `count(distinct Incident.incident_id)` | `anomaly_incident` | `anomaly_incident_count_v1` |
| `prefix_outage_concurrent_count` | 成功查询且分区完整时，180 秒槽内 distinct prefix 的最大并发 | `prefix_count` | `prefix_outage_concurrency_v1` |
| `as_outage_concurrent_count` | 成功查询且分区完整时，180 秒槽内 distinct ASN 的最大并发 | `asn_count` | `as_outage_concurrency_v1` |

这 10 项是 D1 冻结的唯一允许 MetricSeries 集合；具体候选数据是否准入由 D5 数据质量门禁决定。现有页面中的 `resource_change=max(abs(v4_delta),abs(v6_delta))` 混合了不可比较的单位，`peak_updates`、`volatility`、`update_change_rate` 以及各类资源变化率也尚未进入本合同；D6 必须删除、拆分或另行冻结合同，不能沿用旧字段直接发布。IPv4 `/24` 与 IPv6 `/48` 等价值不得相互比较或取最大值。撤回率分母为 0 时返回 `null + not_applicable + denominator_zero`。

### 6.3 当前固定窗口缺口

- 期望五分钟槽：16,992。
- 原始 UPDATE 文件存在槽：10,272；其中 10,238 槽通过压缩容器完整性准入，34 槽为 `parse_failed`，另有 6,720 槽为 `source_unavailable`。
- `feature_country.collect` 实际槽：10,266。
- 对 10,238 个来源有效槽进行指标闭合后，10,232 槽为 `observed`；`2026-03-31T07:30:00+08:00` 至 `08:00:00+08:00` 的 6 槽为 `processing_gap`。
- 前端必须在这些点返回 `value=null` 并断线。

## 8. RouteEvent 与原始引用

严格血缘直接由 Incident、RouteEvent、原始记录引用、处理版本和 MetricSeries 之间的稳定关联表达，不再增加事件级聚合证据包。D0 的事实碰撞使用 `legacy_collision_group` 表达，空国家孤儿使用 quarantine/correction ref 表达；两者都不能静默消失。

RouteEvent 的 `raw_record_ref` 必须闭合到制品、记录序号、元素序号和哈希。调查接口按需联查这些对象，并始终携带 `classification=observation_only` 与 `causal_conclusion=null`。

## 9. DataQualityReport

机器合同为 `contracts/data/data-quality-report.schema.json`。质量报告至少分开报告：

1. 完整性；
2. 唯一性；
3. 正反向引用一致性；
4. 时间与分区一致性；
5. 原始可追溯性；
6. 来源与实体样本覆盖；
7. 指标可复现性；
8. 六类事件阶段覆盖；
9. 固定窗口越界；
10. 未知缺失原因。

quarantine 与 collision group 不是第 11 个质量维度；它们分别作为引用一致性、时间一致性、唯一性或缺失语义维度中的正式检查及证据出现。每个维度必须有 `status=pass/fail/pending`、计数、规则版本和证据引用。总门状态由阻断项和 pending 项确定，不能用单一平均分掩盖失败。

## 10. 版本、修正与准入

- 原事实表保持只读；规范化、quarantine、collision group 和 RouteEvent 均在 `backend/core/` 外旁路生成。
- 修正不覆盖旧制品；使用 `correction_ref` 指向新版本并保留旧版本哈希。
- `legacy_compatible` 只允许在未解释孤儿为 0、碰撞均显式建组、稳定 ID 规则可复算、缺失语义完整且指标对账通过后发布；复现证据的实际范围必须单独披露。本轮仅完成 64 条有界 A/B，`cross_run=partial`、`full_semantic=not_run`。
- `raw_traceable` 只允许在原始引用解析率、文件/记录哈希成功率、VP 与处理版本完整率均为 100% 的覆盖范围内声明。
- 历史二三月可按日或 RouteEvent 子集声明部分 `raw_traceable`，但数据档整体仍必须明确 `partial`，不得提升为全窗口通过。
